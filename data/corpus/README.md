## 为什么这些语料是生成的，而不是下载的

三条理由，都不是为了省事：

1. **版权**。提交物里带第三方报告、标准全文、上市公司年报，学院审查那一关过不去，
   而且「自主知识产权」是报名通知里的硬要求。
2. **难点可控**。「≥2 份目录混乱」是硬指标，现成文档里凑不齐；就算凑齐，
   你也不知道乱在哪一层。按考点造，能精确控制混乱的形态（层级丢失 / 编号错乱 / 顺序错位），
   出问题时能立刻判断是解析器不行还是语料不行——**用自己造的语料，失败原因才是可归因的**。
3. **可复现**。评委会在别的机器上重跑脚本。用下载的语料，链接失效就复现不了。

关于「可复现」的准确口径（实测得出的结论，不要按直觉改）：

- `manifest.json` 里的 **`content_sha256`** 是对**章节数据**做哈希的内容指纹，
  跨机器、跨 PyMuPDF 版本稳定。**判断语料内容有没有被改，看它。**
  脚本每次生成后会与上一版清单对比，内容变了会明确告警。
- **`file_sha256_local`** 是生成文件的字节哈希，**跨版本会变**——
  PDF 写入器会在文件里留下对象编号、trailer `/ID`、字体子集打包顺序等版本痕迹。
  实测把创建时间钉死也修不好：15 份里仍有 13 份对不上。
  所以它只作本地产物指纹，**不要拿它当复现依据**。

代价说清楚：数据是合成的，语言分布不如真实企业文档自然，
「脏」的程度也受生成脚本限制。**决赛前建议再补 3-5 份真实公开文档做交叉验证。**

## 重新生成

```bash
python data/corpus/tools/build_corpus.py
```

脚本会先挑系统中文字体（等线 → 微软雅黑 → Noto Sans SC → Linux/macOS 常见路径），
挑不到会**明确警告**：PyMuPDF 内置的 `china-s` 缺中文标点、ASCII 走全角，
语料观感与 OCR 难度都会失真。不要忽略这条警告。

脚本还会做字体子集化——不做的话，16MB 的系统字体整份嵌进每页 PDF，
15 份语料会涨到 200MB+，提交的 ZIP 包会失控（实际：文本 PDF 50–80KB/份）。

## 扫描件是怎么造的

KB-007 / KB-008 的生成过程是：先正常渲染文本 PDF → 150dpi 灰度栅格化 → 重新组装成
无文本层的图片型 PDF，奇数页向右偏移 6pt 模拟进纸不齐。
所以它们**必须过 OCR**，文本层是空的（`manifest.json` 里的 `has_text_layer: false`）。
这一点在跑分时很关键：扫描件用例答不出来，说明是 OCR 环节的问题，
不是切片或向量检索的问题——**这类用例的价值就是把故障定位到具体环节**。

## 目录混乱是怎么造的

`degrade_outline()` 复刻三种真实故障，不是随机打乱：

- **层级丢失**：所有标题降级为正文，解析器无法靠样式识别章节；
- **编号错乱**：条款编号与出现顺序脱钩（会出现 `[1.6]` 出现在 `[9.3]` 之前），
  靠编号推断层级同样失效；
- **顺序错位**：章节整体打乱，靠位置推断结构也失效。

随机化用固定 seed，任何机器重跑得到同一份**内容**（`content_sha256` 一致）。

## 目录约定

```
data/corpus/
├─ raw/            语料原始文件（15 份，**必须入库**）
├─ manifest.json   机器可读清单（入库）
├─ tools/          生成脚本（入库）
└─ README.md
```

**`raw/` 必须入库，`manifest.json` 与 `tools/` 同样。** 2026-09-19 定了这个口径，
推翻了本文件此前「raw/ 不入库」的写法。三条理由：

1. **体量不成立**：15 份合计 **818,681 字节（约 0.8 MB）**，比仓库里任何一份 SQL
   文件都小，「体积大不适合入库」站不住。
2. **版权不成立**：语料由 `tools/build_corpus.py` 自建，零第三方内容。
3. **不入库会静默丢分**：题面提交要求要「知识库文档样本（不少于 10 份）」。
   一旦 raw/ 被排除，用 `git archive` 打源码 ZIP 时 15 份样本会全部消失，
   而本地跑分一切正常——解压出来才发现没有，属于看不见的丢分。
   另外 `tools/verify_corpus.py` 第 80–83 行在 raw/ 不存在时**直接退出码 2**
   （「找不到语料目录」），干净 clone 上连硬要求校验都跑不起来。

**配套纪律**：提交用的 ZIP **不能用 `git archive` 生成**，必须从工作目录打包，
否则被排除的目录与被忽略的 `release/` 交付物会一起消失。

**.gitignore 写法注意**：不要用 `data/corpus/` 或 `data/corpus/*` 这类目录级排除。
若确实要让生成物不入库（如 `--json` 产出的校验报告），只排到具体子路径
（`data/corpus/reports/`）。**目录级排除下再补 `!data/corpus/raw/**` 是无效的**——
父目录被排除时 git 不会往下看，白名单必须逐级把目录本身放回来。

**与 B 的 RAG 线对接**：B 的 `app/rag/loader.py`、`chunker.py`、`toc.py` 默认路径
写的是 `项目根/data/corpus/1.pdf`，与本目录实际的 `raw/KB-*.pdf` 对不上，
需要对齐，否则 `python -m app.rag.loader` 会找不到文件。
