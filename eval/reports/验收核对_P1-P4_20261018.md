- `app/test_nl2sql.py::test_gold_sql_pipeline_end_to_end`

### 政采元数据环境

命令：

    $env:SCHEMA_META_PATH = 'infra/schema_meta_gov.json'
    uv run --no-sync pytest -q --tb=short

结果：**1541 passed / 365 failed / 1 skipped，退出码 1**。相比默认环境多 353 个失败，主要由于测试仍以 Chinook 表/字段为前提，却加载了政采 schema；例如 `customer`、`genre`、`track` 等 Chinook 对象在政采元数据下不可解析。该结果归类为测试环境不匹配，不代表政采元数据下每个产品路径都失败。测试后已清理该进程级环境变量。

### 判定

- `reason_code=None`：在目标基线可复现，属于既有问题；未修复。
- Chinook 用例加载政采 schema 后的大量失败：环境配置导致；不作为新代码回归。
- 默认环境的 12 个失败：记录为 `986ab1c` 基线失败，不能归因于本轮 P2；本轮未修改代码。

## P4｜HTTP 预测器与真实 API

只读检查 `eval/runner.py:458-497`、`app/contracts.py:220-230`、`app/main.py:168-188` 及 `app/main.py:571-588`：

- `HttpPredictor` 发送的是 `{question, database}` 或 `{question, top_k}`，并按 `{sql, answer, refs, ...}` 一类响应字段提取结果。
- 真实 `/api/ask` 使用 `AskRequest`，要求 `question`、`session_id`，并可选 `retrieval_mode`；接口受登录会话保护。
- 因此差异包括认证、请求字段和响应契约，不是把 endpoint 改成 `/api/ask` 就能兼容。

**P4 判定：未修改。** 单纯替换地址会导致认证或请求校验失败；本轮没有扩大到接口适配实现。
