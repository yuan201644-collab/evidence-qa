## 一、为什么需要两条基线

判分器是评测的地基。地基必须先被证明「既不漏判、也不误判」，才谈得上用它的分数评价模型。
因此固定两条极端输入：

| 基线 | 输入 | 期望结果 | 含义 |
|---|---|---|---|
| oracle 自证 | 标准答案（gold_sql / gold_refs / answer_points）本身 | **全部 100%** | 判分器不能把正确答案判错（无漏判） |
| dry-run 空基线 | 全部空输出 | **全部 0%** | 判分器不能给空输出白送分（无误判） |

只有同时满足「上界 100%、下界 0%」，分数的中间区间才有解释力。

## 二、oracle 自证结果

命令：

```bash
python eval/runner.py --suite all --predictor oracle --dialect sqlite
```

结果（**退出码 0**）：

```
NL2SQL：15/15 = 100.00%  （报错 0，仅列序不同 0）
鲁棒性：11/11 = 100.00%  （退化输入 100.00% / 澄清 100.00%）
RAG：命中率 100.00%，忠实度 100.00%
```

- 15/15 NL2SQL：`compare_resultsets` 对「行序无关、列序无关、列数敏感、浮点容差、空集与报错分离」五条规则全部自洽。
- 11/11 鲁棒性：退化输入（错别字/全角/中英混排/口语填充）被正确还原，歧义问句被正确判为「应澄清」。
- RAG：检索命中率按「文档 + 锚点」集合求交；忠实度 = 要点覆盖率 − 0.25×幻觉数，黄金答案零幻觉。

## 三、dry-run 空基线结果

命令：

```bash
python eval/runner.py --suite all --predictor dry-run --tag dry-run
```

结果（**退出码 0**）：

```
NL2SQL：0/15 = 0.00%  （报错 15，仅列序不同 0）
鲁棒性：0/11 = 0.00%  （退化输入 0.00% / 澄清 0.00%）
RAG：命中率 0.00%，忠实度 0.00%
```

空输出被判 0 分（15 条均記为「报错/无结果」，而非「碰巧通过」），证明判分不依赖任何形式的「空集==空集」误判通道。
