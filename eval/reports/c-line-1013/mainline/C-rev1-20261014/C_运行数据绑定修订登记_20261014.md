## 五、`sem-12` 判定：**系统语义错误**（非参考答案口径不一致）

**三方对照**：

- 题意（`t5_v02_questions.jsonl`）：`买过Rock但从未买过Jazz的客户有哪些？返回客户编号，按编号升序，不重复。`
- 参考 SQL（`t5_v02_reference_cases.jsonl`）：`... WHERE g.name='Rock' AND i.customer_id NOT IN (SELECT ... WHERE g2.name='Jazz') ORDER BY i.customer_id`
- 系统 SQL（10-13 原始回答）：用 `EXCEPT` 表达否定，但**第二分支 JOIN 条件写成 `ON c.customer_id = i.invoice_id`**

**离线确定性复现**（sqlite + 本地 `infra/initdb/02_chinook.sql`，脚本见本目录 `reproduce_sem12.py`；加载后 `customer=59 / invoice=412 / invoice_line=2240 / track=3503 / genre=25`，与 10-13 实测一致）：

| SQL | 行数 | 说明 |
|---|---:|---|
| GOLD（参考，`NOT IN`） | **27** | 与评分器 `gold_rows=27` 一致 |
| GOLD 改写为 `EXCEPT`（**连接正确**） | **27** | id 集合与 GOLD **完全相同** → `EXCEPT` 与 `NOT IN` **本场景语义等价** |
| PRED（原始系统 SQL） | **51** | 与评分器 `pred_rows=51` 一致 |
| PRED **仅修正第二分支连接条件** | **27** | id 集合与 GOLD **完全相同** |

**判定**：

1. `EXCEPT` / `NOT IN` 的口径差异**不成立**——两者都返回同一 27 行 id 集合。
2. 唯一差异源是**第二分支连接条件错列**：`customer.customer_id = invoice.invoice_id`（应为 `= invoice.customer_id`）。修正后立即得正确 27 行。
3. 差集自洽：PRED−GOLD = 28 个 id，GOLD−PRED = 4 个 id，净差 24 = 51 − 27。

**结论**：`sem-12` 属**系统语义错误（NL2SQL 生成缺陷：跨表连接选错列名）**，**不属于**「参考答案 / 行集口径不一致」。按 A 的口径，应**列入代码修复项**，而非修订判据；本判定不修改任何判据与代码，仅提供证据。
