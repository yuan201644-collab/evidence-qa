## 需跟进的三处

1. **acc-17（FAIL，真 bug）**：题面要求「毫秒换算成秒、保留一位小数」，系统生成 `ROUND(milliseconds / 1000, 1)` —— PostgreSQL 下 `integer / integer` 是**整数除法**，`5286953/1000 = 5286`（截断）→ 得 `5286.0`；正确应为 `milliseconds / 1000.0`（或 `::numeric`）→ `5287.0`。**这是 NL2SQL 生成端的真实缺陷**（缺单位换算的精度保护）。
2. **acc-11 / acc-19（CLARIFY，误拦）**：两题都含「作曲者」，normalizer 把它切成子串「曲者」判为疑似错别字、且改写目标有多个（曲目/曲风）→ `unresolved` → 澄清器 `status=ask` 直接拦截、不作答。**题目本身无歧义**，是造词/纠错规则的分词误伤。
3. **模型限流**：`glm-4.7-flash` 对本站账号恒返 `429 / code 1302 您的账户已达到速率限制`；换 `glm-4.5-flash` 后 20 题零限流（本题采集未触发重试）。

## 运行注意（采集侧踩过的坑）

- `/api/ask` 的 `result_set` **只在大结果集时返回分页信息**，小结果集为 `null` —— 接口**不回传行数据**，故判分必须用 trace 里的 SQL 回库重跑（或走 CSV 导出端点）。
- `/api/ask` 必填 `session_id`；`trace` 元素键名是 `tool`。
- 服务进程若继承沙箱代理，LLM 外呼会异常；本次用**清空代理**直连。
