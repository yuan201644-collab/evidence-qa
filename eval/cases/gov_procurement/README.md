# 政采结构化题集（gov_procurement）

面向 `askdata_gov` 库的 30 道结构化问数题，对应赛题"基础 NL2SQL"与"执行准确率"两项。

## 数据源

`postgresql://ict@127.0.0.1:5432/askdata_gov`，9 张结构化表共 12,650 行
（announcements / packages / projects / buyers / agencies / items / awards / suppliers / regions），
另有 documents（2,742 份公告原文，跨源桥）与 regulation_rules（26 条法规条款）。

数据全部来自中国政府采购网 2026-10-08 ~ 2026-10-17 的真实公告，**未做任何人工编造**。

## 题目构成

| scope | 题数 | 考察点 |
|---|---|---|
| single_table | 10 | 单表聚合、COUNT DISTINCT、GROUP BY、窗口函数求占比 |
| multi_table | 12 | 三~四表 JOIN、EXISTS 子查询、两步挂载（items 无 project_id） |
| time_window | 5 | date 字面量、BETWEEN、左闭右开、日期函数分组 |
| null_edge | 3 | FILTER 聚合、口径敏感性分析、空值对分母的影响 |
| 合计 | 30 | 难度 easy 6 / medium 14 / hard 10 |

## 每题的生成方式

**先跑 SQL 拿真答案，再据此定稿题面**，不是先想题再去凑答案。因此：

- 每题的 `gold_sql` 都能在库上直接执行，`gold_row_count` 全部 > 0（无鉴别力的题会被构建脚本拒绝）；
- `gold_rows` 记录实测结果，供人工复核时逐题对照；
- 不写死期望值字符串——runner 判分是对比执行结果集，不是比对 SQL 文本。

## 本库必须知道的三个坑

这三条都在题目的 `notes` 里复述过，出题时刻意覆盖：

1. **`awards.award_yuan = 0` 不是零元中标**。源站写「0.0000000 万元」的空占位被抽成了 0，
   共 47 条。任何金额聚合都必须 `> 0` 过滤，否则均值被显著拉低
   （实测：排除后均值 4,016,533.10，不排除 3,680,032.11）。
2. **`budget_level = 'unknown'` 有 297 条**。统计中央/地方占比时若漏掉这一档，
   分母会少算 11%，占比从 13.95% 变成 15.71%。
3. **`packages.award_yuan` 全部为空**（0/2,660）。包组中标金额只能从 `awards` 关联取，
   不能直接从 packages 求和。

## 已知的数据瑕疵（不影响本题集使用，但报告需注明）

| 瑕疵 | 规模 | 影响 |
|---|---|---|
| `project_id` 形态不统一（含中文、含「（招标文件编号：X）」冗余） | 875 / 2,659 含中文 | 试过四版清洗，**均会让跨公告聚合变差**（一致率从 100% 掉到 88%），故不清洗 |
| `project_name` 有 115 条实际是公告标题 | 115 / 2,659 = 4.3% | 排序类题目会出现长标题，不影响答案正确性 |
| 采集窗口只有 10 天 | 2026-10-08 ~ 10-17 | 跨月/跨季题会落到同一批日期，时间窗口题刻意只考窗口写法 |

清洗方案的量化对比见 `docs/真实规模业务库建设记录_20261017.md` §5.1。
