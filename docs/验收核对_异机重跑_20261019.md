## 2 结果

| 项 | 结果 |
|---|---|
| 登录 | 未登录访问 `/api/*` 返回 401，登录后 200（首次演练卡住的两处阻断之一在此闭合） |
| 真实 SQL 请求 | 「库中一共有多少条采购公告？」→ `announcement_count = 2742`，与库内真实行数一致；耗时 5.5 秒；SQL 为 `SELECT COUNT(*) AS announcement_count FROM announcements;`；溯源 1 条 |
| 真实文档请求 | 「关于评标办法有什么规定」→ 走完六步链路 `normalizer → semantic_clarifier → parse_provenance → hybrid_retrieve → rerank → llm_generate`；返回 5 条引用，每条带 `doc_id` / `doc_title` / `page` / `section_path` / `char_start` / `char_end` / `bboxes` |
| 该文档请求的答案 | 答「无法回答」。原因是语料中确无评标办法内容，属**诚实拒答**，不是链路失败；判据是链路是否走通并有引用，而不是答案是否命中 |
| 降级路径 | 期间一次「有多少个供应商」报「调用 LLM 失败（已尝试 3 次，末次 HTTP 500）」，属外部模型抖动；三次重试后按降级路径报错，未影响其余请求 |

## 4 局限与缺口（写报告时必须保留）

1. **不是另一台物理机**：同机不同目录 + 独立容器 + 独立端口，只能证明「洁净副本可跑通」，不能证明「异机部署已通过」。
2. **bge 权重未走到联网下载**：演练用本机已有模型目录，首次联网下载这条路仍无证据。
3. **前端与溯源面板只做了接口核对**，没有人工在真实链路下点开引用与溯源面板。
4. **路由缺陷未在本实例复测**：「投标保证金是多少」在工作区已修（改为不再被判成问数题），但本次演练跑的是 `712f1b2` 交付包，仍是旧逻辑。修复后的复测要等下一次打包。
5. 单次观测，未做多轮重复以估计抖动。
