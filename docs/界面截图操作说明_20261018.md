## 二、起服务（二选一）

### 路线 A：单端口（推荐，最省事）

后端会把 `web/dist` 挂到根路径，所以一个 uvicorn 进程就同时提供界面和接口，不需要再起 Vite。

```powershell
cd C:\Users\86133\WorkBuddy\多模态数据驱动的可解释精准问数问答智能体
$env:DATABASE_URL   = "postgresql+psycopg://<用户>:<口令>@127.0.0.1:5432/askdata_gov"
$env:PG_DSN         = "postgresql://<用户>:<口令>@127.0.0.1:5432/askdata_gov"
$env:SCHEMA_META_PATH = "infra/schema_meta_gov.json"
$env:APP_TIME_ANCHOR  = "2026-10-17"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

浏览器打开 **http://127.0.0.1:8002**

> 端口用 8002，不要用 8000 / 8001 / 5184——那几个是 `start.ps1` 和另一名协作方的占用口径。

### 路线 B：`start.ps1`（前端热更新模式）

```powershell
.\start.ps1
```

后端 8000、前端 5184，浏览器打开 http://127.0.0.1:5184 。

> 两条路的界面应当一致。若不一致，说明 `web/dist` 落后于源码，需要先 `cd web; pnpm build`，或改走路线 B。

## 三、五张图，各问什么、什么时候截

每张图的判据不是「界面好不好看」，而是**这一屏能否证明报告表 3 里那一行说的能力存在**。下面「必须出现在画面里」一栏就是判据，缺一项就要重截。

### 图 6 · 单表查询与 SQL 展示

| 项 | 内容 |
|---|---|
| 问句 | `库中一共有多少条采购公告？` |
| 必须出现在画面里 | ① 自然语言复述的问题；② 答案数字与单位；③ **生成的 SQL 代码块**；④ 命中的表名与字段名；⑤ 进入溯源的入口（按钮或链接） |
| 截这一屏 | 回答完整展开、SQL 块可见、溯源入口未被折叠的状态 |
| 备注 | 这道题在政采鲁棒集里通过（grob-01），是当前最稳的一条，用它截不会翻车 |

### 图 7 · 文档回答与原文引用

| 项 | 内容 |
|---|---|
| 问句 | `政府采购法对供应商提出质疑的期限是怎么规定的？` |
| 必须出现在画面里 | ① 答案正文；② **至少一条引用卡片**（文档名 + 页码或章节号）；③ 点开引用后的原文片段（高亮命中句） |
| 截这一屏 | 引用卡片展开、原文侧栏可见的状态。若引用是抽屉/弹窗，让抽屉保持打开再截 |
| 兜底 | 若该问句走到 SQL 路径（路由误判），换问：`政采法规里关于投标保证金是怎么规定的？`，仍要看到引用卡片 |

### 图 8 · 澄清后继续回答

| 项 | 内容 |
|---|---|
| 第 1 轮问句 | `他的项目一共花了多少钱？`（故意缺主语，应触发澄清） |
| 第 2 轮问句 | 按澄清提示补充，例如 `清华大学那个具身智能项目` |
| 必须出现在画面里 | ① **第一轮的澄清气泡**（「请补充…」那一条）；② 第二轮补充后的完整回答；③ 两轮在同一会话流里的上下衔接 |
| 截这一屏 | 向下滚动到「第二轮回答完整可见、第一轮澄清气泡仍在画面内」的位置。两张分开截也可以，最后拼成一格 |
| 备注 | 若第 1 轮没触发澄清而直接作答，说明这条问句在当前版本不产生澄清，换一格更模糊的问法（如 `那个项目的中标金额是多少？`）；**不要为了截图去改代码** |

### 图 9 · 错误与超时提示

| 项 | 内容 |
|---|---|
| 制造方式（任选其一） | ① 问一个库里不存在的字段：`按采购方式统计采购公告数量`（当前库里没有 `procurement_way` 列，会走失败路径）；② 临时把后端停掉再发问，得到连接失败提示 |
| 必须出现在画面里 | ① 明确的失败态（红色/警示样式，文案说明为什么失败）；② **不能看起来像一条正常回答**；③ 若有「重试」入口要能看到 |
| 备注 | 这一屏证明的是「错误不被伪装成成功」，这是可解释性评分点，不要截成一条含糊的「没有结果」 |

### 图 10 · 大结果分页及导出

| 项 | 内容 |
|---|---|
| 问句 | `列出所有采购公告的标题和发布日期`（不带数量限制，结果集会超过一页） |
| 必须出现在画面里 | ① 结果表格；② **分页控件**（页码或上一页/下一页）；③ 导出按钮（CSV）；④ 若有「结果已截断/仅显示前 N 行」的提示，必须可见 |
| 截这一屏 | 表格首屏 + 分页条同时可见的状态 |
| 备注 | 若该问句被判为需要限制行数而自动加 LIMIT，正好——把那条截断提示一并截进来，这正是报告里说的「查询截断不能伪装为完整结果」 |

## 四、截图规格

| 项 | 要求 | 原因 |
|---|---|---|
| 像素 | **1440 × 810**（16:9） | 联系表每格按 16:9 排版，宽 6.9 in 三等分。比例不对会导致联系表变高，设计报告从 20 页顶到 21 页以上 |
| 格式 | PNG | 报告生成脚本按 png 读取 |
| 浏览器缩放 | 100% | 缩放变了字会糊 |
| 主题 | 与报告其余插图一致的主题（深色或浅色，**五张必须统一**） | 混主题会显得像拼凑 |
| 内容 | 不得出现账号、口令、本机路径、队名、人名 | 交付物不做身份标识 |

### 怎么截出精确 1440×810

用 Chrome 或 Edge：

1. `F12` 打开 DevTools
2. `Ctrl + Shift + M` 进入设备模式
3. 顶部尺寸框里选 **Responsive**，宽度填 `1440`、高度填 `810`
4. `Ctrl + Shift + P` 打开命令面板，输入 `capture screenshot`，选 **Capture screenshot**
5. 文件自动下载到「下载」目录

> 不要用 `Win + Shift + S`，它截的是屏幕区域，比例不可控，还会带上浏览器边框。

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 界面打开是白屏 | `web/dist` 缺失或过期。`cd web; pnpm build`，或改走路线 B（Vite） |
| 问答一直转圈 | 模型冷启动，等 1–3 分钟。若超过 5 分钟，看后端日志 `agent_temp\startup\backend.log` |
| 图 8 的澄清不出现 | 该问句在当前版本不产生澄清。换更模糊的问句，**不要改代码制造澄清** |
| 图 10 结果不足一页 | 换问句去掉数量限制；或先问「一共多少条」再问「列出来」 |
| 截图里出现深色/浅色不一致 | 五张统一重截，不要靠后期调色 |
| 端口被占用 | 8002 被占就换 8003，只要与 8000/8001/5184 错开即可 |
