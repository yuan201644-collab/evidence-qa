## 四、关键结论（含一处必须记住的修正）

### 1. 忠实度卡在 8 分档，距 10 分差 8~10 个百分点
所有配置均值都在 80~83%，没有一组够到 90%。

### 2. 🔴 「多跳更差」是判定器噪声造成的假象 —— 正确表述是「多跳与单轮打平」
- 原始数字：多跳题集 R1（80.00%）**低于** R0（81.81%），且引入了 R0 本来能过的失败题 `rag-mh-14/15`。
- **但归因发现**：`rag-mh-14/15` **恰好都是判定器假阳性**（要点全中，只因"出现禁答词"被判失败）→ 白扣了多跳 4.58pp。
- **修判定器后的估计**：multihop **R0 → 84.31%**，**R1 → 84.58%** → **两者实质打平**。
- → 对外**不能写「多跳全面优于单轮」**，也不能写「多跳更差」；准确写法 =「**多跳与单轮在同等难度下打平，跨文档难题上未观察到净增益**」。

### 3. 即使修完判定器，仍够不到 90%
修正后最高 84.58%，**还差 5.4~8.7pp**，缺口**全部落在"生成漏要点"**（见 §五）。

### 4. 失败是稳定的 → 逐题查因，别刷轮次
跨 3 轮每轮都失败的题：
- rag 套件：`rag-e-03`、`rag-m-02`、`rag-m-04`、`rag-h-01`（另有 `m-03/m-05` 视臂而定）
- 多跳套件：`rag-mh-03/09/10/13/16`（R0 另有 `07/12`，R1 另有 `14/15`）

## 五、失败题归因（这不是"检索不行"）

判据 = `retrieval.hit` / `faithfulness.missed_points` / `verdict.gold_points_all_hit` + `forbidden_absent`。

| 类型 | 含义 | 题数 | 占失败题 |
|---|---|---:|---:|
| **A 召回失败** | 证据块根本没检索到 | **2** | 10% |
| **B 生成漏要点** | 召回到了，答案没写全 | **13** | 65% |
| **C 判定器假阳性** | 要点全中，被"禁答词"误杀 | **5** | 25% |

- **A 类（真检索问题，仅 2 题）**：`rag-h-01`（**`considered=0`，检索结果为空**）／`rag-mh-16`（top-k 未命中）。
- **B 类（主因，13 题）**：漏掉的**全是"精确型事实"**——数字/编号/公式/条款名/专名。例：`7×24 热线`、公式 `D = L × E × C`、`质保 3 年`、`序列号 SN-8823917`、`总金额 186 万/372 万`、甲方`北方数据中心运营有限公司`、结论句`以合同为准`。
  🔑 检索命中率 93~95%（多为"文档+块锚点精确命中"）→ **证据已在上下文里，是生成环节没写全**。
- **C 类（5 题，全在多跳套件）**：`rag-mh-09/12/13/14/15`。实测验答案原文证实 `rag-mh-12` 是**真·假阳性**：模型在正确复述合同除外清单（"…外接显示器、KVM 切换器、机柜 PDU **不在覆盖范围内**…"），却因 `rag_metrics.py:116` 的**子串匹配**被判幻觉。

## 七、复现环境硬坑（不改就跑不出数，勿重踩）

1. 🔴 **服务启动必须覆盖模型路径**：`.env` 默认写 `BAAI/bge-m3` + `HF_HUB_OFFLINE=0` + 空的 `./models` → 联网下载被 SSL 拦、无限重试。正确起法：
   ```
   BGE_EMBEDDING_MODEL=D:/kag/stage2_models/bge-m3 \
   BGE_RERANKER_MODEL=D:/kag/stage2_models/bge-reranker-v2-m3 \
   HF_HUB_OFFLINE=1 DOC_SEARCH_BACKEND=rag|rag_multihop \
   .venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8123|8124
   ```
2. 🔴 **`HttpPredictor` 超时硬编码 30s**（`eval/runner.py:369`），而多跳实测 55s/题 → 不改就是一片超时。
3. 🔴 **httpx 走系统代理** → 绝对 URL 被当路径、服务端收到 `POST http%3A//127.0.0.1...` 一律 404 → 需 `trust_env=False` + `NO_PROXY`。
4. 🔴 **`AskRequest` 只认 `question + session_id` 且 `extra="forbid"`** → runner 自带 `top_k` 会 422。
5. 🔴 **endpoint 必须写全 `http://127.0.0.1:PORT/api/ask`**（runner 直接 POST 该字符串）。
   → 以上四处均以**运行时打补丁**方式绕过（脚本 `_eval_runs/20261005/run_suite.py`），**未改仓库任何文件**。
6. 🔴 **后台任务活不过会话空闲期**（本项目已连挂两次）→ 长跑必须挂 **Windows 任务计划**（`night_run.sh`，幂等、可断点续跑、服务健康检查不过就中止）。
7. 🔴 **`--predictor http` 不落 predictions 文件** → 改判定器/用例后**必须重跑生成**，无法离线重打分。
8. 🔴 **报告 JSON 只存指标+判定，不存答案原文** → 同上。
