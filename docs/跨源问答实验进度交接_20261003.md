## 交接后的建议动作

1. 不要在 CS05 上继续调参后再把它当留出成绩；代码修改后它只能用于回归。
2. 若要继续验证泛化，先明确当前代码快照，再另建题集；编制、静态复核、运行、匿名盲审应由不同角色完成。运行者只拿 runtime 包和启动命令，不看 gold、配对 JSON、密钥或静态审查中的逐题答案；盲审者只拿匿名表。
3. 下一批应增加题量和场景差异，并尽可能使用已授权、脱敏的真实业务样本；若只能用合成数据，报告必须保持“合成留出试运行”的口径。建议报告同时保留机器 trace 检查、答案正确性、引用完整性、A/B 配对人工判分、延迟与失败原因。
4. 不把 A 称为历史旧系统：它是操作性参考基线。若要验证相对旧系统效果，应取得并运行真实旧版本源码，在相同数据库、题目、模型/温度和运行条件下对照。
