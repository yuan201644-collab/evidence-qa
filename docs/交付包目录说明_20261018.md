## 三、十分钟跑起来

### 3.1 起数据库

```bash
docker compose -f infra/docker-compose.yml up -d
docker ps --filter name=ict-db      # 应为 healthy；宿主机端口 127.0.0.1:5432
```

容器账号：`ict` / 口令见 `.env.example` 的 `POSTGRES_PASSWORD`（默认 `ict_dev_only_change_me`，正式部署请改）。

### 3.2 导入政采库（12,650 行）

```bash
# 1) 建库
docker exec ict-db psql -U ict -d postgres -c "CREATE DATABASE askdata_gov;"

# 2) 把快照拷进容器再执行 —— 直接管道会因宿主/容器编码差异把中文注释读坏
docker cp data/gov/askdata_gov_structured.sql ict-db:/tmp/gov.sql
docker exec ict-db psql -U ict -d askdata_gov -v ON_ERROR_STOP=1 -f /tmp/gov.sql

# 3) 校验
docker exec ict-db psql -U ict -d askdata_gov -c "select count(*) from announcements;"   # 期望 2742
python infra/scripts/verify_gov_db.py
```

> 第 2 步必须走 `docker cp` + `psql -f`。用 `Get-Content ... | docker exec -i psql` 这类管道时，PowerShell 会按本地代码页重编码，中文注释行会报
> `syntax error at or near "公告事实表"`，整库导入在第一个 `COMMENT ON TABLE` 处失败。

### 3.3 起服务（两种方式选一种）

**方式 A（推荐，单端口）**：前端已构建，后端直接托管 `web/dist`。

```powershell
$env:DATABASE_URL   = "postgresql://ict:ict_dev_only_change_me@127.0.0.1:5432/chinook"
$env:PG_DSN         = "postgresql://ict:ict_dev_only_change_me@127.0.0.1:5432/askdata_gov"
$env:RAG_DSN        = "postgresql://ict:ict_dev_only_change_me@127.0.0.1:5432/askdata_gov"
$env:SCHEMA_META_PATH = "infra/schema_meta_gov.json"     # 政采业务库的字段元数据
$env:APP_TIME_ANCHOR  = "2026-10-17"                     # 相对时间词的基准日；政采数据窗口是 10-08～10-17
$env:LLM_API_BASE = "..."; $env:LLM_API_KEY = "..."; $env:LLM_MODEL = "..."
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000/>。后端同时提供 `/api/ask` 等接口，界面与接口同源，不会有跨域问题。

**方式 B（开发模式）**：仓库根目录执行 `start.cmd`，后端 8000、前端 Vite 5184，访问 <http://127.0.0.1:5184/>。

环境变量全量清单与逐条解释见 `.env.example`（198 行，含每个开关为什么存在、写错会怎样）。
只跑数据库与评测、不跑生成链路时，`LLM_*` 一节可以整段留空。

### 3.4 创建登录账号（必须，否则界面进不去）

包内**不含任何账号**，账号库是运行期本地文件。首次启动后接口一律返回 401，必须先建一个管理员：

```powershell
.\.venv\Scripts\python.exe -m app.auth_cli create-admin --username admin
# 交互式输入两次密码，至少 12 位
```

**没有交互终端时**（管道、CI、`docker exec` 不带 `-t`）用环境变量传密码，`getpass` 在非 TTY 下会阻塞：

```powershell
$env:VERIMIND_BOOTSTRAP_PASSWORD = "改成一个至少 12 位的口令"
.\.venv\Scripts\python.exe -m app.auth_cli create-admin --username admin --password-env VERIMIND_BOOTSTRAP_PASSWORD
Remove-Item Env:VERIMIND_BOOTSTRAP_PASSWORD
```

密码只走环境变量、不进命令行参数，避免留在进程列表与 shell 历史里。

- 账号库存放位置由 `.env` 的 `VERIMIND_AUTH_DB_PATH` 决定，默认 `./agent_temp/verimind-accounts.sqlite3`；**相对路径按项目根解析，不按当前目录**（`app/auth_store.py:46-62`）。未配置时回落到 `%LOCALAPPDATA%\VeriMind\app\accounts.sqlite3`（Linux 为 `~/.local/share/verimind/`）。
- 忘记密码：`python -m app.auth_cli reset-admin-password --username admin`。
- 系统只保存 PBKDF2 校验值（`PASSWORD_ITERATIONS = 600_000`），不保存明文。
- 若把服务放进容器，账号库所在目录必须挂卷持久化，否则容器重建后账号丢失。

> 这一节是 2026-10-18 异机演练暴露的缺口：干净副本能装依赖、能建库、能起服务，但没有账号就停在登录页，无法验证「界面 + SQL + 答案 + 溯源」这条链路。

### 3.5 冒烟一句

界面输入「库中一共有多少条采购公告？」，应返回答案 + 生成的 SQL + 命中表与字段 + 执行耗时。
若返回的是澄清追问，把问题改成「一共多少条采购公告」（去掉范围疑问词）再试。

## 五、什么不在包里

| 项 | 体积 | 为什么不在包内 | 需要时怎么办 |
|---|---|---|---|
| 数据库镜像离线包 `ict-db-images-v1.0.0.tar.gz` | 392,519,074 字节（约 375 MiB） | 超过常见提交通道附件上限 | 说明见 `release/README.md`；可用 `docker save` 重建，或在能联网的机器上直接 `docker compose up -d` |
| 政采向量索引 `chunk_vectors` | 打包时 26,544 行（`pg_dump` 340.7 MB）；该表会被灌库重写，本机 2026-10-18 夜实测为 103 行 | 纯浮点数据压缩率低，且可由文档重建 | 设好 `RAG_DSN` 后运行 `python -m app.rag.corpus` 重建；需先具备 bge-m3 权重 |
| 公告抓取中间产物 | 5,622 个文件、139.5 MB | 快照已入库，原始 HTML/正文只是重抽字段时才需要 | **不要运行 `infra/scripts/seed_gov_procurement.py`**：它的输入是该中间产物目录，包内没有，硬跑会报 `FileNotFoundError`。库内容已由 3.2 的快照导入，无需重抽。 |
| 本地小模型权重 | bge-m3 约 2GB、重排约 2.2GB | 体积过大，且属第三方分发 | 首次运行自动下载；离线环境请自行放入 `models/` 并设 `BGE_EMBEDDING_MODEL`、`BGE_RERANKER_MODEL` 指向目录 |
| PDF 版报告 | 约 1–2 MB/份 | Word 可自行导出 | 用 Word 打开 `docs/.../*.docx` 另存为 PDF；本机导出脚本受组策略限制，未纳入包 |
| KAG 深度检索运行时 | 独立 Python 3.10 环境与服务 | 属研究支线，默认不接入问答链路 | 前端「深度检索 Beta」选项默认关闭；未配置时不影响主链路 |

## 六、已知边界（读分数前请先看这几条）

1. **政采结构化 30 题**对外报 53.33%（16/30），落在评分表 6 分档以下（≥70% 才有 6 分）。失败 14 题的分组与根因见记录文档 5.1。
2. **跨源 15 题**为 26.67%（4/15）。跨源路由的实体词表来自 `data/corpus/manifest.json`，政采法规文档词未进表，导致跨源题只走 SQL 一侧；根因与修法记录在记录文档第九节。
3. **文档单源 14/14** 的通过判据不要求「引用命中黄金片段」，同一份报告的 `hit_rate` 是 0.7143（14 题命中 10 题）；对外不给满分承诺。
4. **万行规模 27/30 与 p50 计时（3346–3612 ms）属 Chinook 合成销售表**，不是政采业务库，不能与政采题集相加；该基座的 `run_type` 明确标为开发期合成效率观测。
5. **多轮**四组用例 20 轮，只有 1/4 组全通过（`gmt-01` 4/5、`gmt-02` 2/5、`gmt-03` 1/5、`gmt-04` 5/5）。失败点与两根因见记录文档 5.6。
6. **KAG 深度检索**已接入前端但默认关闭，只提供候选片段、不生成答案；不参与上述任何分数。
7. 报告里的界面截图（图 6–10）需在真实前后端联调环境截取，受控 mock 截图不能作为证据；截图规程见 `docs/界面截图操作说明_20261018.md`。
8. **鲁棒性 18 题在同一题集上两个基线分数不同**：`e0183af` 上 88.89%（16/18），当前代码 72.22%（13/18）。差异来自三题：`grob-06` 单日查询被扩成一个月、`grob-15` 多连接了一条 `awards`、`grob-16` 对象识别不到「项目」。报这个分数时必须同时给基线，否则会被当成同一件事。正文引用的鲁棒性分数是另一套（chinook `robust_cases.jsonl`）的 16/18。详见记录文档 5.5。
9. **包内没有预置登录账号**，首次运行必须先按 3.4 创建管理员，否则界面停在登录页；这是 2026-10-18 异机演练暴露的缺口。

## 七、完整性校验

```powershell
# 逐文件摘要
python -c "import json,hashlib,pathlib; m=json.load(open('MANIFEST.json',encoding='utf-8')); print(m['file_count'], m['total_bytes']); \
bad=[f for f in m['files'] if hashlib.sha256(pathlib.Path(f['path']).read_bytes()).hexdigest()!=f['sha256']]; print('mismatch:', bad)"
```

`MANIFEST.json` 结构：`generated_at`、`source_commit`（打包所用 git 提交）、`file_count`、`total_bytes`、`files[]`（`path`、`bytes`、`sha256`）。
若 `source_commit` 与 `git rev-parse HEAD` 不一致，说明包不是从当前工作区最新提交打的。
