# EvoOntology 任务4消融实验设计 v0.3

日期：2026-10-04。状态：执行前冻结设计。定位：**探索性原因诊断，不作为独立确认性结论**。

## 研究问题

v0.2 的 C−A 只比较“检索知识＋筛选结构”这个组合，不能区分知识文本和结构范围各自的作用。v0.2 每臂只运行一次，模型后端地址也未记入冻结清单。若把旧 A/C 响应与新 D/E 响应直接比较，就无法排除跨轮服务端变化。

因此，本轮在原 32 道题上重放四种最终定位提示；旧 v0.2 只提供封存题目、Gold 和 A/C 提示词，**旧模型响应不进入本轮统计**。本轮四臂使用同一当前模型服务地址、同一运行器、同一计分程序，并对每道题随机排列请求顺序。

| 条件 | 可见数据库结构 | 最终定位提示中的业务知识 | 对照作用 |
|---|---|---|---|
| A | 全部 80 个表/视图 | 空 | 当前轮基线 |
| C | 原 C 臂筛选出的结构子集 | 原 C 臂检索到的知识 | 当前轮完整组合 |
| D | 全部 80 个表/视图 | 与原 C 臂完全相同的检索知识 | D−A 看完整结构下的知识输入；C−D 看相同知识下的裁剪结构 |
| E | 与原 C 臂相同的结构子集 | 去掉知识正文 | C−E 看相同结构下的知识正文 |

这一设计隔离的是**最终定位调用的输入因素**，不是从头重跑知识构建、检索和规划的端到端系统效果。C 的规划与检索结果被冻结复用；所以结果不能单独证明检索器自身有效，也不能替代项目链路的 SQL 执行测试。E 的子集来自原 C 知识参与过的规划，不能把它解释为全程无知识方案。

## 可信度控制与已知限制

- 四臂都重新调用，不把 v0.2 的历史响应与本轮新响应混算。模型名、脱敏服务地址、温度、输出令牌上限、超时、重试次数、运行库版本、题目、Gold、提示词来源、代码和数据库结构指纹写入冻结清单；快照用 SHA-256 校验。凭证不写入清单。
- 预检只要求旧 A/C 的最终定位提示存在且可读，不依赖旧 A/C/B 的成功状态。真正运行前再次核对模型名、服务地址、令牌上限、超时、重试次数、软件版本及真实凭证状态；任何变化都在发请求前中止。每条请求前再校验模型和服务地址。
- 每题 A/C/D/E 的调用顺序由固定种子预先随机排列，并串行发送，降低时间顺序和并发造成的混杂。每题每臂一条有效记录；失败、解析失败或无效输出按零召回计，不补题、不按结果删题。网络重试保留在原题原臂记录中。
- 32 道题来自同一 AdventureWorks 人工构造基准，且 D/E 的设计是在查看 v0.2 后提出。因此本轮只用于定位可能机制，样本小且不是独立盲测；无论区间是否排除零，都不作为“已证明值得接入”的确认性证据。
- 零命中时原 C 提示以字符串 `[]` 表示空知识，而 A 使用空字符串。为保证 C/E 的无命中输入一致，E 保留 `[]`；D 也复用 C 的原始字符串。因此 9 道零命中题的 D−A 存在空值序列化差异。报告同时给出按 C 是否命中预先分层的 D−A；命中子组中知识内容对照更直接，未命中子组只作格式差异诊断。分层依据在模型请求前已冻结，不按结果筛选。
- v0.2 冻结文件没有旧服务地址。本轮不拿旧 A/C 的分数参与比较，因此不要求推测或声称新旧服务地址相同；只能说明本轮四臂内部服务地址一致。

## 指标与分析

主指标为每题字段召回率，32 题等权宏平均。报告 A/C/D/E 各臂分数、逐题配对差值、题目级提升/持平/下降数，以及固定种子 2,000 次题目级配对 bootstrap 95% 区间。预先关注 D−A、C−D、C−E，并报告命中/未命中分层的 D−A。表召回率、字段精确率、调用数、词元用量和耗时为次要指标。

不得只凭点估计或单个显著性区间下结论；这轮多个对比属于探索性分析，也不把区间解释为独立复现。完整记录所有条件，包括不理想结果。

## 后续确认门槛

消融结果用于选定一个候选机制，不据此直接接入正式项目。下一轮须另建从未用于本轮调试的独立题集，题目和 Gold 在模型运行前由未参与调参的人独立编写、盲审并封存；明确主指标、最小有意义增益、排除规则和样本量估算，比较项目基线与唯一候选方案，并至少重复运行以测量模型波动。

只有独立题集上定位收益达到预设门槛，且真实 NL2SQL 链路的执行正确率、安全校验和耗时没有不可接受退步，才建议进入小范围接入试验。否则结论为“现有证据不足以接入”，并指出失败发生在知识命中、定位、SQL 执行或成本中的哪一环。
