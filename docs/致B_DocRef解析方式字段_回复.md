## 一、把「表格」从枚举里拿出去（最要紧）

你给的两组值不一致：

- trace 那组：`OCR / text_layer / plain`
- 卡片那组：`OCR / 表格 / 文本层`

问题在于，**「表格」跟「OCR / 文本层」不是同一个维度的东西**：

| 维度 | 回答的问题 | 取值 |
|---|---|---|
| 解析方式 | 这段字是怎么从文件里弄出来的 | ocr / text_layer / plain |
| 内容形态 | 这段原文长什么结构 | 表格 / 正文 |

**一张扫描件里的表格，这两个维度同时成立**：解析方式是 OCR、内容形态是表格。塞进一个单值字段，填哪个都是错的。

而且这两件事给用户的提示不一样：OCR 意味着**可能有错字**，表格意味着**可能行列对不齐**。根因不同，混在一起等于两条信息都丢了。

→ **本轮只落「解析方式」**。「表格」等有真实用例逼着要的时候**另立字段**，别挤进同一个枚举里。

## 二、字段名与取值范围

```python
extraction_method: Literal["ocr", "text_layer", "plain"] | None = Field(
    default=None,
    description=(
        "这段证据的提取方式：ocr＝扫描页走离线 OCR；"
        "text_layer＝PDF 自带文字层；plain＝md/txt/docx 等纯文本来源。"
        "按页判定；一个 DocRef 只对应一页，故取值唯一。拿不到留 None。"
    ),
)
```

**为什么改名字**：项目里「来源（source）」已经被「数据源」占用了（算 / 查分野、`doc_id` 才是文档来源），叫 `source_type` 容易被读成「数据源的类型」。这里想表达的是**提取方式**。

**为什么用 `Literal` 而不是 `str`**：能防住 `"OCR"` / `"ocr"` / `"ocr_page"` 这类漂移，前端也能做穷举。`kind` 本身就是 Literal，风格一致。
