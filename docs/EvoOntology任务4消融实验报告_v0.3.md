# EvoOntology 任务4消融实验报告 v0.3

实验日期：2026-10-04（Asia/Shanghai）  
运行目录：`eval/experiments/evont_next/run_task4_v0.3d_ablation`  
题集：32 道封存 v0.2 题；本轮 A/C/D/E 四臂均重新调用模型  
模型：`deepseek-v4.1-flash`，温度 0  
审阅：独立盲审通过；冻结前无阻断项

## 结论

**这轮没有复现“业务知识能稳定提高字段定位”的证据。** 当前轮实测 C（筛选结构＋按需检索知识）比 A（完整结构、无知识）低 1.17 个百分点；配对 95% bootstrap 区间为 **−23.05 至 +20.70 个百分点**。区间很宽，结果不能证明有害，也不能证明无效，只能说明 32 题不足以判断稳定增益。

最关键的消融也没有分离出明确的知识效果：完整结构下 D−A 为 +1.02 个百分点（95% 区间 **−20.86 至 +21.88**）；固定筛选结构下 C−E 为 +7.81 个百分点（95% 区间 **−12.50 至 +29.69**）。两个区间都跨过 0。

因此现在不建议把 EvoOntology 接进正式问答主链路。理由是增益尚未被证明，而检索和结构筛选会增加运行逻辑与维护成本。这是“证据不足，所以暂不接入”的工程决策，不是“已证明本体没有价值”。

## 实验做了什么

四臂在相同 32 道题上重新运行，使用同一冻结模型服务、运行器和计分程序；旧 v0.2 的模型回答完全没有进入本轮统计，只用来提供封存题目、Gold 和原 A/C 提示词。A/C/D/E 每题都重新发送一次最终定位请求，题内顺序按固定种子随机化并串行执行。

| 臂 | 最终定位调用看到的内容 |
|---|---|
| A | 完整 80 个表/视图，无业务知识 |
| C | 原按需检索得到的结构子集和知识条目 |
| D | 完整结构和与 C 完全相同的知识条目 |
| E | 与 C 完全相同的结构子集，无知识正文 |

这隔离的是**最终定位提示的输入因素**，不是从头重跑构建器和检索器的端到端效果。尤其 E 的结构子集来自原 C 的规划；它不能代表一个全程不接触知识的独立系统。

## 结果

主指标为字段召回率：逐题计算命中 Gold 字段数占该题 Gold 字段数的比例，再对 32 题等权平均。失败和无效 JSON 按零召回计。

| 臂 | 字段召回率 | 表召回率 | 字段精确率 | 总词元 | 每题请求数 | 中位耗时 / P95 |
|---|---:|---:|---:|---:|---:|---:|
| A | 77.11% | 78.12% | 68.36% | 331,694 | 1 | 6.82 秒 / 21.98 秒 |
| C | 75.94% | 78.12% | 67.48% | 93,986 | 1 | 5.76 秒 / 25.15 秒 |
| D | 78.12% | 78.12% | 67.39% | 336,010 | 1 | 5.99 秒 / 15.21 秒 |
| E | 68.13% | 71.88% | 63.65% | 79,156 | 1 | 5.39 秒 / 15.45 秒 |

| 配对对比（右减左） | 字段召回率差值 | 95% 配对区间 |
|---|---:|---:|
| C−A（实用方案对基线） | −1.17 个百分点 | −23.05 至 +20.70 |
| D−A（完整结构下加入知识） | +1.02 个百分点 | −20.86 至 +21.88 |
| C−D（相同知识下筛选结构） | −2.19 个百分点 | −19.38 至 +15.62 |
| C−E（相同结构下加入知识） | +7.81 个百分点 | −12.50 至 +29.69 |

按原 C 检索结果分层，23 道命中题的 D−A 为 +1.41 个百分点（95% 区间 **−21.20 至 +26.63**）；9 道未命中题为 0（区间 **−44.44 至 +44.44**）。分层在运行前按检索记录确定，没有按模型结果挑题。未命中时 C/D 使用字符串 `[]`，A 使用空字符串，所以未命中层也包含空值序列化差异。

128 条请求共返回 840,846 词元；网络尝试也是 128 次，没有发生重试。3 条模型回答未能解析为规定 JSON（A 1 条、D 2 条），按预定规则保留并计零；其余 125 条解析完成。每条请求均返回完整用量字段。

C 末端定位提示平均用词元 2,937，对比 A 的 10,365 低约 72%。这只计算本轮最终定位调用；**不包括** C 原流程中知识检索规划所需的额外模型调用，也不能据此声称整个系统便宜 72%。按需方案表现出明显的输入缩减，但准确率没有形成可确认增益。

## 可信度与边界

- D/E 设计是在 v0.2 结果之后提出，因此本轮是事后消融，定位为探索性诊断。独立盲审检查了因果对照、执行顺序、冻结配置、错误规则和统计分组，冻结前结论为通过。
- 本轮只使用当前运行里的 A/C/D/E 新回答，避免 v0.2 没记录服务地址带来的跨轮服务混杂。冻结清单包含模型名、脱敏服务地址、温度、令牌上限、超时、重试和软件版本；运行前复核配置，所有代码与输入均有 SHA-256 快照；运行后 14 项输入哈希无差异。
- 32 道题是人工构造的 AdventureWorks 定位基准，不代表真实项目用户问题；每题每臂只运行一次，估计区间很宽。评测只看定位候选，不执行 SQL，也不覆盖问答正确率、安全或线上维护成本。
- 结果未发现稳定增益，不等于证明本体无效。它只是不足以支持目前接入正式项目。

## 是否接入项目

**现阶段结论：不接入正式主链路；可以保留为独立研究分支。** 若导师要求更强结论，下一步应在本报告完成后才揭盲的新题上复验，并进入只读 SQL 执行级别评估；若没有新题上的定位收益，就停止接入。当前统计也显示，要稳定检出较小提升需要远多于 32 题，因此小样本复验只能作方向判断，不能把“未显著”包装成“相同”或“无效”。
