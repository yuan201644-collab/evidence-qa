# EvoOntology 任务4直接定位实验报告 v0.2

实验日期：2026-10-04（Asia/Shanghai）  
运行目录：`eval/experiments/evont_next/run_task4_v0.2`  
题集：封存版 v0.2，32 道独立问题  
模型：`deepseek-v4.1-flash`，温度 0  
测量对象：模型直接返回的候选表与候选字段，不执行 SQL。

## 结论

**目前不能确认按需本体检索方案能提升字段定位。** C 组比无知识 A 组的字段召回率高 2.97 个百分点，但配对 bootstrap 95% 区间为 **−16.41 至 +22.66 个百分点**，包含 0，按预先确定的规则属于“证据不足”。这不等于证明方案无效。

整本注入知识的 B 组点估计最高，比 A 组高 15.62 个百分点；但其 95% 区间为 **0 至 +31.25 个百分点**，下界没有大于 0，也未达到本轮正向增益判据。不能据此下确定性结论。

因此，这轮实验不支持把 EvoOntology 直接接入正式问答链路。更准确的结论是：整本知识注入显示了较大的正向趋势；按需检索与结构筛选组合的平均增益很小且不稳定；两者都需要更多独立题目验证。

|---|---:|---:|---:|---:|---:|---:|---:|
| A：全结构、无知识 | 80.63% | 81.25% | 72.81% | 66.25% / 80.03% | 10,113 | 32 | 6.36 秒 / 15.49 秒 |
| B：全结构、整本知识 | 96.25% | 96.88% | 80.61% | 81.59% / 95.65% | 16,099 | 32 | 6.66 秒 / 37.90 秒 |

各组均为 32 道题。模型响应解析完成率为 96/96，模型请求共 128 次，记录到的总用量为 977,211 词元；所有记录均返回完整用量信息。C 组的知识检索流程 32/32 次正常完成，其中 23 题命中至少一条知识、9 题没有命中知识条目。

## 配对比较

| 比较（右组减左组） | 字段召回率差值 | 配对 bootstrap 95% 区间 | 题目级变化：提升 / 不变 / 下降 |
|---|---:|---:|---:|
| B − A | +15.62 个百分点 | 0 至 +31.25 个百分点 | 6 / 25 / 1 |
| C − A | +2.97 个百分点 | −16.41 至 +22.66 个百分点 | 7 / 19 / 6 |
| C − B | −12.66 个百分点 | −26.72 至 +1.25 个百分点 | 2 / 24 / 6 |

C 组把可见结构平均从 607 个字段压到约 56 个字段，词元用量比 A 组低约 57%；但每题需要两次模型请求，且中位耗时比 A 组长约 42%。因此它表现出输入缩减效果，没有表现出已验证的定位准确率提升。

C 组检索由模型先拟定检索词，再用本地确定性词项匹配知识条目的名称、别名、编号和表名；不是向量检索，也不是论文系统的完整复刻。9/32 题没有检索到知识条目，但规划器仍可从完整表名目录中选表，再由运行器仅提供所选结构。这意味着 C-A 的结果还混合了“无知识时由模型选表并裁剪结构”的情况，限制了对本体知识独立贡献的判断。

## 如何解读

本实验只评价定位候选，不评价生成 SQL 的正确性、执行正确率或最终问答质量。A/B/C 的输入差异也决定了因果解释范围：B−A 对应整本知识注入；C−A 对应“按需检索知识＋筛选数据库结构”的组合；C−B 比较两种完整策略。C−A 不能单独分离本体知识和结构裁剪各自的作用。

32 道题的区间较宽，题集是人工构造的 AdventureWorks 基准，也不代表真实用户问题分布或赛题得分。每题每组只运行一轮（C 组含一次规划与一次定位请求），没有通过重复请求估计模型随机波动；因此结果适合作为方向性证据，不适合泛化到其他数据集。

## 建议

暂不接入正式问答链路。若要继续验证，下一轮优先补两个消融条件：完整结构＋检索知识，以及筛选结构＋无知识。这样能区分 C 组的知识检索与结构裁剪贡献；再扩大独立题数并重复运行，避免把当前的点估计当成稳定收益。
