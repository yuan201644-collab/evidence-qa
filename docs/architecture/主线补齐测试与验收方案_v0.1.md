按“修复定向检查 → 原主线回归 → 真实入口联调 → 任务专项 → 独立新题对照”的顺序执行。先证明正常问题可以回答、异常条件可以拦住，再评估准确性与代价。本方案覆盖本轮任务 3/4/5 接入与代码修复，也检查对原问数、文档问答和工单—合同链路的影响。

本轮最终要回答三个不同问题：

1. 工程正确性：新模块是否接入真实入口，是否误拒正常查询、漏放错误关联或破坏原链路？
2. 任务能力：能否真正完成澄清恢复、数十表定位、多表关联及聚合/嵌套查询？
3. 效果证据：冻结后的独立新题中，相比原主线是否减少错误并保持正常问题可答，耗时与调用成本怎样变化？

单元测试（unit test，隔离某个模块检查确定行为）可以使用工具替身。系统效果必须来自实际模型、实际数据库和实际文档检索的输出。标准答案回放只能验证判定器。

### 2.2 优先核查的已知问题与能力缺口

1. **正常 JOIN 别名的登记顺序。** 当前 `semantic_validator.py` 先调用 `_qualified_equalities`，之后才把当前 JOIN 目标别名放进映射；前者会过滤掉未登记的目标列。因此第一个用例必须是具有正确外键、带两侧别名的普通 JOIN，并检查它确实可执行。此为静态发现，尚无运行复现结果；验证失败后先修实现，不能改预期为拒答。
2. **原评测器与公共入口不完整匹配。** `eval/runner.py` 的 HTTP 请求没有必需的 `session_id`；澄清解析读取 `clarified` / `needs_clarification`，没有读取 `AskResponse.need_clarify`。不能原样对 `/api/ask` 执行并将 HTTP 错误或错误映射当系统成绩。
3. 定位当前只有关键词/别名，没有接入向量召回。实验必须记录降级状态；不能称为已验证向量定位。
4. 关联计划依赖目录外键；缺外键业务关系、复杂作用域、部分嵌套/左连接和完整粒度推理尚未支持。
5. 会话锁只保护状态读写，尚未实现同会话请求全程串行化；短追问以文本合并为主，不能仅靠保存了历史就算多轮通过。

对于答案可确定的嵌套/左连接问题，安全地停止可以通过安全检查，但仍属于任务能力失败。不能把全部“不支持”改写成正确拒答后宣称任务 5 完成。

## 5. T1：本轮修复的定向用例

每组同时有应通过与应阻断的输入。用例预期来自数据库约束、业务定义或实际执行结果，不依赖“当前代码返回什么”。

| 编号 | 用例 | 必须观察的结果 |
|---|---|---|
| J01 | 正确普通 JOIN，两侧使用别名；再测无别名及反向列顺序 | 完整外键可核验；实际执行器被调用；结果正确 |
| J02 | 正确关联加括号、额外 AND 筛选 | 仍放行，不能因括号或筛选误拒 |
| J03 | 正确外键等式 OR TRUE / OR 其他放宽条件 | 不执行；记录具体原因；有限修复仍须完整再校验 |
| J04 | 复合外键全列、缺一列、错误列、各列分别连接到不同父表别名 | 只有同一父表实例的完整列组可通过；各列拼凑关系不能通过 |
| J05 | 三表关联，但新增表 ON 只引用前两张表的等式 | 阻断，不能拿历史等式证明新表已连接 |
| J06 | 员工与主管合法自关联；错误列或 ON TRUE 自关联 | 不可按表名去重跳过检查；合法查询要能完成，错误查询不能执行 |
| J07 | 跨 schema 同名表，全限定与歧义裸名 | 正确 schema 可识别；歧义不能靠裸名碰巧放行 |
| G01 | 发票父表金额 SUM，显式别名、无别名、算术表达式 | 都检测重复汇总风险；不是只对固定写法生效 |
| G02 | 明细字段正确汇总；一对一连接；正确预聚合 | 可判的正确查询不误拒；当前不支持的预聚合记录能力失败 |

### 6.2 真实入口联调顺序

1. Chinook：单表计数 → 带筛选查询 → 合法两表 JOIN → 三表/聚合 → 缺项澄清后完成 → 同指标短追问。
2. AdventureWorks：全限定大小写表名 → 相近业务表 → 跨 schema 外键 → 正确中间表；核对实际活动库与目录。
3. 文档：原单文档问题、多文档问题、证据不足问题；分别检查回答、实际检索步骤和引用，不能用答案引用近似值冒充完整召回。
4. 工单—合同：合法满足/超时、客户冲突、映射与合同有效期分别不覆盖、关键事件缺失/倒序、非受控依据、多合同。开关 0 与 1 都检查共享 SQL 工具带来的影响；旧曝光题全部标回归。
5. 前端：同一会话补充、取消、新会话、步骤名称、SQL 面板、引用打开/高亮、错误状态。未实际执行的草稿不能展示为成功 SQL。

先用公开开发题验证判据和解决失败，再冻结代码。建议开发专项每任务至少 20 个业务场景，多轮按完整会话计一题；正例和异常例均覆盖上述矩阵，不把数量当成通过证据。

| 任务 | 主要指标 | 建议工程目标 |
|---|---|---|
| 3 澄清 | 缺项召回、无必要追问、补充后完整完成、会话隔离 | 缺项发现与完成率各 ≥90%；完整题误追问 ≤10%；隔离/取消/预算关键测试全过 |
| 4 定位 | 必需表/字段候选覆盖、最终选择正确、干扰表误选、合法路径补全 | 必需表字段候选召回 ≥95%；最终选择正确 ≥90%；同时公开精确率和失败题 |
| 5 SQL | 可回答题的执行结果正确率、错误关系拦截、正确关系误拒、按形态分组 | 执行正确率目标 ≥90%；关键错误关系执行 0 次；嵌套/左连接失败不能从分母删除 |
| 来源与步骤 | 来源真实、必要引用完整、步骤对应调用、错误投影准确 | 关键引用与执行状态无伪造；正确性和证据分别统计 |
| 效率 | 端到端中位数/95 分位、模型调用/重试、定位与校验耗时 | 不超已配置预算；与基准同时报告绝对值与差异，不预造时延成绩 |

定位判据允许独立复核确认的等价表/字段/路径；必需业务表、路径中间表和干扰表分角色标注。候选召回不能代替最终选择正确率；候选多、全部塞回整库也不能只靠高召回算成功。

SQL 比较复用结果集合、多重集与数值容差；有排序需求才检查顺序。额外检查业务结论是否完整，不能只有正确数字就算回答完毕。数据必须能区分不同口径：错误 JOIN、错误聚合、错误筛选不能恰好与标准 SQL 同结果。

合法但实现暂不支持的题保留在对应专项分母中。单列“安全停止率”和“任务完成率”，不能合并为一个通过率。超时、服务错误、空响应、不必要拒答同样登记失败。
