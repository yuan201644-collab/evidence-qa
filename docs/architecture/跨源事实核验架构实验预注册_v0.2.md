关联稿：`跨源事实核验架构实验预注册_v0.1.md`。本稿在任何新留出题运行前，细化比较组与可归因范围；不追溯改变已完成实验。

## 一、研究问题与可归因边界

研究问题不是“新架构整体是否优于旧系统”，而是更窄、可复核的问题：在相同的事实任务图、NL2SQL（自然语言转 SQL）工具、RAG（检索增强生成）工具、模型配置、数据及文档语料下，启用跨源关系/口径核验和依赖早停，是否能减少不成立关系、异常时间线、条款冲突条件下的错误肯定回答；相应增加多少拒答、调用与耗时。

本比较估计的是“严格事实核验策略”的总策略差异。若严格组拒绝某映射而消融组沿用首个候选，后续合同编号与检索查询随之不同，这是被测策略的中介结果，不视为输入不匹配。两组不得据此宣称隔离出某一条规则的单独因果贡献，也不得据此证明整个项目架构、通用多跳能力、赛题中级任务验收或真实业务泛化。

## 二、实验组和共同机制

| 项 | 严格核验组 B | 宽松规则消融组 A | 两组共同保留 |
|---|---|---|---|
| 任务图 | 工单→映射→合同条款/事件→结论 | 相同任务图 | 相同任务节点、节点问题模板和工具注册 |
| 映射判据 | 核验编号 JOIN/过滤、唯一性、受控依据、客户、映射与合同各自有效期、合同状态 | 若有可解析候选则取第一条；不核验上述业务条件 | 必须有候选行、必要展示字段和真实 SQL 来源，不能凭空造合同编号 |
| 合同证据 | 对同一份已重排候选，核设备适用范围、条款唯一性、起止指标定义和请求的 SLA 指标 | 对同一候选取首个可解析时限；不核验范围、冲突或口径 | 合同检索均限定到所选合同编号；没有文档引用/无法解析条款时不编造数值 |
| 事件与计算 | 核事件唯一性、时区、工单范围、起止引用完整和非负时间顺序 | 使用同一 SQL 返回行，计算可解析的受理/响应/恢复时差，不执行业务异常核验 | 查询只读、事件类型必须可解析、所有最终回答至少引用真实执行来源 |
| 依赖失败 | 前置事实不受支持时停止下游任务 | 尝试执行下游任务；仍不能绕过工具错误、缺字段和账本来源约束 | 相同编排任务图、运行器与公共契约 |

共享的 SQL 来源检查、必要字段解析、合同文档限定、来源对象真实性和响应引用约束，是测量基础设施，不计为严格组独有机制。因此 A 不是“无工具/无来源约束”的稻草人，而是对严格业务核验与早停策略的宽松规则消融。结果若改善，只能支持该策略包在本题型中的机制效果。

## 三、匹配与运行顺序

- 固定相同代码快照、Python 依赖、SQL 方言/只读配置、问题、结构化库、合同文档、向量索引快照、模型名称、模型端点、temperature、超时/重试和节点调用上限。API 密钥不进入报告或清单。
- A/B 使用同一 `build_work_order_sla_plan`、节点问题模板与 NL2SQL/RAG 装配代码；严格规则开关是预先指定的处理差异。修复或调整任何实验相关代码、规则、提示、数据后，本轮未见题作废并降级为回归。
- 每题按预先生成的随机顺序交错运行 A/B，避免固定先后顺序造成缓存或服务负载偏差。保存实际运行顺序、每次节点输入、SQL、RAG 候选/重排引用、原始回答、trace、异常、耗时及哈希；不得人工重跑后覆盖首次结果。
- 运行者在全部 A/B 原始结果封存并生成哈希前不读取 gold、配对密钥或作者解释。比较器与盲审表单在揭盲前冻结。
- RAG 本地索引初始化/缓存预热单独记录；若两组发生不同的首次建索引成本，主耗时报告同时给出含预热和稳态口径，不只挑较好口径。

## 四、评测口径

所有题和运行错误均保留在分母，并按题报告 A/B 配对转移。至少报告：

1. **错误肯定**：题目不支持“满足/超时”确定结论但系统仍肯定作答的数量；区分无效关系、缺失/冲突证据、时间异常等原因。
2. **可回答题正确性**：结论正确数/可回答题数；另报无法判断率、过度拒答数，避免只看拒答带来的安全表象。
3. **证据质量**：由两位未参与实现与数据编制的盲审者独立评估结论正确性、证据充分性、来源引用匹配与完整性；分歧保留并交第三人裁决。盲审者不见组别、gold 和系统自评。
4. **执行合规**：trace 中真实 SQL 与过滤/连接、候选文档来源、早停条件、工具错误、预算和最终引用是否符合冻结协议；由独立审计者基于原始 trace 核验。
5. **代价**：每题端到端耗时、NL2SQL/RAG/模型调用次数、执行错误数。只有能从服务端响应可靠取到的 token/费用才报告；否则明确为未测。

题量较小，主要提供计数、比例和逐题配对结果，不做“统计显著”“普遍提升”或行业泛化主张。应同时给出对错误肯定和正确回答的原始题数，不以单一综合分掩盖安全—覆盖率权衡。

## 五、泄漏、偏差和停机规则

- 既有 `cross_source_demo`、所有 v0.1–v0.6.8 及此前作者/运行者看过的题一律是开发/回归题，不重新贴“未见”标签。
- 数据作者与独立复核者分离；复核者从 CSV、合同原文和题目独立重算 gold、引用片段及事件时长。运行者不接触受控 gold。盲审者只看去组别的答案与原始证据。
- 代码/数据/提示/模型配置哈希漂移、gold 或密钥泄漏、连错数据库、写操作 SQL、trace 丢失、评测脚本误配时停止并保留原始现场，不静默重跑覆盖。
- 新题上发现实现缺陷后，先封存失败输出；修复后本批只作为已曝光回归，另建新题才能重测。
- 若模型/API 中断、嵌入索引状态不一致或任何一组没按协议完整运行，报告运行失败和缺失，不删题、不补模拟结果。
