## 二、设计原则：不加新路由，加一个开关

后端已有 `/api/ask` 与 `/api/ask/stream`，前端 `ask.ts` 已经按 SSE 消费
（`stage` / `complete` / `error` 三类事件）。所以**不新增对外路由**，只在
`main.py` 里把 `_orchestrator.answer(...)` 换成一个分发函数：

```python
def _answer_dispatch(question, session_id, *, progress_callback=None, **kw):
    if os.environ.get("ASK_BACKEND", "orchestrator").lower() == "kag":
        return kag_ask.answer(question, session_id, progress_callback=progress_callback)
    return _orchestrator.answer(question, session_id, progress_callback=progress_callback, **kw)
```

- 默认 `orchestrator` = **老行为一字不变**，随时可回滚
- 环境变量切 `KAG` 即走新链路
- 前端 `api/ask.ts` 只改超时，不改调用方式

## 三、KAG 客户端协议（从服务器 `build/run4arm.py` 逐行读出，已验证可用）

```
① POST /v1/accounts/login
   body {"account": "openspg", "password": sha256(pwd + "OPENSPG")}
   → Set-Cookie

② POST /public/v1/reasoner/session/create   (Cookie)
   body {"appId": 5, "name": "<自定义会话名>"}
   → {"id": <session_id>}

③ POST /v1/chat/completions                 (Cookie)
   body {"prompt":[{"type":"text","content":<问题>}],
         "session_id": <sid>, "app_id": 5,
         "thinking_enabled": true, "search_enabled": true}
   → SSE，逐行 `data: {...}`
```

SSE 里三个可用字段：

| 字段 | 内容 | 用途 |
|---|---|---|
| `answer` | 累积答案（每帧是全量，取最长） | `AskResponse.answer` |
| `documents[].document_name` | 命中文档名 | 文档列表 |
| `subgraph[].resultNodes[].name` | 块名 `<DOC>_v2_split_<N>` | **refs 来源** |
| `subgraph[].resultNodes[].properties.content` | 块正文 | **refs.snippet 来源** |

块名还原：`^(.+?)_v2(?:_split_(\d+))?$` → 文档 id + 块序号。

⚠️ SSE 必须**跨 chunk 行缓冲**（按 64KB 切会丢流尾答案，且字节数看不出异常），
收尾要 flush 残留行 —— 这两条是跑批阶段踩过的坑，直接沿用。

## 四、事实表从哪来：后端重算，不从容器导出

这是本方案最关键的一个决策。

| 方案 | 做法 | 问题 |
|---|---|---|
| ❌ 容器导出 | `feva_override` 把表写 JSON，后端去读 | 容器内 `/tmp` 对外不可见；要额外开文件服务；跨机传数据 |
| ✅ **后端重算** | 把 `facts.py` + `ledger.py` + `records.json` 随应用分发，后端自己算 | 无（纯 Python + 一个 JSON，1031 条 / 333KB） |

**可行性的硬依据**：`facts.py` 与 `ledger.py` 顶层只 import `json / os / re / urllib`，
不依赖 `kag` 包；`build(question, ledger, with_evidence=False)` 完全离线。

唯一的缺口是"证"这一环（`evidence()` 走 Neo4j）。但**证据块可以从 KAG 的 SSE 里拿**——
`subgraph.resultNodes` 里就带着该文档的块名和正文。于是：

```
拆 / 判  → 后端本地算（facts.build, with_evidence=False）
证      → 从本次 KAG 响应的块名里，按文档筛出块，分配给各行
```

**额外收益**：后端算出的表与容器内生成的表同源同算法，可以互相对照 ——
演示时"答案里的数字"与"界面上的表"能对上，是真一致性而非巧合。

### 代码归位（顺带解决上轮的遗留问题）

把 `build/feva_override/{facts,ledger}.py` + `_records.json` 移进
`contrib/kag/feva_override/`，`app/kag_engine.py` 用 `importlib` 按**文件路径**加载
（绕开 `feva_override/__init__.py` 里的 kag 导入）。这样：

- `contrib/kag/` 里第一次真正包含了**赢分的那套代码**（上轮指出的归属问题）
- 应用侧不复制代码，只有一份真身

## 五、字段映射（KAG → AskResponse）

| AskResponse | 来源 | 备注 |
|---|---|---|
| `answer` | SSE `answer` 最长帧 | 原样 |
| `refs[]` | `subgraph.resultNodes` 去重 | `DocRef(kind="doc", doc_id=<DOC>, doc_title=<DOC>, snippet=<正文前 200 字>)`；`page/bboxes` 留空（我们的语料是 txt，无页坐标） |
| `trace[]` | 自己造 3 步 | `kag_plan` → `kag_retrieve`（hit = refs）→ `kag_generate`（answer_len） |
| `fact_review` | `facts.build()` + 块名映射 | 见下 |
| `sql` / `result_set` / `need_clarify` | `null` / `null` / `false` | KAG 链路无 SQL |
| `suggestions` | 可空 | 后续可放"换个问法" |

### FactReviewItem 扩展（`extra="forbid"`，必须显式加字段）

```python
value: str | None = None          # 判定值，如 "**38 项**"
criterion: str | None = None      # 口径，如 "AH24 · 滁州学院 · 重点类"
evidence_chunk: str | None = None # 块名，如 "AH24_v2_split_3"
```

映射规则：

| 事实表字段 | → FactReviewItem |
|---|---|
| 行标签 `label` | `label` + `summary` |
| 判定 ✅支持 / ⚠️无据 | `status = supported / insufficient` |
| 值 | `value` |
| 证据块列表 | `evidence_chunk`（首个）+ `evidence_ref_indices`（按块名匹配到 refs 的下标） |
| 恒定 | `execution_status = completed`，`fact_id = f"row_{i}"` |

⚠️ `evidence_ref_indices` **必须指向真实存在的 refs 下标**，否则
`FactReviewCard.hasValidEvidence()` 判假、卡片降级成"证据未关联"。

## 八、风险与对策

| # | 风险 | 概率 | 对策 |
|---|---|---|---|
| 1 | 演示现场连不上 8887（换网络/断 VPN） | 中 | 启动时探活；`/api/kag/status` 返回 `unavailable` 时前端提示；演示前 30 分钟必测 |

### 12.2 关键实测（推翻方案里一条假设）

方案 §4 写「KAG 的 SSE 里 `subgraph.resultNodes` 本来就带着块名和正文」——**实测确认成立**：

```
resultNodes 总数 = 93，带 properties.content 的 = 93（100%）
样本：AH24_v2_split_4 / 460 字 / score 1.0625
```

所以证据块不必回查图数据库，直接从响应取。另外三个实测事实：

1. **`reference` 字段是空数组**（`[]`），KAG 没填，引用表必须自己从 `resultNodes` 造。
2. **`resultEdges` 全是 0 条**，图边不会下发；「图作证」只能靠事实表里的块名体现，
   图规模数字走静态快照接口（`/api/kag/remote`）。
3. **块名带双引号**（`"\"AH24_v2_split_2\""`），不 strip 就永远匹配不上文档前缀。

### 12.5 与方案的偏差（都已记录，不改）

1. **首页三入口 → 两入口**（名单统计 / 条款查找），侧栏「数据库连接」换成「事实核验」。
   老项目的问数与跨源入口依赖业务库与工单—合同语料，本项目没有这两份数据。
2. **事实表页做成弹窗面板**，不是独立路由：答案卡里已经有逐行事实，独立页的价值在
   「不提问也能看判定过程」，弹窗足够且不打断会话。
3. **`AskResponse.trace` 用三假步投影 KAG 的三段**（kag_plan / kag_retrieve / llm_generate），
   不是真实工具链，字段值取自本次响应。前端 `hasUnresolvedToolFailure` 只认
   `output.error` 非空的步，因此不会误判失败。
