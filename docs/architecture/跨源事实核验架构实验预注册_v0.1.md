# 跨源事实核验架构实验预注册 v0.1

登记日期：2026-10-04  
适用范围：工单—合同 SLA 跨源问答原型；不外推到通用事实规划、赛题任务四/五或真实业务泛化。  
状态：问题、判据与比较原则预先固定；具体新题尚未编制，代码也尚未冻结。

## 1. 可证伪主张

在数据库与文档工具相同的条件下，显式维护事实依赖、确定性核验对象对应/有效期/客户范围/事件口径，并将已支持事实绑定到来源，能够减少跨源负例上的无依据肯定结论；代价是更多模型调用或更高延迟。实验允许结果为“未观察到改善”或“可靠性提高但成本不可接受”。

## 2. 实验阶段与冻结门

1. 已知样例回归：使用 `data/cross_source_demo/cases.jsonl`，仅验证功能和修复缺陷；样例全部视为已曝光，不能作为泛化证据。
2. 冻结实现：运行全仓库自动测试，冻结代码快照、依赖、LLM/嵌入/重排模型标识、提示、检索参数、事实规则、运行器与数据库/文档哈希。冻结后若修代码或判据，本轮新题立即降级为回归，需另建留出集。
3. 独立建题：题目作者不承担系统运行；标准答案与可接受证据另存于受控目录。独立复核者逐题重算关系、时限、事件与证据；运行者只拿问题包，不拿 gold、作者说明或配对密钥。
4. 原始运行：相同问题、数据快照、工具实现、模型配置和每题工具预算运行匹配基线与事实计划组；题目顺序及组别顺序交错。先保存双方原始答案/trace/耗时，再解封答案标准。
5. 匿名盲审与解盲：对答案/引用去组别化并随机编号，评审者只看问题与证据，不看组别和 gold；另由审计者检查 trace/SQL/检索是否符合冻结协议。完成后才将判断映射回实验组并对照标准答案。

## 3. 比较组与可归因条件

- **事实计划组 B**：当前私有事实计划、依赖早停、确定性规则核验与证据账本。
- **匹配消融基线组 A**：尽量复用 B 的同一 NL2SQL、RAG、模型、提示、数据/索引和子任务查询；去掉“只有 supported 才继续”、跨源规则校验与按事实筛选引用，按固定顺序直接收集候选并形成判断。每题为 A/B 设相同的最大调用次数和总时限；B 提前停止所省调用照实记录。
- **操作性可比门**：运行前用相同的一组已曝光校准题确认两组的数据、工具版本和输入子问题一致。若 A 不能复用相同底层工具/输出生成条件，或实际查询预算明显不同，则本轮只能报告“两个系统方案的比较”，不得把差异归因于架构机制。旧固定 SQL + BM25 演示工具可作为生态参考组，但不作为严格因果基线。

## 4. 新题构成与主要指标

独立题包目标为 12 题，至少包含：可回答正例（满足、超时、恰等于边界）、过期/未来有效期、无映射、非受控映射、客户冲突、多个有效候选、缺关键事件、事件倒序、合同条款缺失或冲突。构成允许在题包冻结前调整，但必须在运行前记录题数、判据和排除规则；不得根据某组输出重写 gold。

主要指标：

1. 负例上的错误肯定数/比例（无效关系、缺证据或时间异常仍判满足/超时）。
2. 可回答题的三分类结论正确数；并列报告拒答/无法判断率和过度拒答数。
3. 逐事实证据充分、引用匹配、引用完整性，由两位盲审者独立填写；分歧交第三人裁定。
4. 失败路径与 trace 合规：实际早停条件、SQL 过滤/连接、文档编号、入选证据、是否越预算。
5. 成本：每题端到端耗时、SQL/RAG/LLM 调用数；只有能从服务响应可靠读取时才报告 token/费用。样本不足时不报显著性或泛化结论。

所有失败题、运行错误和拒答都保留在分母中，不因答案不理想而剔除；同时给逐题 A/B 转移表和原始文件哈希。

## 5. 泄漏与失效停机规则

- 当前既有题、v0.1–v0.6.8 已曝光题及任何开发调试题都不能标作未见留出。
- 运行者在双方原始输出生成前不得查看 gold、密钥、作者推理或逐题预期行为；盲审人不得解盲。
- 代码/配置/题包哈希漂移、答案泄漏、访问非隔离数据库、只读约束违例、trace 伪造/丢失时暂停实验并记录，不能静默重跑覆盖。
- 任何新题上发现实现缺陷后，先保存失败原始运行；修复后当前题集降级为回归，不再报告为盲测成绩。
- 如果事实计划组未优于匹配基线，仍按预注册判据报告，不继续调参追分后复用本批题。
