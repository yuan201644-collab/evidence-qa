# 跨源事实核验架构独立复验预注册 v0.4 修订

版本日期：2026-10-09  
状态：候选修订；未冻结、未外部登记、未运行。  
适用范围：仅适用于 CS18 v0.6；与 v0.1 主预注册及 v0.2、v0.3 修订合并阅读。本修订只明确 Gold 状态字段的语义，不改变题目、数据、两臂、评分、隔离或运行门槛。

## 1. 修订原因与版本关系

针对 CS18 v0.5 的独立复核指出，CS18-043/044 各有两条同时满足本题集结构化关联条件的候选合同。它们不是映射依据、有效期、合同状态或客户主体等前置条件不成立；将其标为 `prerequisite_blocked` 会混淆“前置条件失败”和“多个有效候选并存”。因此新增专用 Gold 状态 `ambiguous_active_contracts`。

本修订对应候选批次 `2026Q4_fresh_cs18_v0.6`。v0.1–v0.5 的候选和 Gold 均作为历史版本保留，不因本修订而重写或改判。v0.6 只对 CS18-043/044 的 `expected_metric_state` 作语义细分；这两题仍为 `expected_status=not_determined`，并保留 `expected_early_stop_reason=ambiguous_active_contracts`。

## 2. 状态字段的分工

- `expected_status` 表示题目要求的最终业务回答类别；多候选题因不能唯一确定合同，仍为 `not_determined`。
- `expected_metric_state` 表示计算条件或业务证据的状态。`prerequisite_blocked` 只用于结构化关联依据、映射/合同有效期、合同状态或客户主体等必要前置条件不成立，因而无法形成合格候选的情况。
- `ambiguous_active_contracts` 表示至少两份合同分别具有合格的结构化设备关联，映射与合同日期均覆盖工单日期、合同状态为 `active`、合同客户与设备客户一致，但仍有多份有效候选，无法唯一选定适用合同。它不等于前置条件失败，也不代表已经计算或判定 SLA。
- `expected_early_stop_reason` 表示执行流程应记录的早停原因码；它描述流程为何停止，不替代 `expected_metric_state`。

CS18-043/044 的 Gold 应列出设备、工单、每条候选映射和对应合同的结构化记录；在此状态下不要求合同检索、合同片段、服务恢复时长或 SLA 结论。只有一个有效候选时不得使用 `ambiguous_active_contracts`；若候选因前置条件失败而被排除，则按相应结构化阻断类别判定。

## 3. v0.6 枚举补充

`expected_metric_state` 继续沿用 v0.3 修订中列出的枚举，并新增：

- `ambiguous_active_contracts`：存在多份分别满足本题集结构化适用条件的有效合同候选；题目询问唯一适用合同，因此应报告无法唯一确定，并提供所有有效候选的结构化证据，不得任选一份进行 SLA 计算。

除 CS18-043/044 外，v0.6 不应使用该状态。结构化前置条件不成立仍标 `prerequisite_blocked`；已确定唯一适用对象后，合同原文存在冲突时仍标 `sla_unresolved`。

## 4. v0.6 静态检查要求与解释限制

候选校验器应逐项确认 CS18-043/044 的两条映射、两份合同及客户/有效日期/状态记录支持“多个有效候选”，Gold 状态为 `ambiguous_active_contracts`，早停原因码保持一致，且没有 SLA 数值或合同检索要求。历史 v0.5 仍按其原状态契约校验。

任何静态作者侧构建或校验结果只说明题包、Gold 与清单之间满足所编码的静态一致性断言，不替代独立 Gold 复核、运行器/评分器兼容审查、数据/API 预检、外部登记或正式运行。全合成挑战集的结果不得外推为真实业务或总体性能结论。
