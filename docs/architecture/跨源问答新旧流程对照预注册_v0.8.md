# 跨源问答新旧流程对照预注册 v0.8（v0.7 比较公平性补充）

版本日期：2026-10-08  
适用范围：尚未运行、尚未封存的新一轮跨源新旧流程配对实验。  
继承关系：完整继承 v0.4–v0.7 中未被本文件明确修订的研究问题、题包范围、主次指标、运行冻结、匿名人工评审、审计和中止条件。v0.4–v0.7 原件保留；已经运行或封存的批次不得按本版重新计分。

## 修订目的

CS14 v0.3 已暴露两项比较器公平性问题：数据库可能把同一时刻序列化成不同 UTC 偏移；旧流程的答案是自然语言，不一定产生新流程的结构化 `cross_source_alignment.status`。本版在后续新实验前固定处理口径。它不追溯修订 CS14 v0.3 或其他已封存批次的主结果。

## 时间戳引用比较

1. 对 SQL 引用中带字段标签的值，先执行原有精确字符串比较；仅当两侧都能解析为**带时区的 ISO-8601 时间戳**时，才允许把它们转换为 UTC 绝对时刻后比较。
2. `Z` / `z` 和显式 UTC 偏移均按其声明的时区解释。相同绝对时刻即匹配；不同绝对时刻不匹配。
3. 日期、无时区时间戳、格式错误的字符串不进行时区推断；它们只有字面值完全相同时才匹配。不得根据操作系统本地时区或数据集默认时区补足缺失偏移。
4. 此规则只处理引用值的表示差异，不放宽表名、字段名、主键、行身份、引用来源或其他必需字段条件。

## 两臂共同的答案正确性主判分

1. 唯一主指标仍为人工严格证据支持成功率：最终正确性为“正确”且最终证据为“充分”才计成功；运行错误、超时、空答计失败。两臂使用完全相同的盲评问题、标签定义、裁决规则和汇总工具。
2. 评审依据答案与冻结题包中的可见来源材料判断业务结论，不要求回答出现某个流程专属字段或固定措辞。自动状态字段缺失、状态名不同或不能从自然语言答案机器抽取，**本身不等于人工判错**；是否回答正确由共同盲评规则判定。
3. 两名评审对两臂全部候选独立评分；正确性、证据或过度拒答任一维度有分歧的候选，均由第三人按继承协议盲态裁决。严格通过只依据最终人工标签计算，按题号和流程臂解盲配对。不得让自动比较器为一臂补写状态、把候选答案改写为状态，或改变人工标签。
4. 自动 `status_match`、`correctness_pass` 与 `strict_pass` 仅作结构化 trace / 机械引用诊断，不作为两臂间的主答案正确性比较或确认性统计。若该臂未输出可抽取的结构化业务状态，评分结果必须保留 `status_comparison_available=false`；该自动状态“不具可比性”不得被改写成自然语言答案的人工错误标签。自动评分输出将主指标留空（`primary_outcome=null`），另标 `automatic_diagnostic_outcome`；不得对该自动诊断计算确认性显著性或置信区间。自动引用、指标和 trace 检查仍须单列报告，并说明适用范围。
5. 运行前单测必须覆盖：旧流程无 `cross_source_alignment.status`、但自然语言答案可由盲评；新流程有结构化状态；两种回答在相同人工标签下都按同一个严格通过定义计分；各类分歧均触发第三人裁决。不得以组别专属的答案解析器改变主判分。

## 冻结与结果边界

本版、`eval/cross_source_runner.py`、`eval/cross_source_heldout/tools/score_architecture_comparison.py`、`eval/cross_source_heldout/tools/score_architecture_blind_review.py`、对应测试、运行包、Gold、模型/依赖、数据库与索引快照、统计口径须在任何新回答生成前计算哈希并在工作区外登记。自动评分器输出版本须为 1.3 或后续经预注册的兼容版本；盲评汇总工具的代码和测试同样冻结。CS14 v0.3 上的时间戳敏感性分析仍是运行后敏感性结果；新规则不得用于重写其原始自动分数、回答或封存清单。新运行结果仍须按合成题集与实际评审者类型限定结论，不据此直接宣称真实业务泛化或赛事验收完成。
