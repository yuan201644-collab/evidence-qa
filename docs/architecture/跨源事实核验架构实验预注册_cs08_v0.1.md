# 跨源事实核验架构实验预注册 CS08 v0.1

登记日期：2026-10-07（CS08 原始回答生成前）  
范围：合成“剧场舞台音视频设备维保”题集上的严格跨源事实核验与宽松参考流程配对实验。

## 1. 研究问题与边界

比较同一题、同一只读数据库、同一合同文档索引和同一工具预算下：

- 严格事实核验流程是否减少错误肯定（关系未确立、客户冲突、有效期失效、事件异常时仍判满足）；
- 这种保护是否伴随更多无法判断、调用次数或耗时。

本实验只报告 12 道合成题的逐题配对结果，不证明真实业务效果、总体泛化、统计显著性或完整赛题验收。两臂端到端独立调用工具，结果是策略包总效应，不是固定 SQL/RAG 输出后只替换校验器的纯因果效应。

## 3. 流程定义

- `matched_reference_ablation`：同一任务图、工具、题目和数据，采用宽松候选规则；不执行严格客户、依据、双有效期、唯一性和事件顺序核验，能构造合法输入时继续下游。
- `new_fact_verification`：执行事实依赖、受控映射、客户一致、映射/合同分别覆盖工单日期、合同状态、文档条款适用、事件唯一性及时间顺序核验；阻断条件按白名单安全早停。
- 两臂共用只读 SQL、同一文档检索、同一模型配置、同一重试/调用上限、同一证据引用契约。

## 4. 执行与封存

1. 运行前只做 runtime 哈希、结构化行数、索引快照、只读权限和模型缓存预检；不读取 Gold。
2. 用固定随机种子生成题目与两臂的交错顺序；已曝光开发题只作预热，不计分。
3. 每题每臂只运行一次；程序/API 错误保留在分母，不择优重跑。
4. 先封存 24 条原始回答、trace、refs、耗时和运行环境哈希，再解禁 Gold/配对信息进行机器核对。
5. 运行后重新核对数据库、索引、runtime、代码与模型快照；变化或 trace 缺失则本轮无效，不覆盖结果。

## 5. 指标与评审

主指标：正确且证据充分（逐题、逐臂）。同时报告：错误肯定、过度拒答、可答题正确性、恰当早停、引用完整性、trace 合规、SQL/RAG 调用次数、耗时和运行错误。  
结构化比较器检查 `expected_retrieval_state`、实际早停原因、`metric_checks`、缺失事件和结构化零结果元数据；不采信回答文本自称的“0 行”。  
两份候选匿名包分别交给未参与代码修改、出题和 Gold 的评审；若无法取得人工评审，必须标为“盲审未完成”，不得用作者自评或模型裁判冒充。

## 6. 停机规则与结论限制

发现 Gold 泄漏、运行包/索引哈希不符、写 SQL、数据库变化、错误 schema、工具契约不兼容或答案在封存前需要改代码时，停止并保留现场；本批转为回归，不称未见题实验。结果即使严格流程没有优于参考流程也照实报告。

本协议不把 12 道合成题的比例外推到真实业务，也不把跨源原型结果等同于比赛全部评分项或整体架构验收。
