# 跨源事实核验架构实验预注册（CS09 v0.1）

版本：v0.1　登记日期：2026-10-07

## 1. 目的与边界

本实验比较同一模型、同一运行包、同一数据库快照和同一问题顺序下的两种编排方式，检验“事实依赖—跨源核验—证据关联—有界早停”是否减少错误肯定回答，并观察证据完整度与耗时变化。题集为合成数据，只用于架构机制验证，不外推真实业务效果。

本轮只使用 `2026Q4_fresh_cs09_v0.1_runtime` 运行包；Gold 存放在包外，原始回答封存前不得读取 Gold、密钥或配对报告。

## 2. 比较臂

- `matched_reference_ablation`：保留同一跨源演示工具和数据访问条件，但关闭事实核验约束（参考基线）。
- `new_fact_verification`：启用事实计划、对象对应检查、有效期/客户/映射依据核验、事件时间检查、文档条款核对和结构化 trace。

两臂共享模型、温度、问题文本、数据库 schema、文档索引和只读权限；唯一自变量是事实核验约束是否启用。

## 3. 题集与运行

冻结题数为 12（CS09-01 至 CS09-12），工单编号为 `WO-2026-52xx`，均走当前事实计划路由。运行顺序由正式运行器按固定外部种子随机化，每题各运行一次两臂；正式运行前只允许使用未纳入本轮统计的预热题检查服务可用性。

运行错误、缺失配对、数据库快照变化、运行包哈希变化或 trace 未能证明进入事实计划的批次均不得计入效果结论，应封存并标记无效。

## 4. 预注册指标

逐题由包外 Gold 按正式比较器计算：

1. 正确性：结论/状态与 Gold 一致；
2. 引用完整性：要求的 SQL、合同文档片段及必要负证据均被回答引用；
3. trace 合规：工具步骤、来源和早停原因符合声明；
4. 错误肯定数：在应早停或无法判断题上输出确定满足/超时的次数；
5. 过度拒答数：材料足以唯一判定却输出无法判断的次数；
6. 端到端耗时：以运行器记录的 `elapsed_ms` 汇总中位数与均值。

主比较报告同时给出每臂 12 题的逐题结果、三项通过数/比例和错误类型，不把合成题集结果表述为泛化准确率。

## 5. 证据与解盲

运行者在原始回答封存前不得访问 Gold；封存清单须绑定运行包清单哈希、协议哈希、随机调度哈希、数据库快照与原始回答哈希。封存后由独立复核者核验 runtime/Gold 事实和协议绑定，再由运行者执行正式评分。若评分器预验证失败、运行臂名称不匹配或题目未进入事实计划，则不适配、不补默认字段、不报告效果，另建新批次。

## 6. 预期解释

若新架构降低错误肯定但增加过度拒答或耗时，应同时报告该代价；若未观察到改善，只能结论为本题集与当前实现下未证实收益，不据此否定后续架构设计。
