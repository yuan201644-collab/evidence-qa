# 跨源架构事实核验匹配对照预注册 v0.1

日期：2026-10-06  
状态：新题运行前冻结用；本文件不追溯改变 v0.13 及更早实验。

## 1. 研究问题与比较对象

研究问题：在相同结构化数据、合同文档、自然语言转 SQL（NL2SQL）、检索增强生成（RAG）、模型配置和预算下，把“事实依赖＋跨源确定性核验＋证据记录”加入问答编排，是否能减少错误肯定回答并提高证据完整性；代价是增加多少调用和耗时。

比较对象固定为：

1. `matched_reference_ablation`：使用 `build_matched_reference_and_fact_arms` 构建；保留同一事实任务模板、同一 NL2SQL、同一 RAG、同一数据库和文档，只关闭跨源确定性核验。仍需输出用户所问的适用合同、实际时长、约定时限和是否满足，不能只返回 SQL 行。
2. `new_fact_verification`：与参考臂共享底层工具和输入；启用事实依赖、客户/映射依据/双有效期/合同状态/文档范围核验、事实—证据账本和有界失败处理。

历史 `old_workflow` 只作为诊断材料，不纳入本协议主比较，避免把不同路由和不完整基线混入结论。

## 2. 运行前冻结项

正式新题运行前必须固定并记录以下摘要：

- 无 Gold 的运行包及其 `SHA256SUMS.txt`；Gold、逐题事实复核依据和密钥置于包外；运行者在原始回答生成前不得读取 Gold。
- 代码、依赖、模型端点及参数、嵌入/重排模型文件快照；`LLM_MOCK=0`。
- 同一只读数据库快照、向量索引快照、schema 元数据和合同文档；账户不得有写表、建表或修改业务数据权限。
- 业务规则：`data/cross_source_demo/mapping_basis_policy.json` 的 policy id、版本、来源和哈希；`allowed`、`undefined`、`denied` 三态语义不在运行后改变。
- 固定随机种子、题目×流程随机调度、预热题、最大 SQL 尝试次数、文档最多一次策略变化补查、时间预算和输出字段。
- 代码冻结后不得因已产生的回答调整判据、题包或比较器；若完整性失败，整批按无效/未封存处理并保留原始目录。

## 3. 题集与角色隔离

新题不得只是旧题换编号。编制者、结构化/文档独立核验者、运行者和人工评审者分别记录角色；参与本轮代码修改者不得担任新题 Gold 核验者或人工盲审者。题型比例在运行前写入题包元数据，至少覆盖：

- 唯一受控映射且可回答；
- 映射悬空、设备缺失、关键事件缺失或倒序；
- 客户冲突、非受控/未定义映射依据、多合同歧义；
- 映射有效期与合同有效期分别失效、端点等于上限；
- 合同明确未约定、条款存在但首轮未召回、同文档特别约定或范围冲突。

Gold 由未运行系统的独立核验者从 CSV、事件表和合同原文逐题重建；引用片段必须是文档真实子串，负证据必须由执行层元数据生成，不能采信模型自述的“0 行/没找到”。

## 4. 预先声明的指标

唯一主指标为“题级结论正确且证据充分”占比，分母为运行包中两臂各自完整回答的全部题目。不得删除错误、异常或无法裁定题后再计算。

分别报告：

- 结论正确性：正确、部分正确、错误、无法判断；
- 证据完整性：充分、部分充分、不充分、引用不匹配；
- 错误肯定、过度拒答、恰当拒答；
- 运行错误、实际 SQL/RAG 调用次数、补查次数、耗时分布；
- 事实核验轨迹是否包含实际 SQL/文档来源、早停原因和证据关联。

“新流程优于参考臂”只有在题级人工盲审和独立技术核验均完成后才可表述；若只观察到某一题或开发题差异，只报告案例，不外推为准确率提升。整流程差异不能单独归因于某一个模块；如需归因，另做一次只移除一个机制的消融。

## 5. 失败与中止规则

- 任一臂回答数少于题数、运行前后数据/索引哈希变化、配置漂移、Gold 泄漏或账户权限不满足：该批不封存为有效对照，保留原始输出和原因。
- 模型或检索失败按预先约定的运行错误计入全题，不临时重跑或替换答案；最多一次文档策略变化补查必须在轨迹记录真实调用。
- 评审无法从冻结包确定事实或引用时，标为“无法判断/资料不可裁定”，不由作者事后补规则；争议交第三方独立裁定。
- 结果不理想仍完整交付，不继续更换题目或调参直到出现优势。
