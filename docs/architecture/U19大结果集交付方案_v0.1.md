# U19 大结果集交付方案 v0.1

日期：2026-10-07  
状态：首版实现及真实 U19 开发回归已通过；上线前仍需确认部署边界与缓存资源指标。

## 结论

U19 不只是 SQL 生成问题，也是“大结果集如何安全、完整地交付给用户”的接口与展示问题。修改前系统的 SQL 自动上限为 1000 行，U19 参考结果为 2480 行，T4 严格匹配 19/20。首版实现保留普通查询上限，仅在触顶时受控扩展；2026-10-07 的真实模型 + 冻结 AdventureWorks 开发回归已达到 20/20，U19 完整交付 2480 行。该题集已曝光，所以这是开发回归，不是盲测或泛化证明。

原来的提示修复只告知“前 1000 行可能不完整”，并未交付续页或导出；本轮已在该保护基础上实现有界结果集。真实 U19 复验尚未完成前，不把它记为已修复。

## 当前实现依据

- `app/nl2sql/validator.py`：无显式行数限制时自动补 `LIMIT SQL_AUTO_LIMIT`，默认值为 1000。
- `app/nl2sql/pipeline.py`：普通查询先执行原自动上限；触顶后对原生成 SQL 再做 SQLGlot 校验，并以硬上限 + 1 只读执行。扩展失败时保留明确标记为不完整的结果。
- `app/contracts.py`：`AskResponse` 增加可选 `result_set` 元信息；完整行数据不塞进问答响应或 trace。
- `app/main.py`：保留 `POST /api/ask`，新增按会话校验的结果分页和完整 CSV 下载接口；会话标识放在 `X-Session-ID` 请求头，避免出现在常规访问 URL 日志中。
- `web/src/types/contracts.ts`、`web/src/components/AnswerBubble.vue`：前端新增结果表、翻页、过期提示和完整 CSV 下载入口。
- `eval/mainline/score_t4_development.py`：从成功执行 trace 取 SQL，在只读数据库事务中重跑系统 SQL 与参考 SQL，比较列名和结果行；本轮确认评分器取到扩展执行的最终 SQL，U19 系统与参考均为 2480 行。

## 方案比较

| 方案 | 优点 | 风险 / 不足 | 判断 |
|---|---|---|---|
| 把全局自动上限提高到 3000 或更高 | 改动少；U19 SQL 可能拿到全部 2480 行 | 影响所有查询；无法限制极大结果；当前答案仍只展示 3 行，不能完整交付 | 不采纳 |
| 把全部行直接塞进 `AskResponse.answer` 或 trace | 不新增查询接口 | 回答和 trace 膨胀；大结果容易超时或占用过多内存；自然语言答案不适合承载表格 | 不采纳 |
| 有界结果集 + 分页表格 / CSV 导出 | 问答保留短摘要；用户可查看完整数据；资源和失败边界可以显式控制 | 需要同步修改后端契约、API、前端和评测器 | **推荐** |

## 推荐方案：有界结果集

1. 小结果保持现有 `/api/ask` 行为不变；只有系统实际执行了 SQL 且结果超过内嵌展示阈值时，才提供一个可选的结果集句柄和元信息。
2. 服务端只保存系统已生成、经 SQLGlot 校验并以只读事务执行的查询结果；客户端不能提交 SQL。句柄为不可预测的短期标识，并校验发起问答时的会话标识；会话标识用于隔离，不作为身份认证。缓存设置有效期、最大行数、最大字节数和总缓存上限。过期、超限或服务重启后明确失败，不能返回伪装成完整的部分结果。
3. 新增结果页读取接口，按游标取固定页大小；新增 CSV 下载接口。前端在回答旁展示表格、总行数、当前页和下载入口。默认聊天答案继续只展示摘要，不把数千行塞进自然语言文本或 trace。
4. 分页基于服务端暂存的同一份结果快照，不会在每一页重新执行 SQL，因此切页不会因数据库行顺序变化造成重复或遗漏；查询本身仍保留其 SQL 返回顺序，不宣称排序语义。验收时逐页拼接并核对 U19 的 2480 行、列顺序与行多重集。
5. 保留 `SQL_AUTO_LIMIT=1000` 作为普通查询保护。大结果模式必须使用单独、明确的硬上限，且达到硬上限时标记“结果被截断”；不能静默取消上限。上限数值应通过目标数据库上的延迟、峰值内存和响应体测试确定，不在本提案中臆定。
6. 评测器在正式验收时读取完整结果页或下载文件，校验字段名及顺序、总行数、值集合和分页连续性；同时保留 SQL 只读与数据库指纹复核。U19 只有完整的 2480 行交付后才能严格通过。

## 首版实现情况

| 项目 | 首版行为 |
|---|---|
| 普通查询保护 | `SQL_AUTO_LIMIT=1000` 保持不变；只有确认自动上限触顶后才受控扩展 |
| 大结果硬上限 | `SQL_LARGE_RESULT_MAX_ROWS=5000`，以额外读取一行识别行数截断 |
| 暂存字节数 | `RESULT_SET_CACHE_MAX_BYTES=16777216`（16 MiB），超限标记为部分结果 |
| 缓存与分页 | 最多 16 份结果、默认 600 秒过期、每页默认 100 行（接口最大 200） |
| 接口 | `AskResponse.result_set` 元信息；`GET /api/results/{id}` 分页；`GET /api/results/{id}/export.csv` 完整结果导出 |
| 失败语义 | 过期/其他会话返回 404；部分结果拒绝完整 CSV（409）；服务重启后缓存句柄失效 |
| 前端 | 回答下方展示结果表、页码、过期提示；完整结果才显示 CSV 下载 |
| CSV 安全 | UTF-8 BOM、保留列顺序；对以公式符号开头的文本单元格加前缀，降低表格软件公式注入风险 |

这些首版保护值已承载本次 2,480 行 U19 结果，但尚未用大规模并发或接近硬上限的数据完成性能校准；生产或多进程部署应评估共享缓存与用户鉴权。

## 待确认的部署边界

当前实现按单进程演示运行；多 worker 需要共享缓存，线上多人使用还需将会话标识与真实身份鉴权关联。首版不会扩大普通查询默认上限，也不会把部分结果标成完整。
