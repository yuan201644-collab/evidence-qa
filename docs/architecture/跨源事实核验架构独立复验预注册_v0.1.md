# 跨源事实核验架构独立复验预注册 v0.1

版本日期：2026-10-09  
状态：方案草案；尚未出题冻结、登记或运行。  
目的：在全新合成留出集上，独立复验 CS17 v0.6 的方向性结果；不得把本文件或后续自检称为实验结果。

## 1. 已知基线与研究问题

CS17 v0.6 经人类盲态仲裁并完成外部锚定后，严格通过为：匹配参考消融流程 3/32，新事实核验流程 13/32；新流程独自通过 10 题，参考流程独自通过 0 题，双方均通过 3 题、均未通过 19 题。该结果仅描述 32 道全合成题，不证明真实业务效果或统计显著性。

本轮问题：在题目、实体和业务文档均全新的合成留出集中，保持模型、NL2SQL、RAG、只读数据源和其他运行配置一致，仅切换跨源事实核验开关时，新流程能否再次提高“结论正确且证据充分”的题级比例，并且不增加应阻断题上的错误肯定回答？

本轮是对同一机制的独立数据复验，不是不同架构、不同模型或真实业务现场验证。v0.6 的题目、Gold、回答和实体不得复制、改号或改写后混入新集。

## 2. 预注册设计

- 候选批次：`2026Q4_fresh_cs18_v0.1`；全新虚构场景拟定为公共安全无线通信站点设备维保。所有客户、设备、工单、合同、事件、文档与编号重新生成，并在出题前扫描历史候选集中的实体编号和条款重合。
- 规模：64 道问题、每题两臂各运行一次，共 128 条原始回答。64 是为了把 v0.6 的题量加倍、细化覆盖，不是经统计功效计算得出的样本量，也不支撑真实总体推断。若目标改为对明确定义的合成生成分布作统计推断，须另立预注册和抽样框；不能把本设计的结果说成已达到统计功效。
- 互斥题型配额：可计算时限 24 题（限内 10、等于上限 7、超时 7）；结构化前置阻断 20 题（依据不受控 4、映射过期 3、映射未生效 2、合同过期 2、合同未生效 2、合同状态不可用 2、客户范围冲突 3、多合同歧义 2）；事件阻断 6 题（缺受理 2、缺恢复 2、时间倒序 2）；完成检索后不可判定 10 题（明确未约定 3、条款冲突 3、设备范围排除 2、有界未命中 2）；口径偷换 4 题（首次响应/到场时限不得替代服务恢复时限）。每题只归入一个主类别，组合条件另记副标签。
- 臂：`matched_reference_ablation` 与 `new_fact_verification`。共同使用真实只读 SQL 和真实 RAG；图谱/KAG 后端关闭。仅事实核验器模式按预注册切换；工具、索引、模型端点、问题、提示模板和生成参数相同。正式运行前须通过源码与运行时装配审计验证这一点，不能只凭配置声明。
- 配对：同一题两臂各一次，按显式随机种子生成顺序；不得依据中间回答重试整题、调提示词、改题或改 Gold。运行错误保留并按失败计入，不得静默补跑。

## 3. 评分与结果解释

唯一主指标沿用共同盲评口径：候选只有在最终人工判定“正确”且“证据充分”时计为严格通过。两臂按题配对，报告各臂通过数、配对差和四格转移表。

正式盲评前，两名评审者须先用 8 道不属于 CS18 的公开校准题训练评分手册，并确认“正确性/证据充分性”边界；校准题及讨论不计入结果。随后两人独立评完全部 128 条候选；任一维度有分歧时，由第三名盲态人类评审整体裁决该候选。使用 v0.8 共同判分规则：不得要求某臂专属字段或措辞；自然语言答案按同一标准判断。候选随机排序、使用匿名标签；评审者记录臂标签猜测及置信度。报告初评一致率、各维度分歧率、仲裁比例和最终标签，不能只报仲裁后分数。若无法安排两名独立人类评审，结果降级为探索性，不能称正式人类复验。

预先定义方向性复验标准：新流程严格通过率至少高 15 个百分点，且在结构化/事件阻断题上的错误肯定数不高于参考臂，称为“达到预设的工程复验标准”；15 个百分点是本项目预先选择的工程价值门槛，不是统计显著性或功效结论。未达到则如实报告未复现或结果不确定，不追加题目或另挑子集挽救结论。无论结果如何，主报告均公布完整 64 题配对表、运行错误、证据完整度、过度拒答、阻断题错误肯定、引用与 trace 合规、耗时和调用成本。不得以自动 Gold 比较代替人工主指标；自动结果只作诊断。

样本为有目的构造的合成挑战题，不按真实业务分布随机抽样；因此不作总体准确率、真实场景泛化或赛事验收推断。任何配对统计检验若另行计算，只能作为该冻结题集上的补充描述，并须在运行前另行登记，不得事后选择检验或阈值。

## 4. 独立性与数据隔离

1. 运行包只含问题、CSV、schema、合同原文和必要清单；不得含 Gold、答案状态、分组/配对密钥或作者自审结论。Gold 物理放在候选目录之外。
2. 数据作者可以查看 Gold，但不得参与候选答案盲评或解盲统计；运行器只能读取 runtime，不能读取 Gold。外部保管人掌握配对密钥并先登记哈希，解盲在原始回答封存及盲评完成后进行。
3. 独立数据复核人只依据冻结题目、CSV、合同原文和 Gold 重建所有关系、有效期、客户范围、事件时长、条款和引用；不看模型回答、配对结果或运行组别。代码/协议审阅者不得同时担任本轮数据作者。
4. 新运行遵守预注册 v0.8 对共同盲评、时间戳比较和来源引用的规则；不追溯重评 CS17 或其他已封存批次。
5. 本轮主代理及辅助评审已接触 CS17 v0.6 的协议/构建逻辑与实验结果，因此不能声称“出题作者对历史设计盲态”或“完全独立出题”。通过新业务域、全新事实和编号、跨历史题包去重、独立逐题 Gold 复核及运行前外部登记降低风险，并在结果中披露此限制。独立数据复核与代码/协议复核必须由未参与本轮构建的人承担。

## 5. 冻结与运行门槛

依序完成：

1. 冻结本协议及题型配额；构建全新 runtime 与外置 Gold，并由独立复核人逐题核验。
2. 独立审查比较器、Gold schema、真实检索引用约束及运行器；测试旧臂无结构化状态时仍按共同人工口径评分。
3. 在隔离数据库导入 runtime，核对 CSV/数据库逐表摘要、只读权限、索引文档与切片；对当前模型 API 做最小连通性检查。所有结果仅记安全身份与哈希，不记录凭证。
4. 对运行包、Gold、协议、覆盖契约、runner/scorer/应用源码、依赖、模型配置、数据库与索引快照生成绑定清单；由工作区外保管人核验并登记一次性预注册。运行前不满足任一门槛即停止，不发送正式作答请求。
5. 预注册明确 `seed`、`time_anchor`、唯一 `run_id`、两臂顺序及内部重试策略；正式运行一次并立即封存原始回答和 trace。封存后不得修改运行包、评分器、人工评分或协议。
6. 准备匿名盲评材料；人类评分、分歧裁决、解盲、汇总和结果材料分别留存并在工作区外锚定。

任何代码变更、候选错误、接口不兼容或保管人无法提供时，停在对应门槛并报告；不得绕过门禁或复用 CS17 的旧凭据。当前源码对照核验显示，v0.6 运行登记中的 `app/` 文件哈希与工作区现值一致；但 v0.8 runner/scorer、CS18 接线、数据库、索引和 API 均须重新核验，旧运行凭据不适用于新批次。
