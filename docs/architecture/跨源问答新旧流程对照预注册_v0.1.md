# 跨源问答新旧流程对照预注册 v0.1

登记日期：2026-10-04；只适用于此后独立编制并复核的新留出集。  
不适用于 ARC-01–ARC-12：该批在线回答已生成、运行未封存，现仅可作回归。  
本协议回答的问题比“严格/宽松验证消融”更贴近项目目标：**在同一批结构化数据、文档语料、NL2SQL/RAG 工具与模型条件下，现有通用问答流程和新事实核验流程的端到端表现有什么差异？**

## 1. 比较对象

| 组 | 执行方式 | 被测流程 |
|---|---|---|
| A：现有流程 | 项目默认编排器；不注册跨源演示路由或事实计划执行器；使用现有规则路由、真实 NL2SQL 与真实 RAG 工具 | 现有通用路由与工具调用流程，不添加人工指定步骤，不要求它必然调用两个来源 |
| B：新流程 | 私有事实计划原型；启用工单→映射→合同条款/事件→结论的依赖图、跨源关系/口径核验、证据账本、有界早停 | 新的跨源事实核验流程 |

这是**端到端流程包对照**，不是单一校验器消融。两臂的路由和步骤数可以不同，NL2SQL 生成的 SQL、RAG 候选也可能不同；这些差异属于流程效果的中介，不得宣称隔离证明了某一条规则的独立因果贡献。若目标改为单条机制归因，需另做固定 SQL/RAG 输出回放的消融，且单独标明它不等于端到端问答效果。

## 2. 条件匹配与改造边界

- 两臂使用相同的冻结 PostgreSQL schema、题目、合同原文、schema 元数据、模型端点与模型名称；结构化连接只读，向量索引预先生成并冻结。
- 两臂调用相同版本的 NL2SQL 生成/校验/执行实现和 RAG 检索/重排/生成实现；统一 SQL 最大尝试次数、引用上限、LLM 温度/超时/重试、RAG 召回/重排深度。新架构不得使用额外私有模型或单独优化的提示参数。
- 为使现有 RAG 工具读取冻结运行语料，允许通过**仅在显式设置时生效**的 `RAG_CORPUS_DIR`、`RAG_DSN`、`RAG_INDEX_READ_ONLY` 运行时配置指定语料路径、只读数据库及只读索引加载；这些变量缺省时的既有默认行为保持不变。
- A 臂设置冻结题集的 `SCHEMA_META_PATH` 与只读 `DATABASE_URL`，关闭专用跨源演示工具/事实计划；B 臂指向同一结构、数据库与文档目录并启用事实计划。两者使用同一 pgvector 切片/向量快照，模型只读检索，不在计分运行中建索引。
- A 臂按真实默认路由自主选择工具；不为了“调用数对称”而强制它查文档或数据库。报告逐题披露实际来源调用和漏调情况。该差异属于本次端到端估计的组成部分。

## 3. 题集独立性与运行前冻结

新留出题由未参与实现和本轮实验的编题者制作；另一名未参与编题者独立从题目、CSV 与文档原文重建 gold、事实边界和引用。运行者只取得运行包，不取得 gold、作者解释、密钥或组别映射。不得在运行前基于新题输出修提示、规则或架构代码。

运行前形成不可覆盖的冻结登记：协议哈希、实际参与程序的源码与依赖清单、runtime 完整文件清单及外部锚定哈希、模型权重快照哈希、数据库行快照、RAG 切片/元数据/向量快照、题目数量、评测指标、随机化种子。源码清单只覆盖实际加载的 `app/` 运行代码、指定实验运行器/准备器和相关测试，不递归纳入无关 `eval/experiments` 历史快照；其他文件若在运行中改动不得导致漂移漏检，必须由审计者检查清单覆盖边界。

任一与实验有关的代码、提示、模型参数、题包、SQL 数据或向量索引哈希变化，均使本批无效并降级为已曝光回归。运行器不得读取或自动发现 controlled gold 目录。

## 4. 执行与封存

1. 执行相关单元/回归测试、数据库/模型/哈希预检；未通过时不生成留出题答案。
2. 保存随机交错的题目与 A/B 次序及固定种子。先用已曝光开发题预热两臂，预热不计分并记录耗时。
3. 每题 A、B 各运行一次真实端到端问答；温度固定，禁止按答案质量重跑、手工修正或删掉运行失败。输出逐条落盘并记录调用、SQL、检索引用、trace、耗时和运行错误。
4. 全部原始回答写入后先封存内容哈希并复核源码、数据和索引快照；只有封存成功后才能由数据保管人解盲。若漂移/失败，保留现场并判无效，不补跑覆盖。
5. 盲审材料随机化候选编号，去除流程组别、工具模式、执行次序、gold 与作者意见；至少两名未参与实现/编题的评审者独立填写结论正确性、证据充分性、引用匹配和备注。分歧逐题保留，并由第三人裁决。另由独立技术审计者查看原始 trace 核验查询/检索/证据/早停合规。

## 5. 指标与解释边界

主报告提供每题 A/B 配对表及原始计数，不用单一综合分掩盖取舍：

- 结论正确性与证据完整度（独立盲审）；
- 错误肯定/过度断言：关系、客户、有效期、合同状态、条款冲突、事件缺失/倒序等方面缺乏证据仍给确定结论；
- 正确拒答、过度拒答、可回答题正确数及无法判断率；
- 引用是否支持其对应事实、trace 是否合规、是否按协议早停；
- 端到端耗时、SQL/RAG/LLM 调用数与运行失败。费用和 token 用量只有在服务端返回可审计数字时才报告，否则标为未测。

合成数据和小样本只能支持“在这批合成题上观察到的配对差异”。不得写成真实业务有效、总体准确率提升、统计显著或赛题验收完成。若独立作者/复核者缺席、A/B 底层工具/提示条件未对齐、盲审材料可识别组别、原始输出未封存或数据/代码哈希漂移，不能称为可信的新旧流程对照。
