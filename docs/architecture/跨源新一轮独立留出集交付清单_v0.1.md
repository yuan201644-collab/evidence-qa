# 跨源新一轮独立留出集交付清单 v0.1

用途：交给未参与本轮事实核验代码修改和 ARC-01–ARC-12 编制/复核的人，建立下一批正式新旧流程对照题。此清单只规定交付结构，不含答案或题目内容。

## 角色隔离

1. **编题者**：根据新业务组合独立编制 runtime 与受控 gold；不运行系统，不参与实现修复。
2. **独立复核者**：不读取编题者的 expected answer、gold 或解释；只看题目、结构化数据和原始文档，独立重算每题结论、时长、关系边界和引用，再与 gold 逐项比对并给出报告。
3. **运行者**：只收 runtime 包与独立复核通过结论，不收 gold、答案密钥、A/B 配对表或编题说明。运行者的输出全部封存后再由保管人解盲。
4. **盲审者**：至少两人，未参与编题、代码实现或运行；只评匿名候选的答案正确性、证据充分性、引用匹配和备注。
5. **技术审计者**：独立核验原始 trace 中的 SQL、RAG 来源、只读性、早停条件、异常、调用与预算合规。

同一人不得同时承担 1+2、1+3、2+3 或实现者+盲审者。若团队人手不足，须如实降低结论强度，不能把自审称为独立复核。

runtime 包不得包含标准答案、expected status、评分提示、A/B 组别、配对密钥、review 文件或路径名中带 `gold` / `key` / `answer` / `pair` 的成员。受控目录不得与 runtime zip 同包或同交接链接发送给运行者。

## 最低覆盖与设计要求

- 建议 12–16 道题；用全新业务对象、客户、合同、工单编号和文档，不复用 ARC、MED、HOLD、v0.1–v0.6.8 或 CS 系列旧题实例，不用只换编号/数值的方式制造“新题”。
- 题目至少覆盖：正常可回答与超时；等于时限边界；映射有效期与合同有效期分别失效；映射缺失/悬空；非受控映射依据；设备与合同客户冲突；多份有效合同歧义；合同停用/暂停；合同不约定所问 SLA；缺少关键事件；事件时间倒序；双指标中一项可答、一项缺端点。
- 每个负例必须由实际数据库零行/冲突/状态或明确文档声明支撑；gold 写明判据需要哪些 SQL /文档证据、何时许可早停，不用含糊的“应该拒答”。
- 日期、时区、包含端点、单位换算、状态语义以及文档优先级在 README 中固定，不允许运行后解释口径。
- 每题询问一个明确工单/业务对象，且 `questions.jsonl` 每行严格只有 `case_id`、`work_order_id`、`question` 三字段。问题不包含标准答案暗示。
- 另做旧题近重复扫描：对历版 runtime 问题文本、业务编号、CSV 实例、合同片段及组合模板查重；报告具体检查范围与方法，不能只写“未发现泄漏”。

## Gold 与独立复核报告必须逐题提供

- 期望状态/答案及是否可回答；涉及多指标时逐项分开；
- 设备—工单—映射—合同关系、映射依据、双方客户、合同状态、映射/合同有效期各自的计算结果；
- 关键事件存在性、事件时间区间、时长重算与时区；
- 每个结论需要的 SQL 来源字段/过滤条件，负查询的表/过滤条件/零行证据；
- 所需合同原文编号及逐字连续引用片段；冲突条款需明确适用范围和优先级；
- 明确早停条件和正确输出边界；不得把“首轮检索未命中”判成“合同没有约定”。

独立复核报告须记录：runtime 所有文件 SHA-256、问题/CSV/文档逐题复算、引用子串验证、与旧题去重范围、gold 是否被改动及重算哈希、未解决问题。任何未闭合问题都必须阻止运行。

## 运行前交接闸门

正式运行前由保管人确认并登记：

- runtime SHA 清单文件本身的哈希外部锚定；
- 独立 gold 复核为 PASS，运行者未接触 gold；
- 旧/新两臂使用同一 runtime schema、SQL 只读连接、文档集合、冻结向量索引、本地嵌入/重排模型快照、LLM 端点与温度/超时/重试/token 上限；
- 两臂真实 NL2SQL/RAG 代码相同；旧臂不强制补查，保留默认路由行为；新臂严格事实图启用；
- 数据、RAG 向量索引、源码、依赖、模型权重哈希全部登记；
- 盲审表单在揭盲前冻结，并由不参与实现/编题者评阅；运行原始答案先落盘并封存哈希，再允许解盲。
