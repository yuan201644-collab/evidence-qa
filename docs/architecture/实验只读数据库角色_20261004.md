# 实验只读数据库角色记录

日期：2026-10-04。为正式对照预先准备本地最小权限账号；记录不包含连接密码。

## 已完成的数据库状态

- 数据库：本机容器 `askdata-cross-source-demo-db` 中的 `cross_source_demo`。
- 登录角色：`cross_source_experiment_reader`；非超级用户、不可建库、不可建角色、`NOINHERIT`。
- 授权范围：`architecture_2026q4_v01` 与 `cross_source_demo` 两个 schema 的 USAGE；对当前五张 ARC 结构化表和两个 schema 中各自已有的 `chunk_vectors`、`doc_meta` 表仅授予 SELECT。
- 权限探测通过：两 schema 的 CREATE 权限均为 false；七张结构表/向量表的 INSERT、UPDATE、DELETE、TRUNCATE 权限均为 false。使用该角色执行正式 runner 的数据库快照函数，五张 CSV 与数据库内容逐表哈希一致；结构表行数为 equipment 12、contracts 12、contract_equipment 12、work_orders 12、work_order_events 28；RAG 索引含 12 份文档、12 个片段，文档集合与运行包一致。
- 凭据存储：随机生成的角色密码保存在当前 Windows 用户的 Credential Manager，目标名 `Codex:cross-source-experiment-reader`；没有写入仓库、命令参数、运行报告或终端输出。
- 当前项目内连接只在 PowerShell 进程环境设置。执行 `& '.\tools\arch_comparison_credential.ps1' -Action SetEnvironment` 会从 Windows 凭据管理器取值并设置 `ARCH_COMPARISON_DSN`，不显示密码；新 PowerShell 窗口需重新执行。

## 可复核动作

1. 用上面的 PowerShell 命令设置 `ARCH_COMPARISON_DSN`。
2. 执行只读查询 `uv run python -c 'import os, psycopg; c=psycopg.connect(os.environ["ARCH_COMPARISON_DSN"]); c.read_only=True; print(c.execute("select current_user, count(*) from architecture_2026q4_v01.work_orders").fetchone()); c.close()'`。
3. 权限验证报告只记录角色名、表数量和权限布尔值，不打印凭据。

## 适用边界

该角色目前只获准访问 ARC v0.1 的 `architecture_2026q4_v01` schema，以及当前 `cross_source_demo` schema 中的向量表。未来独立题包如使用新业务 schema 或新向量 schema，须在数据加载并由保管人确认对象范围后，再为该 schema 单独授予 USAGE + SELECT 并重跑无写权限探测。不可给新角色授予 schema CREATE 或表写权限。

此次快照是权限与数据一致性预检，不代表存在独立留出包，也不构成效果结果。ARC 题包仍已曝光。
