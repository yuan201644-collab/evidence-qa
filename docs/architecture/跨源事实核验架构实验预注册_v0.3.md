# 跨源事实核验架构实验预注册 v0.3

登记日期：2026-10-04（在任何 ARC-01 至 ARC-12 在线回答生成前）  
范围：虚构医药冷链设备维保题集上的私有原型策略消融；不改公共契约、默认后端或产品路由。  
本版取代 v0.2 作为本次运行协议；v0.2 保留为历史稿，不追溯修改。

## 1. 研究问题与主张边界

本实验只回答：在这一小批合成工单—合同题中，严格跨源事实核验与依赖早停策略包，相较宽松规则消融，是否减少错误肯定和无效关系采纳；代价是增加多少无法判断、工具调用和耗时。

本实验不证明完整新架构优于旧系统，不证明真实业务有效，不证明赛题任务验收，也不证明通用泛化或统计显著性。12 题仅报告逐题配对计数与原始分母。主要测量差异是策略包总效应；由于策略可改变后续查询/候选，不能把结果归因到某一条校验规则。

## 2. 组别定义

- **严格核验组 B**：启用对象关系唯一性、受控映射依据、设备客户/合同客户、映射与合同各自有效期、合同状态、条款适用与冲突、事件唯一性和先后顺序等确定性核验；上游事实不成立时按白名单早停。
- **宽松规则消融组 A**：同一任务图、工具和数据，但对可解析候选采用首项/宽松规则，不执行上述业务核验，并尝试执行仍可构造输入的下游步骤。无法构造合法工具输入的依赖节点记为不可调用，不伪造参数。
- **共同机制**：同一题、同一题集、同一任务图与节点模板、真实 NL2SQL 和 RAG、只读执行、合同编号限定检索、相同证据账本与来源约束、同一模型端点/模型名/温度/超时/重试/调用上限。两组都不使用模拟回答。

### 可归因限制：本实验不是“共享 SQL 结果的单规则因果实验”

A、B 对每道题分别端到端运行，会各自调用 NL2SQL 与 RAG；它们不强制复用同一份 SQL 返回行或同一组检索候选。即使代码、提示、模型参数相同，服务端随机性、重试和策略导致的下游查询差异仍可能影响结果。因此本实验估计的是**端到端严格策略包与宽松策略包的配对差异**，不是固定工具输出后只改变校验器的纯因果效应。报告必须公开两臂 SQL、检索候选、工具调用次数与原始 trace；若某臂请求失败，不删除题目或用另一臂结果替代。

## 3. 数据与冻结登记

- 运行包：`eval/cross_source_heldout/architecture_2026Q4_v0.1_runtime/`，12 道题、12 份结构化设备/合同/映射/工单关系及合同原文；全部是合成数据。
- 独立复核：题集作者与独立 gold 复核者分离；复核者从运行包重建事实与引用，复核报告及 gold 在受控目录，与运行包分离。运行者不读取 gold、配对表或独立复核答案。
- 外部锚定的运行包校验清单 SHA-256：`ae6648f94e59f00d44536cdd35384568a25550274c0129fad92ddab24fe10acd`。运行器在读取题目之前核对该值，并只允许显式白名单成员；问题 JSON 只能包含 `case_id`、`work_order_id`、`question` 三字段。
- 结构化数据在独立 schema 中装载；导入脚本拒绝覆盖已存在目标 schema。向量索引在计分前单独构建并冻结，登记文档哈希、各结构化表内容哈希、切片/元数据/向量内容哈希及索引代码哈希。题目运行时，RAG 只读加载；索引缺失、切片指纹不匹配或运行前后快照变化均使本轮无效。NL2SQL 连接只读。
- 模型登记包含端点身份（不含密钥）、模型标识、温度/超时/重试/token 上限、嵌入与重排模型缓存 revision，以及快照中每个本地模型文件的大小和 SHA-256。计分前用已曝光开发题分别预热两臂，不把预热回答纳入得分或延迟；记录预热耗时及成功/失败状态。
- 实验的代码、依赖、模型标识、固定参数、数据快照、运行顺序、原始输出在运行前/后留哈希。哈希用于发现运行后漂移，不声称抵御具备同时改写所有登记文件能力的恶意攻击。

## 4. 执行程序

1. 先运行离线代码/边界测试及数据、模型、数据库预检；预检不生成留出题回答。
2. 在任何留出题回答前生成并保存随机交错的题目—组别次序，固定随机种子；每题 A/B 先后顺序与题目顺序都记录。
3. 对已曝光开发题 WO-2026-0001 的固定问法，A/B 各运行一次，只作模型/向量检索预热；不评分，不作为留出题证据。记录成功/失败和耗时，不在预热阶段因回答内容修改代码。
4. 对每道题各运行一次 A 和 B。温度固定为 0；不因回答质量重跑。API/程序错误保留为运行错误，仍计入运行分母。若在首题后发现代码/索引/配置缺陷，停止、保留现场，本批只作回归，修复后须另建未见题。
5. 原始输出封存并生成哈希后才允许接触 gold 或配对信息。对外盲审材料去除组别、模式、运行顺序和 gold，仅保留问题、回答、实际引用及必要证据上下文；由未参与实现和编题的人独立判读。原始 trace 留给独立合规审计者。
6. 运行结束重算源代码、题包、模型、结构化数据、向量索引哈希；任一与预登记值不符则标记无效，不静默补跑或覆盖结果。

## 5. 指标

逐题报告两臂正确性、错误肯定、过度拒答、证据充分性/引用匹配、早停合规、真实 SQL 与文档候选、运行错误、端到端耗时、NL2SQL/RAG/模型调用次数。

- 错误肯定：证据不支持确定的满足/超时结论，系统仍给确定判断；逐项给出原因。
- 可回答题正确率与不可判断率同时报告，不能以多拒答换取表面安全提升。
- 证据由两位独立盲审者评估；分歧记录并裁决。若无法取得独立人工盲审，必须标记“盲审未完成”，不得用作者自评或模型裁判冒充。
- token 与费用只有在端点响应提供可核验数据时才报告；否则标为未测，不从字符数推算。
- 小样本仅作描述性结果，不报告统计显著性；不把 12 题的比例包装成总体性能估计。

## 6. 停机与泄漏规则

金标准/密钥在回答封存前不可读；模拟模式、错误 schema、runtime/索引校验失败、写 SQL、意外数据库变动、源码/配置漂移、输出泄漏或 trace 缺失均停止并保留现场。首次在线输出后发生任何方法修改，本批转为已曝光回归，不再称为未见集实验。
