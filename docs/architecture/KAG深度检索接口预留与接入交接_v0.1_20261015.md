## 1. 已确认的产品方向与执行范围

项目 RAG 是默认文档检索路径。用户可手动选择“深度检索”，由 KAG 补充 RAG 的候选原文，交给项目做候选融合、事实核验、统一回答和引用。此次不采用 KAG 自行生成另一份业务答案的方式。

负责人已明确：本轮规划方不熟悉 KAG 支线实现，不代为接入。主线负责共同核验框架、稳定的候选接口和前端展示约定；KAG 支线执行者负责具体适配、依赖/服务、已有索引、文档身份映射、引用修复及专项验证。跨模块公共字段实现前同步契约差异。

以下名称是拟新增的项目内部接口，不是已经存在的 OpenSPG API。本文不指定未经核实的外部方法名、URL 或环境变量；支线应在交付时给出其实际传输方式和启动配置。

## 3. 主线接入位置

```text
已接续并澄清的问题 + 待确认事实 + 允许资料范围
  → 项目 RAG 检索
  → 标准模式：使用项目候选
    深度模式：请求 KAG 补充候选
  → 项目完成身份映射、去重、排序及范围检查
  → 统一事实核验与回答器
  → 事实记录 + 最终 refs + 实际检索路线
```

| 问题方向 | 标准 | 深度 |
|---|---|---|
| 纯问数 | 原 SQL 与核验链路 | 不调用 KAG，记录本题不适用补充检索 |
| 文档问答 | 项目 RAG | RAG 候选加 KAG 候选，统一生成与引用 |
| 跨源 | 数据库与项目 RAG 协同核验 | 仅补充文档候选；受已确认对象、合同、权限和文档范围约束 |

用户选择深度检索不能绕过原有输入纠错、澄清、上下文、安全校验或跨源前置依赖。检索模式与模型选择独立，实际请求逐轮记录所选模式；不能仅凭“深度”标签推定使用了图谱。

现有 `GRAPH_BACKEND=kag` 装配入口在所检查主工作区仍注册占位工具，不能视作真实接入或直接据此启用产品模式。支线应把真实补充检索接入候选阶段，并提供可核验的真实调用记录。

## 4. 预留内部接口

建议项目适配接口名：`EvidenceSupplementer.supplement(request) -> SupplementResult`。主线按此职责预留，支线可以通过其已经验证的本地服务或受控子进程实现；交付时必须明确具体实现与故障行为。

### 4.1 请求：SupplementRequest

| 字段 | 必要性与含义 |
|---|---|
| `request_id` | 本轮唯一标识，用于取消、诊断和证据归属，不包含登录令牌 |
| `question` | 本轮接续、纠错、澄清后的有效问题；同时可携带原话用于诊断 |
| `fact_targets` | 待补查事实 ID、目标和当前缺口；KAG 的规划只能提出候选，不能自行裁定事实成立 |
| `corpus_scope` | 当前资料集合与版本、允许文档 ID/内容哈希；来自主线已认证范围 |
| `entity_constraints` | 已确认的设备、合同或其他稳定编号及适用限制；无则为空 |
| `rag_candidates` | 项目本轮已有候选及其规范身份，用于补充和去重，不含标准答案 |
| `remaining_budget_ms` | 本轮剩余总预算；补充检索须在此范围内返回状态 |
| `max_candidates`、`max_context_chars` | 主线允许的候选条数和上下文字符预算；限制在融合后也生效 |

`corpus_scope` 是必守边界。当前用户问题没有授权使用的资料不能因 KAG 能搜到就加入结果。跨源已绑定某合同的检索，不得改用同名其他合同。

### 4.2 返回：SupplementResult

| 字段 | 必要性与含义 |
|---|---|
| `request_id` | 与输入一致 |
| `status` | `completed / partial / unavailable / failed / timed_out / not_applicable`，本次拟定的内部状态集合 |
| `candidates` | 候选原文与定位，不返回用于替代项目回答的最终答案 |
| `executed_routes` | 本轮实际调用的向量、关系或混合路线及执行状态；不得把配置存在写成实际运行 |
| `elapsed_ms` | 实际测量的补充调用总耗时，内部组件不可观测的部分如实注明 |
| `reason_code` | 稳定、可公开的原因码，区分资料未索引、范围不匹配、服务不可用、超时与执行失败 |
| `diagnostics` | 安全的条数、映射成功/失败数及阶段耗时；不返回密钥、连接串或原始堆栈 |

`completed` 只说明补充检索按协议完成，不代表回答完整或事实正确。图谱找到一条路径同样不等于该关系已经核验。

### 4.3 每条候选：CandidateEvidence

- 候选 ID、来源系统及实际检索路线；原始索引块 ID。
- 项目规范文档 ID、原始文件哈希，以及规范文本哈希/版本。
- 原始坐标类型和区间；转换后的规范文本区间；页码/章节（确实取得时填写）。
- 实际引用原文及必要上下文，保留数值、单位、限定条件和例外。
- 可选图谱关系路径；每段关系附对应原文证据，只有三元组且无原文的路径不能成为已确认关系。
- 原始得分与其来源；不同检索器得分不能不经校准直接比较。融合与重排由项目统一处理。

主线需要的是可定位原文。仅有实体名、文档名、关系摘要或生成式解释的候选，不进入“已核验原文证据”集合。

## 5. 引用绑定：启用前必须关闭的风险

1. 支线提供 `KAG 文档 ID → 项目规范文档 ID` 的明确映射及版本校验。同一名称不证明同一文件。
2. 明确 PDF 页内坐标、合并文本坐标和项目虚拟拼接文本坐标。不能只因起止位置都是整数就混用；规范位置须能复算出对应原文。
3. 引文必须属于允许文档，且与登记版本一致。坐标转换失败、原文不对应或身份不唯一时，不把它标为有效支持证据。
4. 候选先按稳定身份保存；合并、重排后回答器使用的是本次上下文编号，不能沿用 KAG 旧编号。
5. 生成后再把上下文编号转换成最终响应 `refs` 编号；事实关联使用同一最终响应的 0-based 索引并一起保存。
6. 验证索引范围、文档身份、原文区间、支持内容四个层次；编号有效或同属一份合同并不代表内容支持该事实。
7. 有界补查或事实修正沿用统一核验预算；仍找不到支持片段的事实标待确认/不足，不把整份回答标为完整。
8. 必须加入 Stage22 AO-Q08 回归：年度金额对应预算段；异常低价评审段不能因为同属 AO01 就作为金额证据。正确片段仍在候选中而最终错挂时必须能检出。

对无法可靠映射的候选保留安全诊断，不能伪造页码、偏移或把缺失定位填成 0。原始实验资料坐标不回写以迎合新实现。

## 6. 超时、取消、资源和回退

- 所检查前端标准请求等待上限为 180 秒；Stage22 图谱混合流程平均估时约 194 秒、P95 约 257 秒。深度模式不能原样沿用该上限并声称已经可用。
- 接入前实测真实项目端到端耗时，明确标准/深度的总预算、内部调用上限和前端等待上限，形成配置记录；不设无限等待，也不把单服务超时当总预算。
- 前端、项目编排、KAG 适配器传递同一本轮剩余预算。停止等待与后台实际取消分别记录；子进程/服务未确认结束时不能声称已停止计算。
- 项目 RAG 已有足够依据而 KAG 超时，可按标准证据回答，同时显示深度补查未完成和实际路线；缺口仍存在则说明不足。不能静默降级后显示“深度检索完整通过”。
- 默认模式不以 KAG 在线为前提。索引按资料版本准备和复用，不逐题建图；KAG 服务就绪与当前资料确已索引分开检测。
- KAG 与项目 Python 依赖/服务保持适配边界。支线决定其已验证环境，不为接入强行替换主项目依赖或关闭用户其他服务。
- 全部密钥、凭据及服务配置走本机受控配置；不得在交接、日志、候选证据、前端或 Git 中传递秘密。

## 7. 前端与记录的预留

- 输入区预留“标准问答 / 深度检索”，默认标准，旁注“深度模式可能需要数分钟”；与模型选择分开。
- KAG 或当前资料索引不可用时，显示具体可公开原因，深度入口不可假装可用。纯问数请求不新增检索调用。
- 处理记录只展示实际事件：项目检索、KAG 补查、候选融合、事实核对、组织回答。未执行阶段不画完成勾选。
- 保存请求模式、实际路线、回退原因、候选来源和耗时。每项事实可查看对应原文；关系路径作为辅助说明，不代替原文。
- 深度模式不成为第四类首页业务方向。问数/问答/跨源是问题方向，标准/深度是文档取证策略。

公共请求建议预留 `retrieval_mode: standard | deep`，缺省为 `standard`；实际字段位置及新响应版本按统一契约阶段确定。保留已有 `AskRequest`、`AskResponse` 和严格旧客户端的兼容规则；不能擅自向旧版响应添加未知字段或枚举。

## 8. 支线接入步骤与验收用例

执行顺序：确认主线候选与接口 → 修复引用并验证文档映射 → 实现候选适配器及就绪检查 → 测量时间并配置预算 → 接入手动模式 → 同候选三路回归 → 负责人验收后开放入口。

| 场景 | 必须观察到的结果 |
|---|---|
| 标准文档问答，KAG 离线 | 标准 RAG 可用，KAG 调用数为 0 |
| 纯问数选择深度 | 原 SQL 功能保持，不调用 KAG；实际策略如实记录 |
| 深度文档问答 | 两路候选进入统一融合和项目回答器，最终证据可回查 |
| 深度跨源问题 | 沿用已核验对象/合同及资料范围，KAG 不能绕过早停 |
| Q08 引用错挂反例 | 检出金额与引文不对应；正确片段存在也不能把错误引用判通过 |
| 候选重排、重复、编号变化 | 事实和最终 refs 仍对应；索引不因顺序变化错挂 |
| 文档别名、版本漂移、坐标不兼容 | 身份/位置不明确的候选不成为支持证据，原因可诊断 |
| 图谱关系只有摘要、无支持原文 | 关系保留候选/不足状态，不伪装成已核验 |
| KAG 超时、服务失败、部分返回 | 统一预算生效；回退与完整性如实表达 |
| 用户权限/会话切换 | 不混入越权资料，不沿用另一会话的候选或引用 |
| 多轮更换对象、日期或指标 | 重新约束当前候选，不复用已失效事实 |
| 新旧客户端与普通/流式接口 | 缺省标准；旧调用可用；新模式与最终证据一起持久化 |
