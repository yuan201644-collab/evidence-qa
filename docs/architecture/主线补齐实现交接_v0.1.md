## 当前实际主线

```text
请求
  → 后端单进程会话恢复
  → 要素改写与窄规则澄清
  → 路由
  → SQL 工具内关键词表字段候选
  → 元数据外键路径
  → 限定结构提示
  → SQL 生成
  → sqlglot 只读/存在性检查
  → 有限 AST 关联检查
  → 执行与引用
```

定位相似度不是数据库执行许可，也不证明业务对象关系成立。SQL 存在性校验仍用完整目录；只有定义在元数据中的完整外键列组可成为关联边。语义规划路径默认关闭；设置 `NL2SQL_SEMANTIC_PLANNING_ENABLED=1` 后才启用。无法唯一关联或遇到边界时，链路停止或请求补充，不应解释成“没有数据”。

## 未完成或未验证事项

1. 未接入现有 bge 嵌入器到表/字段候选排序；当前在 trace 中明确标记关键词降级。
2. 尚无定位索引预构建/版本绑定流程；当前主要是请求时读取元数据并匹配。
3. QueryIntent 目前只有少量规则抽取，没有稳定填满维度、筛选和统计粒度；没有新增模型规划调用。
4. JOIN 路径仅使用声明外键；多路径时停止，缺外键的真实业务边仍不能覆盖。
5. 粒度检查是窄范围启发式，不是通用聚合正确性证明；普通嵌套 `EXISTS` 已补充外键校验，但零行对象、复杂过滤位置、CTE、多层别名和左右连接尚未充分支持。
6. 会话状态没有跨进程持久化，也未实现同 session 请求队列；需要评估并发请求时状态竞争。
7. 前端构建和若干真实入口已验证；浏览器交互、AdventureWorks 定位专项、完整任务 3 生命周期、真实文档问答和完整跨源矩阵仍未验证。
8. 当前仅有已曝光开发集的在线回归分数；没有新架构未见题效果或泛化数字，也没有独立人工盲审/双系统正式对照结果。

## 恢复测试后的建议次序

1. 先进行静态和单元级检查：SchemaCatalog 同名表、SQL AST、澄清状态、会话隔离和工具字段投影。
2. 固定同一活动数据源与匹配 schema 元数据，在小型受控题上验证定位候选及外键路径；记录关键词降级，不把它称作向量增强。
3. 单测和回归通过后再接入 bge 向量排序，并与关键词基线做同题对照。
4. 对任务 5 分开检查单表、多表 JOIN、聚合粒度、嵌套、左连接、歧义路径和未知路径；只有真实执行且有独立 gold 的结果才计入效果。
5. 最后进行前端构建与端到端澄清恢复，再决定是否默认启用或合并。恢复测试前不要推送或合并到 `main`。
