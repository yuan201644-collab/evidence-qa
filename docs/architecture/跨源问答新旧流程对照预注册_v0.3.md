# 跨源问答新旧流程对照预注册 v0.3

版本日期：2026-10-04  
适用范围：代码与本协议冻结后，另行独立编制的全新留出题包。  
历史关系：补充并替代 v0.2 在后续新题实验中的口径；不回写、不重新解释 v0.2 已封存运行。此前所有 8201–8212 题、答案、Gold 和回归报告均已暴露，只可作回归诊断。

## 1. 研究问题与比较对象

比较两个端到端问答流程在同一批合成跨源问题、数据、模型端点、数据库和检索索引上的表现：

- 旧流程：按现有默认路由自主决定调用 NL2SQL 或 RAG。
- 新流程：由显式事实计划组织 NL2SQL、合同检索、规则核验、事实依赖、证据关联和有界早停。

本实验估计的是两套流程整体的本批差异，不把结果归因于某个单独模块。两臂使用相同题包、只读数据库、文档索引和声明模型端点，温度均为 0；逐题 A/B 各运行一次，题目顺序和每题的臂顺序按冻结种子交错。禁止按输出质量重跑、手工修正或删题。

## 2. 冻结事实口径与安全边界

1. 工单设备到合同的关系只由精确设备编号连接 `work_orders → equipment → contract_equipment → contracts` 建立。映射依据必须属于冻结白名单，设备客户与合同客户一致；合同状态有效；设备映射期与合同有效期分别覆盖工单日期；恰有一份适用合同才继续。多合同、关系冲突、缺失或未知均不得按首条或名称猜测。
2. 合同原文须先按合同编号准确关联。适用范围可以逐字列设备编号，也可以逐字出现由上述已验证编号连接取得的设备主数据名称；名称必须完整精确匹配，不接受近似字符串或同名推断。合同客户、设备客户冲突、原文明确排除该设备或范围冲突时停止判断。
3. 修复时长的评测口径固定为 `accepted → service_restored`，由冻结运行包数据字典解释事件含义，并使用事件行时间计算；工单登记时间不得代替受理时间。合同文档需支持对应服务事项和时限值，文档不需要复述数据库内部事件代码。回答应披露实际采用的起止事件和时长。
4. 仅当合同原文明确写出无相应时限时，才按“合同未约定”处理；检索未命中不能表述成合同未约定。多条冲突时限且无明确优先规则、条款范围不清、时长边界异常、关键事件缺失或重复时，不给确定结论。
5. 允许的早停原因码固定为：无设备记录、无设备合同映射、依据非受控、无有效映射、映射或客户冲突、多份有效合同、合同停用/未生效/已失效、合同文档范围冲突、合同明示无对应时限、时限条款冲突、关键事件缺失/重复、事件时间倒序。零结果必须从执行查询的表名、过滤字段和值和实际行数生成，不接受模型自述作为缺失证据。

题包必须含足够的正例，使“缺证拒答”不能在盲审中冒充架构成功；也必须含关系失效、歧义、缺失和边界负例，检查错误肯定与安全拒答。编制者须在题包说明中列出每题的预期决策路径，但说明不得进入运行包。

## 3. 题包编制与 Gold 独立核验

- 至少 16 道新题，使用未在历史运行或诊断中出现过的业务组合、编号和文档内容；建议覆盖可回答正例、未约定、期限边界、映射期限与合同期限分别失效、客户冲突、多份有效合同、非受控依据、缺设备/映射、缺关键事件、时间倒序和文档冲突。
- 数据作者与 Gold 核验者分离。作者只交运行包及包外 Gold；核验者只凭运行包和 Gold 独立重建对象关系、日期覆盖、事件时长、合同文义、标准结论及引用子串；修订前后均保存哈希。作者或核验者不得接触计分 A/B 原始回答后再声称“未见”。
- 运行包只含问题、SQL schema/字段说明、CSV、文档、文档清单和 SHA-256 清单；不得含 Gold、密钥、预期状态、标准答案、答案提示或作者解释。运行包、Gold、配对密钥和人工审阅表分别隔离存放。
- 题包与目标数据库逐表逐行内容哈希一致；文档 ID 集合与索引 ID 集合完全一致；计分前后数据库和向量索引快照相同。数据库账号只读，数据库事务只读。

## 4. 预注册运行与评审

1. 生成答案前，冻结协议、运行包清单、源码与依赖哈希、配置、模型可识别信息、数据库/索引快照、时间锚点和随机调度表。登记及其 SHA-256 放在项目目录之外并设为只读或版本化；正式运行一次性校验登记。
2. 记录每题两臂原始回答、引用、trace、耗时、工具调用及错误。托管模型若不提供权重修订号/文件哈希，明确标为不可得；token/cost 未获服务端可审计数字则记未测。封存时计算并将 sealed manifest SHA-256 锚定到项目目录之外。
3. 至少两位未参与实现或编题的人类评审者，在看不到组别、trace、Gold、密钥和对方意见的情况下，独立判断每份回答的事实正确性、证据充分性、引用匹配并备注。组别/题目配对密钥由数据保管人单独保存。意见分歧逐题保留并交第三人裁决。AI 评审仅用于预审/诊断，不替代人类评审。
4. 独立技术审计者另看 trace，核对 SQL 只读、精确对象关系、工具调用、文档引用、事实核验、缺失证据来源、早停原因和预算边界。技术审计与匿名答案评审分开进行。

## 5. 报告指标和解释限制

主结果逐题给出配对表及原始计数，至少报告：人工评定的正确性、证据充分性和引用匹配；可回答题上的正确答案数；过度拒答与正确拒答；错误肯定/关系错配/无证据断言；SQL、RAG、重排和模型调用数；trace 合规和失败原因；端到端耗时分布。保留全部错误、超时和空回答。

合成题和有限样本只支持“在这批冻结的合成问题上的配对观察”；不宣称真实业务有效、普遍提升、统计显著、跨日期严格可复现或赛题验收完成。运行包已曝光、人工评审缺席、Gold 复核缺失、盲审泄漏、数据库/索引漂移、模型/运行配置失配或封存失败，均不得称为可信的新旧流程效果对照。
