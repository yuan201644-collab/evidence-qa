# 新架构配对实验方案 v0.1

日期：2026-09-29  
状态（2026-10-01）：早期配对试运行与盲审已完成；H03/H05 已补强并由匿名回归复核确认，五项参考规则已接受用于当前合成范围。现有题已曝光；正式验收和新题效果验证仍未完成。历史运行及本轮细节见阶段 C v0.2 记录。

## 1. 这次实验要回答什么

针对“工单事实 + 合同条款”的跨源问答，检验明确核验对象映射、有效期和指标口径，并在证据不足时定向补查或停止，是否能减少无依据的确定结论、提高证据完整度；同时记录新增耗时和检索尝试。此实验只评估当前工单—合同演示链的阶段 C 增量，不验证尚未实现的通用事实规划、逐主张公共证据结构、业务澄清续接或真实 KAG 接入。

要检验的主张：

> 在同一组跨源问题上，加入阶段 C 的核验和有界恢复后，系统更少把不适用合同或不足证据当作确定结论；合法样例仍能回答并提供相应来源，额外代价由耗时和补查次数呈现。

这是一个小规模工程验证假设，不是赛事规则，也不预设准确率提升幅度。当前工具不调用模型，不能用模型调用成本推断其他主链路的成本。

## 2. 比较组

| 组别 | 定义 | 说明 |
|---|---|---|
| A：参考基线 | 按阶段 B 已记录的行为建立可复现参考实现：参数化只读查询 → 按明确设备/合同编号及生效期关联 → 合同文档首轮检索 → 时限计算与引用 | 阶段 B 源码没有可用的版本化快照。若不能恢复源码，结果必须标为“按阶段 B 记录复原的参考基线”，不能称作原版代码的前后对比。 |
| B：阶段 C 候选 | 当前 `CrossSourceDemoTool`，增加受控映射依据、客户范围核验、无效事件顺序处理、缺条款定向补查、统一时间预算及相关调用记录 | 使用当前工作区代码和同一份数据快照。 |

两组共享同一数据库快照、Markdown 文档、问题文本、证据标准、软件依赖与机器环境。A 组不调用 B 组的核验/恢复逻辑；B 组不读取题目标准答案。若 A 组复原行为无法精确从记录确定，逐条注明复原假设，并把它视为参考算法对照，而非历史版本。

主实验先比较 A 与 B 的整体差异。若要说明哪一项机制单独起作用，再追加消融组，一次只关闭一项阶段 C 检查；不能把整体配对结果归因到某一个功能。

## 3. 题集

- **诊断集**：现有 `data/cross_source_demo/cases.jsonl` 的 7 题已经参与开发和修复，只用于排错、确认评测脚本与输出格式，不进入正式效果统计。
- **留出集**：另建一批新工单、新编号及相应合同/事件记录。题目和证据标准由未负责调试工具的人复核并冻结；运行时系统只拿到问题和业务数据，不读取答案文件。
- 留出题覆盖有效且满足时限、有效但超时、映射缺失（含同名干扰）、合同不适用、必需事件缺失/顺序异常、映射/来源歧义等当前已实现的行为。若要测“初次检索未命中但定向补查能找到条款”，另建独立文档检索挑战题，按真实 BM25 检索结果验证，不能只用模拟返回值。
- 单位冲突、跨轮业务澄清和真实数据库网络故障属于尚未实现或尚未集成的能力，列为后续验收用例，不计入本轮阶段 C 效果分母。
- 题数是探索性工程评测的设计参数，不代表赛事规定。样本不足时报告逐题结果和原始计数，不据此声称统计显著或行业泛化。

## 4. 记录指标

| 维度 | 逐题判据 |
|---|---|
| 结论正确 | 应判断的题：达标/超时及计算值正确；不可判断的题：正确停止或限定，不作肯定结论 |
| 关系与口径 | 设备—合同映射及有效期正确；事件起止、时区、单位和限值一致 |
| 证据完整 | 每个关键计算事实都有相应 SQL 事件/映射证据和适用合同条款；引用来自本次实际查询/检索结果 |
| 过度断言 | 在映射、合同或必需事件不成立时，仍给出确定达标/超时结论的题数 |
| 恢复行为 | 初查缺条款后的定向补查是否成功；无效重试次数；预算耗尽/故障后是否停止并保留已确认信息 |
| 成本 | 端到端耗时、SQL 与检索耗时、检索尝试次数；报告逐题值及均值/中位数。P95 仅在运行次数足够且说明计算口径时报告 |

人工复核答案和证据时，评审者先看匿名化结果，不看组别；至少保留原始输入/输出、逐题判分理由及分歧处理记录。所有失败、超时、拒答和无证据结果都留在分母与报告中。

## 5. 运行控制与复现

每轮保存以下信息：代码提交号与工作区差异摘要、A 组复原说明、数据/文档/题集文件哈希、Python/依赖版本、数据库快照标识、预算参数、操作系统、运行时间、逐题原始响应与人工判分。两组交错运行，降低服务升温或机器状态变化带来的偏差；索引构建时间与在线问答时间分开记录。

已有 `eval/runner.py` 面向 NL2SQL/RAG 既有题型，没有跨源样例适配；当前环境该入口还因缺少 `sqlglot` 无法启动。跨源实验应新增独立的 `eval/cross_source_runner.py` 或等价隔离工具，读取本方案的留出题和真实在线响应，不改变现有评测契约。另需在实验环境中解决 `sqlglot` 缺失，以便满足项目既有正式回归检查。

## 6. 阶段 C 配对实验的判读

报告必须先列逐题 A/B 转移：两组都正确、仅 A 正确、仅 B 正确、两组都错。阶段 C 候选要通过以下工程判据，才能在“合成工单—合同演示范围”内称为配对验证通过：

1. 所有预先列明的安全边界题中，B 不把无映射、无效合同、口径错误或必需事件缺失判成确定达标/超时。
2. 在有效且证据齐备的题上，B 保持正确判断，并给出题目规定的结构化和文档证据；引用与 trace 一致。
3. 真实检索挑战题能分别报告首查、补查和最终结果；在次数/时限耗尽时限定回答并停止。
4. 同时披露 B 相比 A 的题目级变化和耗时/重试代价；不以少数合成题宣称普遍提升或统计显著。

制定方案时列为未完成的集成验证项（历史口径）：真实 PostgreSQL 故障注入、只读拒写、关闭演示开关回归和通用业务澄清续接。前三类工程检查现见 2026-10-01 v0.2 记录；通用业务澄清续接仍未实现/验证。它们及当前配对结果都不等于赛题中级任务四已验收。

## 7. 执行顺序

1. 冻结当前阶段 C 代码和诊断集哈希，确认是否能找回阶段 B 源码；找不到则批准并记录“复原参考基线”的假设。
2. 设计、复核并冻结留出集及逐题证据标准；实现独立跨源评测入口。
3. 先以现有 7 题调通评测器，再运行留出集 A/B 配对；运行人不查看标准答案，评审人盲审答案与证据。
4. 整理题级转移、失败样例、耗时与调用记录，更新阶段 C 验证记录；任何失败先定向修复，再用未见题复测。
