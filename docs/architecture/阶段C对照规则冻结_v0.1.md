冻结日期：2026-10-01。适用于下一批尚未编制/提供的问题和合成工单—合同数据。当前七题的首次实验结果已被查看；本文件不把它追认为预先冻结的正式实验。

## 1. 已获确认的操作规则

2026-10-01 收到的匿名回归复核意见明确接受以下规则用于当前合成演示范围。已解盲的七题只用于理解规则影响，不再作为新题成绩。

| 对照内容 | A：记录复原参考算法 | B：阶段 C 候选 |
|---|---|---|
| 对象映射、客户、适用期、映射依据 | 要求明确设备—合同编号映射并筛日期；不执行阶段 C 新增的客户一致性与依据白名单拦截 | 验证客户标识、受控映射依据、映射和合同有效期；冲突或未核实则停止 |
| 多份有效合同 | 按合同编号升序取首项（操作性复原假设） | 识别多个候选并停止唯一判断 |
| 事件倒序 | 不专门拦截负时差，按差值与限值比较 | 标记顺序异常，不作达标判断 |
| 合同文档检索 | 使用首轮查询一次；缺条款即停止 | 最多两次有界查询；第二次使用定向问题 |
| 数据与来源形状 | 与 B 共用 SQL/事件/文件读取和引用序列化 | 相同数据、查询来源和序列化；仅验证/恢复决策处增加规则 |

A 是依照阶段 B 记录恢复的参考实现，不是历史阶段 B 源码、经典 KAG 或成熟行业基线。差异效果只说明与这份操作性参考算法的差异。若要主张相对强基线的架构优势，应另增加强基线及逐机制消融。

## 2. 下一轮固定配置

- 同一数据库、文档、问题、机器和软件环境；运行端不向候选发送 gold。
- 结构化数据只读；数据库限定为名为 `cross_source_demo` 的隔离实例。禁止把失败/超时映射成查询零结果。
- 采用现有 BM25 实现与参数（k1=1.5、b=0.75）、同一文档过滤逻辑、top_k=8；A 一次，B 最多两次。
- B 时间预算按 `CROSS_SOURCE_DEMO_TIME_BUDGET_MS=5000`，尝试上限按 `CROSS_SOURCE_DEMO_DOC_ATTEMPT_LIMIT=2`。该预算不是硬实时保证，报告列出实测耗时。
- A/B 交错运行；保存问题、响应、调用记录、引用、耗时、失败和超时。逐题列双方通过、仅 A、仅 B、双方未通过、运行错误；运行错误保留，不静默丢题。
- 机器检查状态、所需指标值、证据定位、负例条件和引用/调用记录一致性；之后再匿名审阅答案与证据。
- 结论只描述冻结数据和问题，不转换成统计显著、真实业务泛化或赛事得分。

## 4. 新题交给独立成员编制

由未参与本轮实现、调试和题目修正的成员设计新数据与证据。可以用清楚标记的合成数据；若用真实数据，先确认授权和脱敏。问题与标准答案不能根据候选输出事后修改。

编制内容：

1. 独立结构化快照：`schema.sql` 和 CSV，覆盖工单、设备、客户、合同、设备—合同映射和事件；主键、时区、时间区间端点规则明确。
2. 对应的 Markdown 合同原文，写明起始事件、终止事件、单位、限值与适用期。预期不能判断时，写出缺失/冲突依据。
3. `questions.jsonl` 与分开保管的 `gold.jsonl`。逐题列预期状态、计算依据、映射/合同/条款对象、必须返回的证据，或停止理由；说明此题与旧题的区别。
4. 优先从尚未用新题检验的条件组合中选择，例如 SLA 恰好等于上限、映射日期边界、合同与映射有效期不同、缺失起点事件或客户冲突。是否纳入由编制者根据数据证据决定，不为凑类别制造不自然规则。题数由团队确定，不冒充竞赛要求。
5. 对数据、文档、问题和 gold 计算 SHA-256，记录生成和独立复核者/日期。gold 不进入提示词或 API 请求，运行结果匿名化后再审。

冻结数据之后不因系统结果修改 gold。若实现已为该题调整，披露并另建题集，不能继续称为未见题。
