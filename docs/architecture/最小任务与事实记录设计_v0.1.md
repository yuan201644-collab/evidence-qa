# 最小任务与事实记录设计 v0.1

日期：2026-09-27  
状态：阶段A内部设计草案；不是公共接口，不代表已实现。进入阶段B前需团队确认场景、字段、存放位置、适配方式和预算。

## 1. 设计目标与边界

目的不是增加一层通用智能体框架，而是让复合问题中每个待答事实、依赖和来源可核验，并使缺证据/冲突能局部停止。设计仅供讨论；不修改 `app/contracts.py`，不将整套模型塞进 `ToolResult.data`，不更改默认后端。

当前 `TraceStep`适合记录工具调用事实，命中来源适合表示候选或工具引用；现有 `AskResponse.refs`汇总规则与编排中最终引用筛选的语义需进一步核对。它们均不能直接表达“答案主张X由事实Y的证据A与B共同支持”。候选设计需区分四个概念：

| 概念 | 含义 | 不应混同 |
|---|---|---|
| 调用记录 | 工具、输入、输出、耗时、错误 | 不代表输出可信 |
| 候选命中 | 检索或查询返回的潜在线索 | 不等于事实已验证 |
| 事实记录 | 经过类型/口径解释的值及状态 | 不等于最终答案主张 |
| 最终证据关联 | 某项答案事实由哪些实际来源支持 | 不等于所有曾命中的来源 |

## 2. 建议的内部记录概念

以下为逻辑字段，不是最终字段名或序列化协议。可先由编排层私有对象持有，复用现有工具输入输出适配；具体放置位置需结合当前消费方确认。

### 2.1 任务（Task）

| 概念字段 | 说明 |
|---|---|
| task_id | 本次问答内稳定唯一标识 |
| target_fact | 要回答的原子事实，而非整句复合问题 |
| dependencies | 前置任务ID；无依赖的任务可并行 |
| source_candidates | 允许考虑的数据源/工具及选择理由 |
| required_scope | 对象、时间锚点、指标/事件类型、粒度、单位等必要条件 |
| status | planned / running / candidate / verified / blocked / failed / skipped 等候选状态 |
| attempts | 定向执行次数、失败类别、耗时；受全局预算约束 |
| disposition | 输出、限定、澄清、冲突并列或停止 |

依赖执行前检查：任务标识唯一、依赖存在、没有循环、对象绑定条件满足、工具在允许清单内。模型只可提出任务/工具候选，代码验证权限、只读约束和依赖状态。

### 2.2 事实（Fact）

| 概念字段 | 说明 |
|---|---|
| fact_id / task_id | 事实标识及产生它的任务 |
| subject | 标准对象类型与标识；保留来源原始标识 |
| predicate / value | 属性或关系、规范化值，并保留原始表示 |
| valid_time | 来源所描述事实的生效区间；另记查询时间锚点 |
| metric_context | 指标定义、事件起止、过滤条件、聚合粒度 |
| unit | 原单位、换算规则、规范单位；无单位属性需显式声明 |
| evidence_ids | 指向来源证据定位；候选与已采纳证据分开 |
| predecessor_fact_ids | 依赖的桥接事实；不得用未验证候选作前置 |
| support_state | candidate / supported / contradicted / insufficient / stale / ambiguous |
| check_results | 检查项、结果、依据、失败类别及建议动作 |

### 2.3 证据定位（Evidence）

- 文档：文档内部标识、标题、页码、章节路径、片段/偏移（按实际可用坐标保存）。
- SQL：实际只读语句或可审计查询摘要、表/字段、过滤与时间条件、聚合定义、返回列/结果定位；受敏感数据策略约束保存原始行。
- 关系桥接：两侧对象原始ID、标准ID、映射来源（外键/受控映射表/人工确认）、有效区间及审计状态。
- 每条证据注明是检索候选、工具返回还是被最终事实采纳；不把一次调用的全部命中自动标成最终支持。

聚合SQL结果通常并无单一源行主键。不可将虚构主键填入 `SqlRef.row_pk`；需要以可复核查询条件、表字段、实际结果列及聚合粒度解释其来源。是否扩展公共引用模型应另行提交差异与兼容方案，经团队同步后再定。

## 3. 对象对应与口径校验

对象桥接至少验证：对象类型兼容、标识映射存在且唯一/经确认、映射有效期覆盖问题时间、来源关系含义适用于当前业务。仅同名、文本相似或模型自报置信度不能通过。

事实比较至少检查：指标定义、事件类型、时间范围/时区、有效期、单位、过滤条件和聚合粒度。可确定换算的单位转换要记录规则；定义不同或缺少必要维度时澄清/限定，不能用近似口径输出确定判断。

## 4. 失败状态和有界动作

| 情况 | 允许动作 | 停止/输出 |
|---|---|---|
| 维度、对象或别名歧义 | 请求澄清；保留原问句和候选变化 | 未澄清的分支不执行猜测计划 |
| 缺桥接实体/关系证据 | 仅补查所缺映射或前置事实 | 达预算上限则标记 insufficient |
| 时间、指标、单位或粒度不一致 | 规范化并记录转换；必要时重查 | 无法对齐则限定结论或停止判断 |
| 来源冲突 | 记录各来源、时间和差异；按明示权威规则处理 | 无裁决依据时并列冲突，不静默择一 |
| SQL/检索/模型超时、空结果或非法输出 | 记录明确错误；只对可重试错误定向重试 | 达尝试/总时限/调用预算后停止 |
| 必需证据不足 | 保留其他已确认事实，可给部分答案 | 明确列出未确认项，不补造答案 |

重试次数、总时限、模型调用上限必须配置化并经测量确定，本设计不指定臆造阈值。重试只让失败任务及其失效下游重新执行，不重复成功且未失效的独立任务。预算耗尽时统一停止新增调用。

## 5. 候选示例：工单与合同条款

场景和数据关系尚未由团队确认。若选定“某设备工单是否满足合同修复时限”：

1. 任务T1读取工单设备ID、修复开始/完成事件与时间戳，并记录SQL来源和查询过滤条件。
2. 任务T2依据受控映射证据把设备ID关联到合同对象；映射缺失/多义则阻断T3，不按设备名猜合同。
3. 任务T3检索适用合同条款及有效期，形成条款原文事实，并定位文档页/章节。
4. 任务T4校验事件定义、时间锚点、单位及合同有效期，之后才能作确定性比较；任一口径不明则澄清或限定答案。
5. 最终“达标/超时”这一主张关联T1、映射证据和T3条款三类实际证据。调用日志保留所有尝试，但未被采纳的候选不列作支持证据。

这只是记录形态演示，不是已实现系统输出或系统能力证明。

## 6. 现有接口适配选项

| 选项 | 做法 | 优点/风险 |
|---|---|---|
| A. 编排层私有模型（建议先评审） | 私有任务/事实对象；工具继续返回现有 `ToolResult`；映射事实由适配器读取 | 不动公共契约；需谨慎保存从工具到事实的来源关系，前端暂不展示全量关系 |
| B. 独立内部运行态 | 建立问答运行上下文，逐工具适配，再把兼容的 `TraceStep`/引用投影到现有响应 | 便于状态管理；不能假设前端理解新对象；重复保存和同步风险较高 |
| C. 公共契约扩展 | 经三人讨论后新增事实/逐主张引用结构 | 表达最清楚，但影响所有模块、前端、评测与冻结约定，阶段A禁止直接实施 |

首选先讨论A，不能在不了解现有组合器/前端消费的情况下决定字段名或修改契约。需要解决的契约语义差异：注释要求 `AskResponse.refs` 是所有 trace hit 并集，而编排路径可能只保留最终引用；应先统一“命中候选”与“最终支持”的定义，再提出兼容改法，不可阶段A中静默更改。
