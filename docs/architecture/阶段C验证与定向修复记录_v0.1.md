# 阶段 C 验证与定向修复记录 v0.1

日期：2026-09-28  
状态：合成工单—合同演示链的第一批验证约束已实现；阶段 C 整体验收仍未完成。

## 1. 范围

本阶段只扩展 `data/cross_source_demo` 的可选演示工具，不修改公共响应契约、默认路由、默认数据库或团队任务书。已有样例用于检查对象编号、映射/合同有效期、事件定义、时长和单位、引用与失败边界。该工作不是通用任务规划器，也不意味着真实业务或赛题中级任务四已完成。

## 2. 本轮实现

| 机制 | 当前行为 |
|---|---|
| 对象与有效期核验 | 只按设备/合同编号连接；映射依据须在当前演示的受控清单中；设备客户与合同客户必须一致；映射区间和合同区间都必须覆盖工单日期；缺失映射产生显式零结果 SQL 引用，不按名称猜测 |
| 指标口径与计算 | 首次响应、现场到达、服务恢复分别计算；从合同文档解析分钟/小时单位；负时长单独标为事件顺序异常，不能被静默忽略 |
| 逐指标来源线索 | 调用记录（trace）的指标检查记录起止事件标识、合同文档标识、实际秒数、限值、单位和结果；现有公共引用契约不变 |
| 引用一致性 | 失败提前返回时只把本次决策采用的 SQL 来源列为命中；最终引用与 trace 命中去重并集保持一致 |
| 有界补查 | 合同文档首查未包含修复时限时，按定向查询策略重试；每次尝试、候选数、耗时和结果状态进入 trace。只重查文档条款，不重复成功的 SQL 任务 |
| 时间预算 | 单次工具运行默认预算 5000 ms；数据库连接超时按剩余预算设置，每条 SQL 前设置剩余语句超时；预算耗尽后停止后续任务并输出限定结果 |
| 模型调用预算 | 该演示工具不调用模型，调用次数固定为 0；这一配置不扩展到其他工具 |

预算是本合成演示的初始工程参数，不是赛事规则。初值参考了首条在线样例曾观测到的 SQL 约 192 ms、文档检索约 683 ms；这只是单次观察，不是稳定基线或 P95。允许通过 `CROSS_SOURCE_DEMO_TIME_BUDGET_MS` 设置 1000–30000 ms，通过 `CROSS_SOURCE_DEMO_DOC_ATTEMPT_LIMIT` 设置 1–3 次尝试；默认两次表示一次初查加一次定向补查。参数说明同步在 `data/cross_source_demo/README.md`。

## 4. 尚未完成或未验证

- 本轮新增 9 项隔离单元补测，覆盖定向重试、补查仍无条款时停止、客户标识冲突、未受控映射依据、多有效合同歧义、负时长拒绝判定、文档检索中预算耗尽、连接异常分类、语句超时异常分类；9/9 通过。数据库相关两项通过模拟连接器/游标抛出异常，不连接或改写演示数据库，不等同于真实 PostgreSQL 故障注入。
- 真实数据库连接超时、PostgreSQL 语句超时、只读事务写入拒绝，尚未做故障注入；真实数据库和接口在线样例仍只覆盖正常连接路径与既有七题。
- 样例未覆盖单位不一致和别名/对象歧义；语义复杂的事实支持仍需人工审阅。
- 本轮只执行了只读查询，没有尝试写 SQL；代码路径使用只读事务，但写操作拦截尚无独立运行验证。
- 项目现有 `eval/test_metrics.py` 与 `eval/test_rag_metrics.py` 均通过（Windows 下需 `-X utf8` 避免子进程输出按 GBK 解码）；`eval/tools/validate_cases.py` 通过。正式 `eval/runner.py` 与 `eval/tools/local_check.py` 尝试启动时因当前虚拟环境缺少 `sqlglot` 而停止，本轮没有改动依赖配置。
- 现有正式评测器没有跨源演示用例适配器，尚不能用它对 `data/cross_source_demo/cases.jsonl` 做有效的同题配对基线；因此没有正式跨源指标或基线结论。七题仍是开发诊断集，不是留出集。
- 未验证关闭演示开关时默认路由不变，未测并发或稳定时延。
- 尚未迁移到真实且获授权的数据，也未实现通用 Task/Fact 运行模型或逐主张公共证据结构；公共契约保持不变。

进入阶段 D 前，需先补齐失败分支与同条件对照验证，并由团队确认真实/授权场景、预算和评测集范围。KAG 只有在验证证明确有复杂关系缺口后才继续评估。
