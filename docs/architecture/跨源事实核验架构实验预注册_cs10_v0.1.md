# 跨源事实核验架构实验预注册（CS10 v0.1）

版本：v0.1　登记日期：2026-10-07

CS10 是在评分器兼容性修复后的全新留出批次。它不得读取或复用 CS09 的 Gold、回答、密钥或题目；合成数据仅用于机制验证。

## 1. 比较臂

- `matched_reference_ablation`：同一 SQL、文档检索、只读数据库与模型配置，关闭事实核验约束。
- `new_fact_verification`：启用事实依赖计划、对象编号对应、映射依据/客户/双有效期核验、事件顺序检查、合同条款核对和结构化溯源记录。

除上述约束开关外，两臂共享模型、温度、问题文本、数据库快照、文档索引、运行顺序和资源预算。

## 2. 题集与运行规则

题集为 12 道全新工单—设备—合同问题，编号 `WO-2026-53xx`，固定问法为“工单 WO-2026-53xx 是否在合同修复时限内完成？”。每题每臂运行一次，运行器固定记录问题、臂名、随机调度、数据库快照、原始回答与完整 trace。Gold 只在 24 条原始回答封存并完成哈希校验后读取。

运行前先由正式评分器预验证 Gold；若题目未进入事实计划路由、出现运行错误、包/数据库快照变化、Gold 字段不完整或评分器哈希与冻结不一致，整批标记无效，不补字段、不回放答案。

## 3. 指标

逐题报告：正确性、引用完整性、trace 合规、错误肯定数、过度拒答数和端到端耗时（均值/中位数）。主结果给出两臂 12 题通过数、比例、逐题配对转移和错误类型；不称为真实业务准确率或泛化证明。

## 4. 证据与审计

runtime 与 Gold 物理分离；runtime 清单、问题文件、Gold、协议、评分器及数据库/索引快照均登记 SHA-256。独立复核者仅从 runtime 数据与合同原文重建 Gold 事实，不能访问运行输出或解盲材料。原始回答封存后才允许正式评分，且评分结果需标记合成题集范围与剩余盲审限制。
