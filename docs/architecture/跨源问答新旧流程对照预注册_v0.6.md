# 跨源问答新旧流程对照预注册 v0.6（v0.5 补充修订）

版本日期：2026-10-04  
适用范围：尚未运行、尚未冻结题包与登记的新一轮跨源新旧流程配对实验。  
继承关系：完整继承 v0.4 与 v0.5 中未被本文件修订的研究问题、主次指标、随机配对、冻结、匿名评审、运行成本和审计边界。v0.4、v0.5 原件保留；任何已运行或已封存批次不得套用本版重新评分。

## 修订原因

留出包独立复核发现，正向题虽然询问维修耗时与时限结论，但 Gold 没有声明指标期望值；现有比较器在指标期望字段缺失时会对空检查列表按通过处理。另有题目要求报告工单日期，但 SQL 引用判据未强制覆盖 `work_orders.opened_at`。本修订在任何正式 A/B 回答生成前补齐判据，避免把缺失的期望字段当作通过。

## Gold 与判分约束

1. `clause_present_expected` 题必须显式包含完整 `required_metric`：`start_event`、`end_event`、`elapsed_seconds`、`limit_hours`、`within_limit`。字段缺失、类型非法、非有限数值、负耗时、非正时限均使整批 Gold 预验证失败；不得以空 `expected_metric_checks` 或字段省略代表通过。
2. 对 `expected_status` 为 `repair_within_limit` / `repair_over_limit` 的题，`required_metric.within_limit` 必须分别为 `true` / `false`。Gold 数值与事件时间、合同条款的对应关系仍由独立复核人从运行包重算，不因结构校验通过而视为事实核验完成。
3. `clause_present_expected` 题的 `required_sql_snippets` 必须至少有一项覆盖工单日期字段 `opened_at`，用来检验回答中的工单日期能否由实际 SQL 引用支持。工单主键本身不替代日期字段证据。
4. 本轮安全早停原因仍仅限 v0.5 的五类：`customer_scope_conflict`、`mapping_basis_unapproved`、`validity_window_not_cover`、`ambiguous_active_contracts`、`event_time_reversed`。Gold 预验证拒绝全局白名单内但不属于本轮范围的其他原因。
5. 上述判据只允许在本轮未运行前修订并登记。若任何候选回答已经生成，不得增补字段后重新评分；须保留该运行作为无效/探索性材料，并另建新留出包和登记。

本修订不改变 v0.4 的唯一主指标，也不构成对旧运行结果的追溯性修分。
