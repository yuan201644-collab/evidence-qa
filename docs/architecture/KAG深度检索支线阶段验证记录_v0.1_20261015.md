## 1. 当前判断

标准问答仍走项目 RAG。用户手动选择“深度检索”时，项目 RAG 与 KAG 各自提供候选原文，之后由项目统一排序、生成答案和记录引用。KAG 不单独生成最终业务答案，也不进入默认路径。

本机已具备一个通过建库质量门、文档身份检查和真实端到端烟测的可选路线。现有结果支持“这条路线在当前隔离语料上能工作，并曾补回 RAG 漏取的条款”，不支持“多种新题上已稳定优于 RAG”或“可以默认接入”。

## 3. 项目 RAG 与深度路线的一次探索性对照

同一项目语料、同一问题分别跑标准和深度路线：

> WX-2026-0417 的乙方对常用备件和进口备件分别承诺多久到货？这份服务承诺的期限多长？

- 标准 RAG：45.35 秒。答出了常用备件 72 小时、进口备件 15 个工作日，但没有取到承诺函中“一年、期满前一个月协商续签”的句子，因此答称现有材料未明确承诺函期限，并区分了合同质保期。
- RAG + KAG 深度路线：60.57 秒，其中 KAG 候选查询约 28.86 秒。答案给出一年及续签时间，并引用承诺函和合同来源。
- 另一次端到端深度烟测共 111.22 秒；当次 RAG 检索约 26.3 秒、KAG 查询约 31.4 秒、融合重排约 35.3 秒、生成约 18.2 秒。

这是一道基于已知材料关系构造的探索性问题，不是盲测题或预注册留出题。它证明联调路径可行并展示了一个可能的补证收益，不构成泛化效果估计。当前 KAG 单次超时设为 60 秒，最多 16 条候选，上下文上限 18,000 字符；尚未验证端到端硬截止时间与后端任务取消在所有故障情况下都可靠。

## 4. 引用金额回归

Stage22 AO-Q08 的问题是：正确预算段已在候选上下文中，但 RAG 加图谱混合路线第 3 次重复把“931.02 万元/年”引用到 AO01 的异常低价评审段 `[32432:36017]`，没有引用明确写出预算的 `[8314:11585]` 段。

本次在项目生成器增加了有限范围的金额文本核对：识别答案中带人民币单位的阿拉伯数字金额，查找该金额后同句、下一笔金额前的引用，并检查所引片段是否含有等值金额（如“931.02 万元”与“9,310,200 元”视为等值）。不做语义支持判定，也不处理中文数字、算式推导或其他币种；未匹配时会在答案和生成 trace 中提示核对。

回放 AO-Q08 的 9 条答案记录，错误的 RGV 第 3 次重复触发警示，其他 8 条没有金额文本不一致警示。新增确定性回归覆盖“正确预算段在候选中但答案错引低价段”和“正确预算引用”两种情况。该检查能抓出本例的数值错挂，但不等同于完整引用语义核验。

## 5. 代码与本机设置

- `app/kag_supplement.py`：隔离 KAG 子进程的临时目录，修复 KAG 候选字符区间映射，并执行文档范围、版本和引用定位校验。
- `app/rag/answer.py`：增加有限范围的金额与所引片段数值一致性检查；结果写入 `llm_generate` trace，未匹配时在回答中给出核对提示。
- `tests/test_kag_deep_route.py`、`tests/test_citation_amount_audit.py`：适配器与 AO-Q08 金额引用回归。
- `eval/runner.py`：Git 状态输出包含无法按 Windows 本地代码页解码的文件名时，使用替换解码，避免跑分元信息检查崩溃。
- 本机 `.env` 已加入非秘密的 ID40 运行目录、KAG Python 路径与检索预算；该文件已被 Git 忽略。没有把密钥写入模板或代码。`.env.example` 仍默认注释关闭，只示例本机已验证的目录和预算。
- 输入框中的深度选项只有就绪检查通过才可选；旁注明确该路线是实验支线、增加等待时间且需核对引用。架构说明仍标为研究支线，不宣称默认接入。

- 全套 Python 测试：仍有 2 项失败，分别为 `app/test_nl2sql.py::test_gold_sql_pipeline_end_to_end` 与 `tests/test_runtime_metadata_overrides.py::test_normalizer_and_router_use_the_same_explicit_runtime_metadata`。失败位于 SQL 流水线和运行时元数据词项，不涉及本次 KAG 或金额核对文件；当前工作区有既有未提交改动，不能据此断言它们是基线缺陷。

## 7. 后续验收顺序

1. 先处理并单独复测上述两项全套测试失败，确认不影响主线。
2. 在同一冻结语料上预先登记一组不同关系结构的配对题，标准与深度路线各跑多次；盲审答案事实、引用具体区间、无依据补充、超时及总耗时。
3. 把 Stage22 AO-Q08 的错挂记录纳入真实生成回归，并补测金额未引用、多个金额共享句子、中文数字及单位换算等边界；仍只把这类检查称为数值一致性警示。
4. 增加端到端预算与取消语义验证，记录请求截止时间、KAG 子进程是否实际退出，以及回退后答案来源。
5. 至少在第二个独立真实业务项目重复观察后，才能讨论是否建议长期保留为可选功能；任何结论都继续与“默认 RAG”区分。
