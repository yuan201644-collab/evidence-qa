# 跨源事实核验架构独立复验预注册 v0.2 修订

版本日期：2026-10-09  
状态：修订草案；未冻结、未外部登记、未运行。  
适用范围：与《跨源事实核验架构独立复验预注册 v0.1》合并阅读；除本修订明确覆盖的批次标识、事实裁定规则和题目措辞外，v0.1 的设计、运行条件和限制继续有效。

## 1. 修订原因与版本关系

v0.1 的独立复核发现：多合同题在两份合同结论相同的情况下仍被标为不可判定；若干前置阻断题的合同原文又显式列出了目标设备，可能与“不得检索/不得建立关系”的 Gold 预期冲突。v0.3 虽修复了文档解析格式，但上述事实裁定问题仍需按本修订闭合。v0.1、v0.2、v0.3 均为未运行的候选，保留原样，不作为正式结果。

本修订对应候选批次 `2026Q4_fresh_cs18_v0.4`。v0.4 的题目数、互斥题型配额、两臂、人工主评分口径与运行门槛继承 v0.1；题面、Gold 与文档证据按下文修订。正式运行只允许在 v0.4 通过独立复核、运行器/评分器审查、只读数据与 API 预检、哈希绑定和工作区外预注册后进行。

## 2. 本题集的对象关联裁定规则

以下是本合成题集的局部判题规则，不代表公共安全通信行业标准或真实合同法律解释：

1. `contract_equipment` 是设备与合同对象关联的结构化权威来源。仅 `mapping_basis_policy.json` 的 `allowed` 列表中依据可建立受控关联；未列入 `allowed` 的依据不能单独建立关联。合同正文可以核验已经受控关联的适用范围、条款与明确排除项，但不能替代缺失或不受控的结构化关联。
2. 关联有效期与合同有效期分别校验，均按工单 `opened_at` 所在日期作闭区间判断；任一不覆盖即不得使用该合同。合同状态 `active` 是本题集的有效状态；其他状态不视为可用。合同客户与设备客户必须一致；字段冲突不能由合同正文中偶然重复设备编号而覆盖。
3. 在以上结构化前置条件通过后，合同原文可以否定候选关联（例如明确排除目标设备），也可以提供或冲突性地提供 SLA。文档中的同名、相似描述或未签署草案不能升级为结构化对象关联或有效 SLA。
4. `mapping_unresolved`、`mapping_basis_unapproved`、`validity_window_not_cover`、`contract_status_inactive`、`customer_scope_conflict`、`ambiguous_active_contracts`、`key_event_missing` 与 `event_time_reversed` 均是本题集明示的安全阻断类别。发生阻断时，Gold 只要求支撑已执行判定所需的结构化证据；不得要求系统引用其流程尚未检索的文档。
5. 对多份同时有效的候选合同，只有当题目要求“唯一确认适用合同”时，合同不唯一才直接回答不可唯一确认。为避免把“合同不唯一”误当成“符合性不可判定”，CS18-043/044 的题面将明确要求唯一确认适用合同；不得把两份合同阈值相同、且符合性结论不变的普通是/否问题标为不可判定。

## 3. v0.4 题包修订清单

- CS18-043/044：问题改为要求确认是否存在唯一适用合同；两条有效映射及两份合同原文保留。正确结论是“不能唯一确认”，必需证据为两条有效映射、两份有效合同及客户一致的结构化记录，不以相同 SLA 阈值作为拒答理由。
- CS18-025–027：保留不受控映射依据；对应合同文档不再直接列出目标设备编号，而明确说明未附经签署的设备清册、不能单凭合同正文确定具体设备关联。
- CS18-033/034：保留 `contract_equipment` 对目标设备零行；对应合同文档同样不再直接列出目标设备编号或暗示其在适用范围内。
- CS18-041/042：保留设备客户与合同客户不一致；合同正文只说明合同限定于合同客户名下设备，不列入目标设备编号。该冲突按本修订第 2 条第 2 项判为前置阻断。
- CS18-057/058：保留受控、有效的结构化关联与合同原文明确排除目标设备。Gold 的 `expected_metric_state` 改为 `document_scope_excluded`，`expected_status=not_determined`，并要求合同原文证据；不得误标成一般 SLA 未约定或阈值冲突。
- CS18-028–032：继续分别测试映射过期/未生效。合同原文出现设备编号并不覆盖关联有效期；Gold 继续要求结构化日期证据并设置 `retrieval_not_required`。

上述修订不得改动其他题目的事件时间、客户、设备、工单、合同编号、有效期、SLA 数值或答案事实。v0.4 构建后由未参与构建者从运行包和 Gold 独立重建全部 64 题，再决定是否可冻结。

## 4. v0.4 协议与复核要求

交付的 `protocol.md` 必须包含完整 v0.1 正文及本修订全文；不得只在运行器常量或生成脚本中隐藏裁定规则。覆盖契约须逐题映射到 64 个唯一 `case_id`，合计与 v0.1 配额一致。Gold 校验器必须单独断言 CS18-043/044 的唯一合同问题措辞、CS18-025–027/033–034 文档无目标设备编号、CS18-041/042 客户限定语、CS18-057/058 的排除状态及其文档引用。

独立复核人需核查全部问题、CSV、schema、合同原文、映射依据策略与 Gold；尤其复算结构化关联、两类有效期、合同状态/客户、事件端点与时长、所有文本片段、早停证据最小性和题目判定是否唯一。复核人不得读取 A/B 回答、运行分组密钥或配对映射。

## 5. 当前结论

CS18 v0.1 的静态引用与算术核验虽通过，但语义裁定未通过；v0.3 的独立审阅已确认多合同题的结果不变问题仍存在。故旧版本均不得冻结、登记或运行。只有 v0.4 完成数据修订与全量独立复核、代码/协议兼容审查、真实只读数据库与 API 预检及外部预注册后，才能进入一次性正式运行。当前结论不是效果结果，也不支持新架构优于参考流程的新增经验判断。
