# 主线与前端版本统一记录

版本：v0.1　更新日期：2026-10-16

## 结论与问题定位

已将可核对的交付候选、新版三入口首页、跨源来源目录和 KAG 补充检索标签集中到同一集成分支，准备以本次合并后的 `main` 为后续开发基线。页面包含问数、问答、跨源问题三个入口，输入框固定在底部；三类问题统一展示各自真实的事实与证据记录，不将单源问题强行送入跨源路径。

原先 5184 端口确实加载了主工作区里的旧双入口首页，最新页面却保留在另一份临时工作目录。旧启动器只检查 HTTP 200，并允许 Vite 自动换端口，所以“端口能访问”不代表“版本正确”。这次定位依据是端口进程、实际加载的 `WorkspaceView.vue` 模块及其源码路径，不是缓存猜测。

## 启动规则

1. 唯一日常开发入口：仓库根目录 `start.cmd`，地址 `http://127.0.0.1:5184/`；前端源码只认当前仓库 `web/`。
2. Vite 启用严格端口占用检查；不再自动开到 5185 等地址。受控测试才可显式指定临时端口。
3. `/__verimind_frontend` 返回开发页面标识和实际源码目录。启动器只有两者都匹配才复用进程；旧页面、另一工作目录或缺失身份接口均不复用。
4. `start.ps1 -Restart` 只允许自动停止已核实属于本目录的前端；该命令也重启后端，执行前先结束正在进行的问答。不要用它停止其他人的项目服务。
5. 静态交付包带 `frontend-version.json`；开发目录核对使用 `npm run test:runtime`。该检查不是后台服务版本证明，也不是业务正确率验收。
6. 默认代理仍为 8000。需要隔离后端时，在本机 `web/.env.development` 配置 `VITE_BACKEND_TARGET`，不要修改公共默认值。
