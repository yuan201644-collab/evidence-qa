# 阶段 B 演示链路接入说明 v0.1

日期：2026-09-28  
状态：2026-09-28 已完成 7 道合成样例的在线接口验证；仅覆盖 `data/cross_source_demo` 的合成工单—合同数据，不代表真实业务泛化或赛事正式评测。

## 1. 本次实现范围

在不修改 `app/contracts.py`、默认数据库数据或默认路由行为的前提下，新增一条可显式启用的工具路径：从工单编号查 PostgreSQL 只读记录，验证设备—合同映射及有效期，在独立合同 Markdown 文档中检索条款，再由代码对齐事件定义、计算时长并输出有来源的判断。

本路径不是通用 NL2SQL，也不是完整混合RAG。SQL为代码内固定、参数化的只读查询；文档侧复用项目 `Bm25Retriever`，以合同编号限定到唯一演示文档，再解析本样例中定义的服务时限表。它不调用模型生成SQL或最终判断，也未使用向量召回、重排或生成模型。

## 2. 代码落点

| 文件 | 职责 |
|---|---|
| `app/tools/cross_source_demo.py` | 查询工单、映射和事件；检索合同条款；校验有效日期、指标与缺失/歧义情况；生成 trace 和引用 |
| `app/orchestrator.py` | 仅当 `CROSS_SOURCE_DEMO_ENABLED=1` 时注册工具；命中 `WO-YYYY-NNNN` 编号时专用路由；默认关闭时原路由不变 |
| `data/cross_source_demo/schema.sql` | 创建独立演示 schema 和五张表 |
| `data/cross_source_demo/load_postgres.py` | 限定数据库名为 `cross_source_demo`，仅向空表导入随仓 CSV；发现已有行即拒绝，不清空或覆盖 |
| `infra/docker-compose.cross-source-demo.yml` | 独立 PostgreSQL 容器和数据卷，不复用 Chinook / AdventureWorks 卷 |

## 3. 安全与证据边界

- 在线连接先设置 PostgreSQL 只读事务，再检查当前数据库名；只允许查独立的 `cross_source_demo` 数据库。
- 用户输入只用于工单编号提取和参数值，不拼接成SQL标识符或SQL语句。
- 实际命中的 SQL 来源和合同文档来源分别落到 `TraceStep.hit`；最终 `AskResponse.refs` 与全部 `TraceStep.hit` 的去重并集一致。对于无映射的负例，以明确的零结果 SQL 引用说明按设备编号查询未找到映射，不伪造不存在的行。
- 对象关系只按 `equipment_id` 和 `contract_id` 显式映射，不按名称猜测；映射有效期与合同有效期都必须覆盖工单日期。
- 时限比较分别使用首次响应、现场到达、服务恢复事件；缺少适用合同、文档条款或必需事件时不生成“达标”结论。
- 公共契约没改。现有引用结构能列出本次实际证据，但还不能表达复杂答案中每一个独立主张与证据的一对多细粒度关系。

## 4. 运行方式与验证状态

本机启动、载入和调用命令见 `data/cross_source_demo/README.md`。由于本机 Windows 将原主机端口 `55432` 列为排除端口，配置现改用 `55532`；容器内端口仍为 `5432`。启动时设置独立数据库口令和 `CROSS_SOURCE_DEMO_DSN`，启动演示 PostgreSQL，再载入数据，最后启用可选路由。

### 4.1 已完成的在线样例核验

2026-09-28 在本机启动独立 PostgreSQL、导入 CSV，并通过 `POST /api/ask` 对 `cases.jsonl` 中 7 道问题逐题发送请求。7/7 请求返回 HTTP 200；逐题核对了答案事实、指标状态、工具 trace 和引用：

| 工单 | 在线结果 | 核对结论 |
|---|---|---|
| WO-2026-0001 | `repair_within_limit` | 修复 7小时40分钟，对比 8小时限时，满足 |
| WO-2026-0002 | `repair_over_limit` | 首次响应 20分钟/30分钟内；修复 8小时30分钟，超时30分钟 |
| WO-2026-0003 | `repair_within_limit` | 修复 3小时，对比 4小时限时，满足 |
| WO-2026-0004 | `repair_over_limit` | 修复 5小时，对比 4小时限时，超时1小时 |
| WO-2026-0005 | `no_active_contract` | 合同已过期，回答无法据此判断是否达标 |
| WO-2026-0006 | `missing_object_mapping` | 明确映射查询为零结果，不按同名设备猜测 |
| WO-2026-0007 | `missing_required_event` | 缺少服务恢复事件，不计算修复时长 |

修正提前结束分支的引用汇总后，7/7 响应均满足 `refs == 去重后的 trace.hit 并集`，并且每条引用都有非空片段。有效合同路径和缺失必需事件路径包含对应合同文档引用；过期合同与缺失映射路径不检索未被证明适用的合同条款。`cases.jsonl` 中这两道负例的期望证据与状态名已同步为实际决策口径。

中文响应通过 UTF-8 客户端检查正常；Windows PowerShell 5.1 的终端显示出现乱码属于客户端解码/显示现象，不影响本次直接 UTF-8 解码后的内容核对。
