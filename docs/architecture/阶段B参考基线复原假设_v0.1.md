## 目的与边界

工作区没有可用的阶段 B 版本化源码快照，因此无法做“原代码前后对比”。本说明只依据《阶段 B 演示链路接入说明 v0.1》和《阶段 C 验证与定向修复记录 v0.1》，定义一个独立、可复现的参考算法 A；当前阶段 C 工具作为候选算法 B。所有报告须称 A 为“按阶段 B 记录复原的参考基线”，不能称为历史阶段 B 代码。

## 从阶段记录可确认的共同能力

根据阶段 B 接入记录，两组共同保留：

1. 从工单编号做固定参数化只读查询，读取工单、设备、合同映射和事件；不使用模型生成 SQL。
2. 按设备/合同编号及映射有效期、合同有效期核验关系，不按设备名称关联。
3. 对适用合同文档做 BM25 首轮检索，从条款提取首次响应、现场到达、修复完成时限。
4. 按事件时间计算时长，并输出答案、工具调用记录和 SQL / 文档引用。

阶段 B 文档中 7 题在线验证的结果状态、主要口径与证据要求，可用于校准共同能力；该 7 题仍是开发诊断集，不能作为正式对照成绩。

## A 组相对 B 组的复原差异

阶段 C 记录明确列为新增或加强的机制，在 A 组关闭，在 B 组保持现状：

| 机制 | A：参考基线 | B：阶段 C 候选 |
|---|---|---|
| 客户范围一致性 | 不执行显式客户编号交叉核验 | 执行交叉核验，冲突则停止 |
| 映射依据白名单 | 不拒绝非白名单 `mapping_basis`（仍要求明确设备—合同映射） | 拒绝未受控映射依据 |
| 多份有效合同 | 按复原规则选择一个候选，不作新增歧义拦截 | 多个有效候选时停止并列出候选 |
| 负时长 | 复原假设：按算出的时差直接比较 SLA，不另设顺序异常停止 | 标为 `invalid_event_order`，不判断 SLA |
| 文档检索 | 只进行一次首轮 BM25；未命中修复条款则停止 | 可按定向策略补查，受尝试上限约束 |
| 总时间预算 | 不实施 SQL 与文档检索共用的总预算 | 共用单次预算，并在 trace 记录剩余预算导致的停止 |

两组对时间戳、限值边界（等于上限算满足）、适用日期和来源输出使用同一规则。A/B 使用同一批结构化数据、合同文档、查询文本、PostgreSQL、检索器、依赖和机器。A 组必须独立于 B 的 `CrossSourceDemoTool` 核验/重试逻辑，防止把阶段 C 机制误带入基线。

## 尚无法从记录确定的假设

以下不是已知历史事实。为使复原版本可执行，建议采用右栏的操作性规则，并在任何正式对照前让队员复核：

| 未知项 | 建议复原规则 | 影响 |
|---|---|---|
| 多个有效合同谁优先 | 按合同编号升序选择第一个 | 对歧义题，A 的结果依赖此规则；必须单列，不算历史行为 |
| 同一首轮检索结果里有多个切片 | 与当前 BM25 相同，取 top-k 候选中首个包含修复时限的切片 | 仅控制检索候选的处理顺序 |
| 首轮未命中后如何回答 | 明确输出条款证据不足，不计算达标/超时 | 不允许把缺证据题强行猜成肯定答案 |
| 负时长在旧代码中的精确呈现 | 仅复原“未做顺序异常拦截”，记录实际负时差与比较值；不声称文案与历史一致 | 该题用于检验新增安全拦截，不比较自然语言措辞 |
| 文档与 SQL 引用格式的细节 | 采用相同响应序列化器与字段形状，但只引用 A 实际执行命中的来源 | 保持评审体验一致，不伪造未检索来源 |

若团队不接受某条建议规则，应在实现 A 之前修改本表并重新冻结；不得在看到留出集结果之后按成绩调整 A。

## 配对运行和判分

- 每题分别运行 A 与 B，两次运行使用新 session；交错运行 A/B 次序，避免固定顺序带来的热缓存偏差。
- 运行端只读取 `questions.jsonl`。`gold.jsonl` 由评测器在答案生成后读取，不传入 A 或 B。
- 先由机器核对最终状态、计算值字段、引用定位和 trace；再匿名化、盲审答案语义与证据充分性。
- 必须保留题级 A/B 输出和四格转移：两组都正确、仅 A 正确、仅 B 正确、两组都错。拒答/超时/接口错误保留在分母。
- 结果只支持“该合成工单—合同任务集上的参考算法对照”，不支持真实业务泛化、赛题分数或统计显著性结论。
