## 3. 多候选与条款冲突问题的题意

为了避免从“候选不唯一”错误推出“业务答案不可判定”，下列问题只询问唯一适用对象/唯一时限，不伪装成普通二元符合性问题：

- CS18-043/044：题目要求“能否唯一确定本工单的适用合同”。两份同时有效的结构化关联即足以证明合同不唯一；Gold 判 `not_determined`，不把它解释为服务时限符合性未知。Gold 必须列出两条关联及相应合同/客户/有效期证据。
- CS18-054–056：题目要求“能否从合同原文确定唯一的服务恢复时限”。Gold 判 `not_determined`，必须引用两个冲突时限及“文件未说明适用先后”的原文。此题不计算是否符合，故不得因工单耗时为零而将“时限唯一性”答案改判为唯一。

其余 `computable` 题继续询问是否符合时限，Gold 必须按实际耗时与唯一适用时限判断。若以后改回普通符合性题，只要所有有效候选条款下结论相同，就不能标不可判定。

## 4. Gold 状态字段契约

`expected_status` 仅允许 `repair_within_limit`、`repair_over_limit`、`not_determined`。`expected_metric_state` 必须且只能使用下列枚举：

- `computable`：存在唯一可计算的 accepted→service_restored 时长和适用上限，且必须有 `required_metric`。
- `prerequisite_blocked`：结构化关联、映射/合同有效期、合同状态或客户主体前置条件不成立。
- `event_missing`：受理或恢复端点缺失。
- `event_reversed`：恢复时间早于受理时间。
- `sla_not_stated`：已检索合同明确未约定恢复时限。
- `sla_unresolved`：检索后有多个恢复时限且无可确定的适用顺序，或仅存在未签署草案。
- `document_scope_excluded`：结构化候选关联已成立，但合同正文明确排除目标设备。

`expected_retrieval_state` 仅允许 `retrieval_not_required`、`clause_present_expected` 和 `bounded_not_found`。本 v0.5 题集中不使用 `bounded_not_found`；如任何题使用，必须在题面配额、Gold、检索预算及判定上预先定义，不能临时把召回失败当作正确拒答。
