# 跨源评测判据修订提案 v0.1

日期：2026-10-02。适用范围：v0.3.1 已曝光回归题中暴露的 M05、M06、M08、M14 判分口径，以及后续新题的判据设计。本文件是供团队确认的提案；**不修改既有题集、gold、比较器或历史报告**。v0.3.1 为已曝光合成数据，只能用于回归。

## 核心原则

按“系统实际走到哪一步”评估该步所需的证据，而非要求每题都引用所有来源。跨源问答应允许安全短路：如果对象关系不可信，不能为了满足引用清单继续查合同；如果合同主表已证明映射悬空，也不需要先算事件时长。缺少证据时，评价系统是否准确描述“缺什么、查了什么、因此停止”，而不是把“检索没命中”升格成“原文没有约定”。

每道评测题建议显式记录：

1. 预期结论和允许的拒答状态；
2. 判定阶段（对象/映射核验、合同状态/日期核验、文档条款检索、事件计算）；
3. 此判定阶段必须引用的最小证据；
4. 哪些后续证据不应要求（例如拒绝非受控映射后不要求合同 SLA 文档）；
5. 哪些事实属于已核实、哪些只是检索过程结果。

## 四个已曝光边界的建议

| 题目 | 当前判据冲突 | 建议的严格通过条件 | 建议动作 |
|---|---|---|---|
| M05：合同映射指向不存在的合同 | gold 的 `expected_sql_pks` 包含 accepted/restored 事件行；否定证据文本为英文 `no row`，比较器没有识别中文等价表述 | 引用工单、设备、显式映射；引用 `contracts` 对合同编号的零结果（`row_pk=null`，同一来源说明合同编号过滤条件与未返回记录）；结论限定为无法证明合同适用。无需事件时间证据，不应声称合同过期 | 对未来 gold 只列最小决策证据；比较器将否定证据的结构检查与语言表达分离，允许受控同义短语（“未返回记录 / 无匹配行 / 0 行”） |
| M06：设备主数据缺失 | gold 负证据用 `no row`，实际中文引用明确写“未返回记录（0 行）”，自动器按字面不匹配 | 引用工单行；设备表引用主键为空、同一证据明确设备编号过滤和零结果；状态区别于工单不存在 | 比较器按结构化字段和中文零结果同义表达检查；不要求不存在的设备行主键 |
| M08：有效合同文档未检索到修复时限 | 题目要求说明“检索未命中”，gold 又要求合同文档引用；当前 trace 有两次检索、每次候选数和 `required_metric_not_found`，但未返回 DocRef | 结论只能是“在本次有界检索中未取得可核验修复时限，故不判断”；证据至少要有合同编号、检索次数/策略、每次结果状态和候选数。不能据此断言合同明确不约定 | 可保留现有拒答行为；如需提高可审计性，可将命中候选的文档位置/片段作为“检索过程证据”单独标识，但不能作为“合同没有该条款”的证明。机器判据可以检查 trace，不强制伪造 DocRef |
| M14：映射依据为 `equipment_name_guess` | gold 要求合同文档 ID 与 4 小时 SLA 片段，却要求根据非受控映射依据停止；若照做就违反提前停止原则 | 引用工单、设备、映射依据、合同关系记录；明确非受控依据并在合同 SLA 检索前停止。无需合同文档和事件时长引用 | 未来 gold 删除 `expected_doc_ids` 和修复 SLA 片段要求；把“未触发文档检索”列为预期行为 |

## 比较器建议

- 将“答案正确性”“决策所需引用完整性”“过程 trace 合规”拆成独立字段，保留每项失败原因；不要让一项不相关的 SQL 主键缺失覆盖正确的拒答结论。
- 对拒答类题目，`expected_sql_pks` 只包含作出该拒答所必需的行；事件主键仅在事件计算或缺失事件判定时列为必需项。
- 对否定证据按结构判断：来源表、查询对象/过滤字段、零结果标记；文本只作展示证据，不用英文短语与中文答案做脆弱的逐字匹配。建议记录一个可审计的 `absence_check` 对象，由 SQL 查询结果构造，避免仅靠模型生成的自由文本推断“无记录”。
- 对需提前停止的题目，机器检查应同时约束“不执行后续检索”，而不只是期待某份文档引用。
- M08 的检索未命中属于过程结论：自动检查 trace 的尝试数、检索策略、候选数及未找到目标指标状态；人工检查回答是否把它错误表述为“合同没有约定”。

## 不建议的处理

- 不为让 M05/M06 自动通过而把“no row”硬编码进面向用户的中文引用。
- 不为让 M14 满足现有 gold 而在非受控映射下继续检索合同。
- 不将 M08 的“检索未命中”写成合同明确缺少服务恢复时限；这与明确写有“不约定”的 M09 是不同事实。
- 不回写 v0.3.1 原始包、gold、SHA-256 清单或已经生成的报告。若团队决定修正旧题，另建新版本副本，标注“已曝光回归修订”，重算清单并独立复核。

## 建议的下一步顺序

1. 团队确认上述最小证据口径，重点看“拒答是否应要求后续来源”的边界。
2. 另建比较器单元测试：中英否定表达等价、非必要事件引用不强制、非受控映射必须早停、检索未命中不得推断条款不存在。
3. 更新比较器后，只在 v0.3.1 已曝光题上做回归；报告标注为判据修订后的回归，不称作模型/系统准确率提升。
4. 由未参与本轮系统修改和旧题修订的成员制作全新留出集，并由另一位未见 gold 的成员核对数据和文档；运行者只拿运行包。

需要团队确认的结论：是否接受“每题只要求支持当前决策步骤的最小证据，安全早停不要求后续来源”作为统一评分原则。若未确认，本提案不授权覆盖现有评分脚本或 gold。
