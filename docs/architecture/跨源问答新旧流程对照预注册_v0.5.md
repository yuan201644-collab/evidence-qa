# 跨源问答新旧流程对照预注册 v0.5（v0.4 补充修订）

版本日期：2026-10-04  
适用范围：尚未运行、尚未冻结题包与登记的新一轮跨源新旧流程配对实验。  
继承关系：除本文件明确修订的判分细节外，完整继承《跨源问答新旧流程对照预注册 v0.4》的研究问题、主次指标、题集、冻结、匿名人工评审、运行成本、审计边界与中止条件。v0.4 原件保留，不覆盖；此前已经运行或封存的批次不得套用本版重新计分。

## 唯一方法学修订：最终引用与 trace 命中集合的关系

v0.4 实现曾要求最终 `refs` 集合与所有 `trace.hit` 集合完全相等。该条件与项目既有工具语义不一致：检索、重排步骤的 `hit` 会如实保留中间候选；工具最终 `refs` 则是被答案或确定性事实判定选用的引用。因此，只要存在未被最终引用的真实检索候选，集合相等就会把正常且可审计的 trace 错判为不合规。

自 v0.5 起，trace 覆盖判据修订为：**每一条最终引用必须能在至少一个实际执行步骤的 `hit` 中找到完全相同的来源对象；trace 可以包含未被选为最终引用的中间候选。** 这是单向包含关系：`final refs ⊆ union(trace.hit)`。最终引用仍须满足原有定位、来源、内容和 Gold 片段要求；不能因 trace 中出现候选，就自动算作最终引用或答案证据。引用集合为空时，此项仅表示没有“最终引用脱离 trace”的不一致，不替代正确性/证据盲审。

该修订不更改唯一主指标“严格证据支持成功率”，也不更改人工标签、Gold 字段、题目排除规则或配对统计。相关自动 trace 字段仍单列为次要指标，不可单独代表答案正确或证据充分。

## 实施约束

1. 新一轮运行必须使用本文件的 SHA-256 作为协议锚点，并在工作区外重新登记；不得修改旧批次的协议锚点、运行记录或评分结果。
2. 冻结源码应包含执行上述单向包含检查的评分代码及对应测试；运行后不得据输出调整检查逻辑或重算确认性结果。
3. 本版不放宽任何事实证据要求：数据库负面事实仍须由查询执行元数据构造；文档来源仍须来自本轮实际检索；安全早停仍须使用冻结白名单原因码和可定位支持证据。

## 本轮可测范围的预先限定

本次新留出集只覆盖当前新臂已经具备真实执行接线的两类路径：`clause_present_expected`，以及有已执行行级 SQL 证据支撑的 `retrieval_not_required`（仅限 `customer_scope_conflict`、`mapping_basis_unapproved`、`validity_window_not_cover`、`ambiguous_active_contracts`、`event_time_reversed`）。这些早停题在 Gold 中将 `expected_status` 记为 `not_determined`，具体阻断原因由单独的 `expected_early_stop_reason` 核验。两字段表达不同层级：前者是业务答案状态，后者是确定性流程原因。

本轮明确不含 `bounded_not_found`、映射零行、设备主数据缺失、关键事件缺失或其他依赖数据库负面事实的题目：当前 A/B 新臂尚未接通协议要求的两次真实补查或完整零行引用与元数据。虽然白名单和 Gold 格式保留这些能力类型，但本轮不以此推断它们已实现。若后续要评估这些路径，须先补齐实现、单测、评分器集成测试，并在新协议 / 新题集下冻结。

旧臂通过其真实 `hybrid_retrieve` / `rerank` trace 表示 RAG 调用；新臂通过私有 `cross_source_doc_retrieval` projection 表示真实混合检索调用。评分器只为条款存在题接受这两种对应形态；两次尝试数量、策略和候选数仍只从新臂明确记录的实际 attempt 元数据核验，不从旧臂步骤数推算。`retrieval_not_required` 的安全流程检查还要求 alignment 步骤携带至少一条进入最终 `refs` 的 SQL 定位证据（若为数据库负面事实，则须使用包外 Gold 明确声明的负面引用/检查）。

旧臂不产出新臂的确定性 `cross_source_alignment.status`，因此自动 `expected_status` 比对对旧臂可能保守失败；这是次要自动诊断，不得替代两位匿名评审对答案语义和证据充分性的主指标。原始答案文本不得为获得状态匹配而被运行器改写或拼接人工判定结果。
