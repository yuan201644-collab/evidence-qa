# 跨源问答新旧流程对照预注册 v0.2

版本日期：2026-10-04  
继承：`跨源问答新旧流程对照预注册_v0.1.md`。除本文件明确补充/覆盖的项外，v0.1 的比较对象、盲审规则、指标及结论边界继续有效。  
适用范围：尚未生成任何正式留出答案的新一轮实验。已曝光 ARC-01–ARC-12 和所有历史题集不因此恢复未见资格。

## 修订动机与状态

v0.1 尚无与之匹配的运行包、冻结登记或计分运行。为避免正式运行时临时解释可信度缺口，v0.2 在任何新题计分回答生成前补明数据库只读权限、运行包与数据库逐行一致性、运行前外部冻结登记、盲审去组别方式，以及托管大模型权重不可哈希这一已知限制。若已经针对某题生成过任何回答，该题不得进入本协议的新留出集。

## 1. 新增硬闸门：题包与数据库一致

运行包 CSV 是该批结构化数据的唯一冻结源。运行前必须逐表比较 CSV 解析后的所有行与目标数据库表的所有行，不得只比行数。表定义和主键从同一运行包 `schema_meta.json` 读取；类型转换按元数据执行；任何不支持的数据类型、空值歧义、主键重复、行数或内容哈希差异均停止运行，不可忽略或现场修正。冻结登记及报告同时保留 CSV 与数据库的逐表行数和内容哈希。

运行账户必须是专用只读角色：对五张业务表和向量索引表不得有 `INSERT`、`UPDATE`、`DELETE`、`TRUNCATE` 权限，对业务及向量 schema 不得有 `CREATE` 权限；连接本身还须置为只读事务。权限预检失败即停止，不以“代码里没有写 SQL”替代权限证据。

RAG 文档索引的文档 ID 集合必须与运行包合同文档文件名集合完全相等；向量内容、分块元数据及结构化数据均在问答前后复算快照。向量索引只在冻结前准备，不在计分期间写入或自动补建。

运行包应提供不含答案提示的 `data/documents_manifest.json`，每份文档仅列 `id`、`file`、`title`、`category`。文档路由、标准化和 NL2SQL 的结构化路由信号都必须使用本次运行包里的 schema 元数据与文档清单；不得让默认安装库的 `infra/schema_meta.json` 或默认语料清单悄悄参与某一臂。v0.2 运行器会将运行包元数据路径显式注入两臂，并纳入哈希。

## 2. 新增硬闸门：运行前冻结与外部锚定

在生成正式答案前，先保存题包清单、预注册、源码、依赖、配置、模型可识别信息、数据库/索引快照及随机调度表构成的冻结登记。登记文件必须放在项目工作区之外；运行者或独立保管人把登记 SHA-256 固定到另一个只读/版本化位置，再启动正式运行。正式运行必须验证登记哈希并逐字段比对当前状态；缺少外部锚点、登记复用、任一项漂移或答案数不符，均不得封存为有效对照。

日期/相对时间解析基准 `APP_TIME_ANCHOR` 必须作为必填命令参数显式冻结，两臂共享同一值；不得默认读取运行机器当天日期。

结束后运行器保存原始回答哈希、预运行登记哈希和完整性检查结果。保管人还须将封存清单哈希复制到运行目录之外；运行目录内由脚本生成的锚点副本不算独立锚定。异常、超时、空回答全部保留，不按答案好坏重跑或删题。

运行包仅允许问题、必要数据库结构/字段元数据、结构化 CSV 和合同原文；不得带 Gold、配对密钥、作者自审或可能泄露逐题标准答案的编题说明。运行器不搜索 Gold 路径，只接受显式运行包路径，并拒绝未列入清单的文件。

## 3. 托管大模型版本的可验证边界

本项目的对话模型通过远程 OpenAI 兼容接口调用时，实验方通常只能固定并记录服务端点身份、请求模型名、温度、超时/重试和调用时间；若服务方不返回可核验的权重修订号或文件哈希，就不能声称已锁定或逐字节复现其模型权重。该项必须在冻结登记中标为“远程模型权重哈希不可得”，不能用模型显示名称冒充权重哈希。

A/B 仍在同一实验时段使用同一端点和模型名，温度为 0，题目与流程臂随机交错执行；若服务端提供可审计的模型修订标识，应逐请求留存并检查一致性。若无法获取服务端修订标识，报告必须把服务端模型漂移列为残余混杂因素，并将结论限定为该次运行、该服务端点声明配置下的观察；不得宣称跨日期严格复现或隔离了模型版本变化。Embedding/重排模型若为本地文件，则继续保存实际权重快照的逐文件哈希。

## 4. 新增盲审材料生成规则

盲审表从成功封存的原始回答生成，生成前验证封存清单外部哈希、原始输出哈希、记录数、每题恰好一份旧流程与一份新架构输出。每次独立随机化题号、候选编号、候选顺序及组别标签；评审稿删除流程臂标识、执行次序和工具 trace，只保留问题、原回答及其引用证据。原始 trace 另交独立技术审计者，不与人工盲审稿混发。

组别/题号密钥写入项目工作区之外的受控位置，只由数据保管人持有；与匿名表分开交付。盲审者不得看到 Gold、密钥、作者自审或另一位评审意见。至少两位评审者独立评定；后续按 v0.1 规则保留分歧并裁决。评审稿哈希、生成器哈希和密钥哈希分别记录。

## 5. 结论边界

除 v0.1 所列限制外，新增说明：即使通过本协议，远程模型权重未公开哈希时仍存在不可消除的服务端版本不确定性；合成题集及有限题数仅支持描述本批冻结题上的配对观察，不支持真实业务外推、普遍提升或统计显著结论。对外报告须逐题列出结果和失败，不隐藏运行错误，并同时给出盲审原始计数、trace 合规、调用数与耗时分布。
