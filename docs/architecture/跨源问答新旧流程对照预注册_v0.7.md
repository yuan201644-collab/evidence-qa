# 跨源问答新旧流程对照预注册 v0.7（v0.6 补充修订）

版本日期：2026-10-04  
适用范围：v0.12 运行因引用来源使用 mock 而判无效后，重新独立制作、复核且尚未运行的新留出集。  
继承关系：本版完整继承 v0.4、v0.5、v0.6 中未被本文件修订的方法、范围和判据。既有无效/已封存批次不适用本版重算；v0.4–v0.6 原件保留。

## 修订原因与硬性约束

v0.12 独立技术审计发现，两臂都注册了 `graph_reason` 的 mock 实现；该实现可以返回预置 DocRef，造成最终文档引用虽能在 `graph_reason` trace 中找到，却不是本轮实际 RAG 检索结果。该次运行已按独立无效处置记录判为无效，原始回答、封存、预注册、评分和盲审表均保留，不得分发、评分或重跑。

1. 正式实验只允许使用真实结构化查询与真实 RAG。当前没有真实图谱/KAG 后端，所以两臂都必须以 `graph_backend="disabled"` 构建，不得注册 `MockGraphReasonTool` 或其他返回预置业务引用的工具。
2. 旧流程的跨源计划按真实 `nl2sql` 后真实 `doc_search` 执行；新流程使用其冻结事实计划与相同只读 SQL/RAG 数据源。工具调用数量、耗时仍按各流程实际记录，不人为配平。
3. 条款存在题的每一条最终 DocRef 必须与真实文档检索步骤的 `hit` 完全匹配。只有其他步骤（包括 `graph_reason`、业务工具或 mock 工具）的 hit 不构成文档检索证据；评分器必须将其判为引用完整性失败，技术审计也必须检查这一点。
4. 正式运行前必须通过测试：旧/新两臂均未注册图谱 mock；无图谱时旧流程会形成真实 SQL+RAG 工具计划；仅在 `graph_reason` hit 中出现的 DocRef 不能通过文档引用判据；实际 RAG hit 中的 DocRef 可正常通过相应来源检查。
5. v0.12 的题包、Gold 和回答已被作者/运行者与审计者接触，修正后不得继续作为确认性留出集。新包必须更换业务实体、编号和条款组合，由独立数据复核人重新核验、冻结并登记；旧包仅能作为已曝光回归材料。

除上述来源与运行配置澄清外，v0.4 的唯一主指标和人工匿名评审流程不变。任何新运行仍须在答案生成前冻结并在工作区外登记协议、运行包、Gold 哈希、代码与数据库/索引快照；Gold 不得进入运行器。
