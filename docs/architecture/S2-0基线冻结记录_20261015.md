| `database_name` | chinook | chinook | ✅ |

复现命令：`D:\python\python.exe agent_temp\_s2\fingerprint_check.py`

### 3.2 后果：T5 评分**直接报错，无法出分**

`eval/mainline/score_t5_development.py:175`：

```python
if actual_fingerprint.get(actual_key) != expected_fingerprint.get(expected_key):
    raise RuntimeError("评分数据库与 T5 冻结数据内容指纹不一致，停止评分")
```

即 **T5 20/20 这条战绩今天无法重新验证**。这不是"分数下降"，是"根本跑不了"。

### 3.3 根因：两个额外 schema 被灌进了同一个 `chinook` 库

`eval/mainline/fingerprint_postgres.py:40-46` 扫描的是**所有非系统 schema**：

```python
"WHERE table_type='BASE TABLE' "
"AND table_schema NOT IN ('pg_catalog', 'information_schema') "
```

而 `chinook` 库现在的 schema 分布：

| schema | 表数 | 行数 | 来源 |
|---|---|---|---|
| `public` | 13（11 Chinook + `chunk_vectors` + `doc_meta`） | 15,607（不含 RAG 两表） | 原始 chinook |
| `scale` | 3 | **111,000** | `infra/scripts/seed_scale_sales.py` |
| `arch_coldchain_v012` | 7 | 0 | `eval/cross_source_heldout/architecture_2026Q4_v0.12_preparation/build_v012_artifacts.py` |

126,887 − 111,000 − 0 ≈ 15,887 ≈ 15,769 + RAG 表 → 增量被这两组 schema 解释清楚。

**时间线**：

| 时间 | 事件 |
|---|---|
| 2026-10-11 00:14（`dddc236`） | T5 数据清单最后改动（冻结主线候选源码） |
| 之后 | `1de728c` 新增 `seed_scale_sales.py`（独立 schema `scale`） |
| 之后 | `build_v012_artifacts.py` 建 `arch_coldchain_v012` |

**讽刺之处**：`seed_scale_sales.py:4-6` 的注释写明"放在独立 schema `scale`，而不是 public"的理由是——**

> `infra/scripts/verify_infra.py` 的「chinook 基表数」断言（`CHINOOK_EXPECT["tables"] = 11`）查的是 **public schema 下的全部基表**

它防住了 `verify_infra.py`，**但没防住 `fingerprint_postgres.py`**（后者扫全部 schema）。同一个动作保住了 A 断言、打坏了 B 断言。
