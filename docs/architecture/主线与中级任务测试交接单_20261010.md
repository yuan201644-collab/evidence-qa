## 4. 测试前保护措施

当前工作区有大量未提交和未跟踪文件，属于团队现有工作。开始时必须：

1. 记录当前分支、`git status --short`、相关源码文件哈希；不得清理、回滚、覆盖或提交已有改动。
2. 检查测试会连接的数据库、服务、索引及端口，记录无凭据的配置摘要和数据快照指纹；不确定服务归属时先停止，不要关闭或删除容器、卷、索引。

4. 不在报告、命令历史或输出中打印 API 密钥、密码、带凭据连接串或令牌。批量模型调用前先核实当前模型配置与调用规模，保留必要成本/请求数记录。

6. 发现代码问题时先停止在“测试发现”状态，提交最小复现、trace 和影响面；本次委托是测试，不默认授权修改业务代码、公共契约或默认配置。

## 5. 执行顺序

### 阶段 A：静态盘点与可复现性

- 对照最新报告核对当前分支、源码哈希、Python/依赖、模型服务、数据库快照及关键开关。
- 清点现存测试、开发题包、参考结果、采集脚本与评分器。区分运行器读题、生成器读参考答案和封存后评分的时序；若不能证明答案未进入生成/采集阶段，结果只能标为诊断。
- 先确认现有测试命令及被排除测试的原因，不根据旧日志假设当前环境相同。

### 阶段 B：自动化回归

按仓库当前依赖与测试配置运行定向测试，再运行项目已记录的全仓回归。历史记录中的 Windows PowerShell 命令形式如下；运行前应核对是否仍适用：

```powershell
$env:PYTHONUTF8 = '1'
uv run --locked --with pytest python -m pytest --import-mode=importlib -q -o addopts= -k 'not test_final_counts_and_qualification and not test_third_reviewer_replaces_only_disputes and not test_runtime_package_and_question_fields_are_fail_closed'
```

记录精确命令、退出码、通过/失败/跳过/排除数、警告，以及失败测试是否与本轮范围有关。不要为了得到绿色结果临时扩大排除范围。

### 阶段 C：主问答链路

至少覆盖以下检查，并从真实运行 trace 核对，不只看最终自然语言答案：

- **NL2SQL：** 表和字段定位、SQL 只读校验、实际执行结果、结果列/行与引用是否一致；拒绝写操作 SQL；无结果、歧义和大结果集处理。
- **RAG：** 单文档事实、多文档核对、语料缺失时的拒答/限定；引用是否能回到正确文档片段，答案是否超出证据。
- **编排与可解释性：** 路由选择、工具输入输出、错误/重试/超时路径、来源引用与 trace 的一致性；不得用模型思维链代替系统实际执行记录。
- **多轮：** 澄清前后槽位、会话隔离、取消/过期/容量边界；明确标注当前不支持的多进程或重启恢复能力。

### 阶段 D：中级任务专项

**任务 3：缺失信息澄清**

- 测试触发条件是否确实缺少必要维度；提供补充后是否在同一会话恢复原问题；继续补充、改问、取消、超时、容量淘汰和不同会话交错是否串线。
- 核对每轮 trace：澄清字段、用户补充、恢复后的 SQL 和最终答案是否一致。
- 单独记录未覆盖的多进程并发、进程重启、长时间压力等边界，不把单进程内存测试泛化到这些情形。

**任务 4：多表 schema 定位**

- 在大量相似表/字段的环境中，逐题检查候选表字段召回、关联计划和最终 SQL 是否包含必要对象并排除干扰项。
- 对最终只读 SQL 做实际执行与结果复算；分别报告查询成功率、严格结果匹配率、表/字段召回率和错误类型，不能只报告一个总分。
- 重点复核 U19 大结果集：当前默认上限、截断提示、实际返回行数、参考结果行数及多重集差异。不得为了通过该题直接删除安全上限或掩盖截断。

**任务 5：复杂 SQL 与关联粒度**

- 覆盖多表 JOIN、聚合、嵌套/存在性子查询、多路径、空结果和一对多重复计数等模式。
- 对每题记录计划路径、实际 SQL、执行结果、参考结果复算及行粒度；重点检查 JOIN 后聚合是否因重复行改变数值。
- 将 SQL 结构不同但结果等价与真正语义错误分开记录。

**任务 1：要素识别与问题改写**

- 以题面和 `docs/要素识别与改写_接口_v0.1.md` 为判据，覆盖业务别名、口语表达、错别字/格式变体、业务编号与新类型要素；检查是否识别、是否错误替换、是否保留原始含义，以及改写是否确实改善后续路由/查询。
- 对未收录别名和类型变化单独测试，区分显式 unresolved、正确标准化与臆造实体；不能只在已有词表上统计命中率后宣称具备不限定实体类型的泛化能力。
- 记录要素级精确率、召回率/F1 或项目已冻结的指标定义；若找不到冻结判据，先报告口径缺失，不临时挑选有利指标。

**任务 7：PDF 目录结构识别与分层切片**

- 依据题面原文，检查非标准目录、缺失/混乱编号、层级缩进或标题格式变体下的标题识别、父子层级恢复及切片 `section_path` 是否正确。
- 使用原 PDF 页面或可信抽取结果核对标题与页码；抽查切片边界，确认正文没有被错误并入邻近标题，跨页章节没有丢失上下文。
- 分开报告标题识别、层级恢复、切片路径和下游检索/引用结果；多跳 RAG 命中不等于任务 7 通过，任务 7 通过也不等于 RAG 忠实度达标。

### 阶段 E：结果复核与报告

- 评分/对照脚本应在运行输出封存后读取判据；报告中写明判分规则和人工抽查方式。
- 为每个失败案例保留题号、输入、问题类型、trace、实际 SQL、只读执行结果、参考结果、偏差分类和可复现命令。
- 运行前后检查数据库/包哈希，说明代码树是否脏、是否存在 API/依赖变化、有没有超时或重试。
- 失败不可静默丢弃；环境错误、生成错误、SQL 执行错误、结果不匹配、引用不足分别统计。

| 边界 | 本题可证明什么、不能外推到什么 |
