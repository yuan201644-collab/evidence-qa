**判分口径**：一组用例有 5 轮，**必须 5 轮全部通过才算这一组通过**。任何一轮失败，该组即判失败（后面的轮次仍会跑，但整组不计分）。


## 五、剩余两个根因（你的工作）

### 5.1 度量口径：「花了多少钱 / 合计多少」被映射到 `budget_yuan`，应为 `award_yuan`

**证据（`gmt-03` 第 2 轮）**：

```sql
-- 当前生成（错）：
SELECT SUM(projects.budget_yuan) AS total_spent
FROM projects JOIN buyers ON projects.buyer_id = buyers.buyer_id
WHERE buyers.buyer_name = '清华大学'
GROUP BY buyers.buyer_name
-- 返回 168,644,000

-- 期望：45,058,000.00，用 awards.award_yuan
```

**`gmt-02` 第 3 轮**同一根因：「只看公开招标的项目，合计多少」期望 `1,972,844,290.01`，字段 `award_yuan`，返回 1 行。

**要注意**：`gmt-03` 第 2 轮的**对象锚定已经修好了**——`WHERE buyers.buyer_name = '清华大学'` 是对的，就是靠上一轮选中行（`first_row` → `selected_row` → 提示词）贯通出来的。别把这段改坏。剩下**只差度量列**。

**为什么不建议直接改词表**（重要）：

`app/nl2sql/semantic_validator.py` 的 `_locus_of_measure` 是**字面包含**判据，刻意不做同义词表。之前 `grob-18`「中了标的钱」因为与列说明「中标金额」没有公共子串而失败，当时的结论就是**不为一道题放宽判据**。如果你现在给度量词加一张「花了→中标金额」的同义词表，会连带改变鲁棒性 18 题里已有 16 题通过的行为，很可能掉分。

**建议的排查顺序**（按性价比）：

1. 先看 `awards.award_yuan` 在 `infra/schema_meta_gov.json` 里的**列说明原文**是什么，以及 `projects.budget_yuan` 的说明。口径差别应该写在说明里。
2. 用只读脚本跑一句：「花了多少钱」这句话在 `app/query_requirements.py` 里被归成了什么 `measure` 要求（`_MEASURE_TERMS` 附近）。
3. 再看 `app/nl2sql/linker.py` 与 `semantic_validator.py` 是怎么把它落到具体列的——大概率是「金额」这个词先命中了 `projects.budget_yuan`。
4. 真正干净的修法通常在**列说明/别名元数据**层（`infra/schema_meta_gov.aliases.zh.json` 的 `columns` 分区），而不是在代码里加同义词。这个文件是本次新增的，`AliasTable` 是 pydantic 严格模型，**只允许** `version / updated_at / notes / tables / table_mentions / columns / values` 七个键，多一个就校验失败。

### 5.2 `gmt-01` 第 5 轮：「把地区也带上，两个维度一起看」

**期望**：按 `region_name` + `procurement_way` 两个维度分组，保留第 2 轮的 `budget_level = 'central'` 条件，**5 行**。

**当前**：返回 `regions` 单表 31 行（`SELECT region_code, region_name, level FROM regions LIMIT 1000`），完全丢掉了统计对象和筛选条件。

**已经修好一半**：这一轮现在**能被识别成追问**了（`app/memory.py` 的 `_FOLLOWUP_MARKERS` 补了「也带上 / 一起看 / 两个维度」，`regions` 别名补了「地区」，`_has_new_group` 结构判据替代了中文词表）。剩下的是：追问提示词虽然生成了，但模型没有沿用上一轮的 `COUNT(*)` + `budget_level='central'`。

**排查建议**：

## 七、硬约束（都是踩过的坑）

1. **PowerShell 里内嵌 `python -c` 带 SQL / 引号 / `<` 一律失败**。要跑诊断脚本，用 `write` 工具写成 `agent_temp/pb/xxx.py` 再执行。
2. **jieba / torch 会往 stderr 打印加载信息**，让 PowerShell 报 `[exit code: 1]`，但脚本本身是成功的。看输出内容判断，不要看退出码。
3. **`normalize(q, time_anchor=...)` 只接受 `datetime`**，传 `date` 会 `AttributeError: 'datetime.date' object has no attribute 'date'`。
4. **不要把可能出现在复合短语里的两个字当表别名**：曾经把「中标」当裸别名，结果把「中标金额」切成了「中标」+「金额」。别名表 `infra/schema_meta_gov.aliases.zh.json` 已经被清理过一轮。
5. **改切块规则必须同步升 `INDEX_FORMAT_VERSION`**，否则向量库会认旧索引。本轮任务不涉及向量库，别动。
6. **判断「是不是追问」的判据宁可漏、不可误**：漏判追问只是这一轮答得差；误判追问会把单轮问题错接到上文，直接改掉查询对象，后果严重得多。单轮 77 题里目前还有 2 题被误判（`grob-09`「数量是多少？」`grob-10`「帮我看下最多的那个。」），那是鲁棒性题集里设计成**应该**澄清的，可以接受，别去动。
