# EvoOntology 任务4直接定位实验设计 v0.2

更新日期：2026-10-04。状态：**32题 Gold v0.2 已独立复核并封存；本地 preflight 与输入 SHA 冻结已完成；尚无模型运行记录**。

## 实验问题

本轮只回答一个范围明确的问题：在 AdventureWorks 的 80 个数据库对象（71 张基表、9 个视图）上，Builder 产出的业务知识是否能帮助模型直接定位问题所需的表和字段？本测评使用人工拟定的问题集，不代表真实项目的业务定义，也不用于兑换赛事分数。

主要比较是 C 臂（按需检索知识，并只提供检索选中的数据库结构）相对 A 臂（完整数据库结构、无业务知识）对字段召回率的影响。B 臂（完整数据库结构、整本注入知识）用于辅助比较。三臂共用题目、模型设置与输出格式。

**解释边界**：B-A 比较整本知识注入的增量；C-A 比较“按需知识检索＋结构筛选”的组合效果；C-B 比较两种知识呈现/结构输入策略。由于 C 同时减少可见结构并增加检索规划请求，C-A 不能单独证明增益来自本体知识，也不能把变化归因于某个单一因素。若需要拆分知识检索与结构筛选的独立贡献，须另增消融臂，本轮不做。

## 题目与标准答案

题集为 32 道人工澄清的任务4定位题，封存文件为 `eval/experiments/evont_next/task4_cases_sealed_v0.2.json`，修订生成器和未封存草稿仍保留在同目录。本题集是可控基准：遇到原题中“去年”“销售额”“当前”“差异”等不明确说法时，我们明确补上固定日期、金额公式、数据粒度或筛选规则。这里的澄清是为了让本轮的定位标准可重复，不是对真实业务的断言。

每题的 `required_tables` 与 `required_columns` 表示完成题目所需的必要候选集合。生成器校验题目引用的表、字段存在，字段所属表包含在所需表中，且所需表在外键图中连通；题面不直接泄露数据库物理表名和字段名。原始封存 v0.1 题集和既有运行记录保持不变。

日期依据已对正在运行的 AdventureWorks PostgreSQL 容器执行只读查询：订单日期最早为 2011-05-31、最晚为 2014-06-30；2013 年订单头记录 14,182 条；2013 年上市产品 136 个；当前数据中 `TerritoryID` 为空的订单为 0。复核命令示例：

```powershell
docker exec ict-aw psql -U postgres -d postgres -c 'SELECT min("OrderDate")::date, max("OrderDate")::date, count(*) FILTER (WHERE "OrderDate" >= DATE ''2013-01-01'' AND "OrderDate" < DATE ''2014-01-01'') FROM "Sales"."SalesOrderHeader";'
```

时间范围是这份固定数据集的观测值，不应推广成 AdventureWorks 其他版本或真实业务数据的时间范围。

## 输入条件

| 实验臂 | 模型可见输入 |
|---|---|
| A | 完整数据库结构，不提供业务知识 |
| B | 完整数据库结构，加 Builder 知识条目全文 |
| C | 先按需检索业务知识，再只提供选中表及其连接所需结构；检索失败时不给完整结构兜底 |

每题每臂运行一次，题目是统计配对单位。每题三臂的执行次序使用固定种子随机打乱。运行失败、无效 JSON 或检索失败均保留，不补题、不静默重跑。

## 输出与计分口径

模型只返回一个 JSON 对象：`tables` 为按相关性排序的全限定表名数组，最多 10 项；`fields` 为按相关性排序的全限定表.字段名数组，最多 30 项。输出 JSON 无效或超过上限时，视为空候选预测。

评分时仅去除候选首尾空白，按精确大小写比较。重复项只保留第一次出现；未知表名或字段名保留在预测列表中并计为假阳性。Gold 是必要候选集合，因此采用集合包含评分：预测可以包含额外项，但额外项降低精确率，不会因集合不完全相等而将正确项判错。

- 精确率 = 命中 Gold 的去重候选数 / 去重候选总数；空预测记 0。
- 召回率 = 命中 Gold 的候选数 / Gold 候选数；失败题召回率记 0。
- 排序指标为表召回率@1、@3，字段召回率@5、@10。
- **主指标为字段召回率的题目宏平均**：先逐题计算，再对 32 题等权平均，不按每题 Gold 字段数加权。
- 表精确率/召回率、字段精确率、排序截断召回率、JSON 完成率、调用量与时延均为次要结果。
- 本版本不运行或评分最终 SQL，不以 SQL 执行结果作为结论依据。

异常记录、无效输出、检索失败或缺臂均不得从统计中剔除；对应召回按 0 计，正式汇总须保留 32 个配对题目。这样失败不会通过缩小分母抬高结果。

## 分析与结论规则

主比较为每道题的 `C字段召回率 - A字段召回率`，对题目级差值做 2,000 次固定种子的百分位 bootstrap，报告平均差值和双侧 95% 区间。只有区间下界大于 0，才记为“在本基准观察到正向增益”；区间包含 0 时记为“证据不足”，不得表述成已证明无效。B 对 A、C 对 B 为次要比较。JSON 完成率的配对差异另报精确 McNemar 结果，但不替代主指标。

题目数只有 32，因此本轮定位为可复现的初步验证，不声称结果能代表全部数据库、项目问题或真实用户分布。若后续要支撑更强结论，应先扩大独立题集，再执行一次新的冻结实验；不得把新旧结果混合统计。
