# 知证 VeriMind 图标资产与扩展指南 v0.1

更新日期：2026-10-12  
适用范围：前端、品牌图标总览、项目流程图及后续新增的 FEVA 机制图标。

## 1. 图标资产分层

品牌图形的源文件统一保存在 `web/public/brand/`，项目界面和文档引用同一份 SVG，避免复制后出现不同版本。

前端侧栏主标志与浏览器图标的引用地址使用相同版本参数（当前为 `?v=20261012`）。替换主标志后，两处版本参数应一起更新并重新构建，避免已打开的浏览器继续显示缓存中的旧图形；SVG 源文件仍只维护一份。

| 类别 | 源文件 | 用途 |
|---|---|---|
| 彩色主标志 | `verimind-mark.svg` | 前端侧栏、浏览器图标、流程图品牌署名 |
| 单色主标志 | `verimind-mark-mono.svg` | 单色打印与低彩度材料 |
| FEVA 整体架构图标 | `icons/feva-architecture.svg` | 工作台架构入口与 FEVA 整体机制标识，不代表独立执行模块 |
| 机制与能力图标 | `icons/*.svg` | FEVA 各机制、数据库问数、文档问答和 KAG 研究支线 |
| 数据库目录图标 | `icons/database-catalog.svg` | 左侧栏数据库展示入口；表示实时连接状态与已加载的表字段结构目录，不属于 FEVA 执行机制 |
| 通用交互图标 | `web/src/components/AppIcon.vue` | 菜单、关闭、复制、翻页、发送等界面操作，不属于品牌图标族 |

当前机制与能力图标：

| 文件名 | 名称 | 语义 |
|---|---|---|
| `fact-flow.svg` | 事实流 FactFlow | 待回答事实及其依赖顺序 |
| `source-bridge.svg` | 跨源证桥 SourceBridge | 不同来源之间的受控对象关联 |
| `metric-align.svg` | 口径对齐 MetricAlign | 事实定义和比较基准核对 |
| `evidence-ledger.svg` | 证据账本 EvidenceLedger | 事实状态与证据来源记录 |
| `bounded-verify.svg` | 有界求证 BoundedVerify | 补查预算与停止边界 |
| `query-guard.svg` | 查询卫士 QueryGuard | 结构化数据查询能力 |
| `doc-lens.svg` | 文证透镜 DocLens | 文档检索和原文定位能力 |
| `gap2graph.svg` | KAG增强路线（原 Gap2Graph） | KAG 研究支线；图标不表示已接入默认问答链路。文件名保留历史代号，不随展示名改动 |
| `database-catalog.svg` | 数据库与库表目录 | 展示业务库连通状态，并浏览当前结构目录中的表、字段、类型和关联 |

FEVA 整体架构图标以多层折面围合中心核，表达五阶段协同组成的核验机制；它不表示新的执行阶段，也不取代五个阶段各自的模块图标。

## 2. 生产与生成方式

最终交付图标采用手工维护的矢量 SVG，不依赖运行时模型调用、外部图片地址或位图生成服务。设计探索可以借助草图或图像模型寻找方向，但进入项目的资产必须整理成可审阅、可编辑的 SVG 源文件；概念图不作为线上图标直接引用。

功能图标按以下约束绘制：

- 画布为 `48 × 48`，图形保留约 `3 px` 安全边距；主要轮廓在 `16 / 29 / 44 px` 下都应可辨。
- 延续折面视觉：切角多边形、斜向折痕、错位层叠或负形；每枚图标控制在 2–5 个主要形面。
- 单枚图标原则上不超过三种填充色：品牌蓝 `#315bc7`、深蓝 `#254ba6`、浅蓝 `#8fa8e9`、核验青绿 `#168b82` / `#55d4c3`。KAG 支线使用紫色系。
- 为 SVG 添加可读的 `<title>` 与唯一的 `aria-labelledby` 标识。图标本身不承载状态结论，也不依赖文字以外的隐藏含义。

推荐的新增流程：

1. 写清楚该模块在系统中的真实职责，以及它与相邻模块的区别；先定义语义，再画形状。
2. 选一个简单轮廓隐喻，优先保证小尺寸可识别，不把整段技术流程塞进一枚图标。
3. 在 `web/public/brand/icons/` 新建 SVG，使用 `viewBox="0 0 48 48"`，直接编辑路径与色面。
4. 将文件名和用途登记到 `docs/brand/图标总览.html`，并在实际界面位置引用同一源文件；若新增的是独立模块卡片，再登记到 `WorkspaceView.vue` 的 `architectureModules`。
5. 若流程图需要展示该图标，将文件名加入 `docs/architecture/项目整体流程图_v0.2.cjs` 的 `brandIcons` 映射。该生成器会读取源 SVG 并嵌入流程图，避免图标副本漂移。
6. 更新总览图和流程图预览，检查实际页面，再运行前端构建和界面检查。

新增图标前，先按下面的简报写清需求，避免只凭“画得像不像”反复返工：

```text
模块中文名 / 英文名：
在系统中的实际职责：
与相邻模块最重要的区别：
希望表达的单一视觉概念：
必须避免的误读：
优先使用的品牌色：
主要使用尺寸：48×48 SVG；界面显示约 29–44 px
```

如果用生成式工具探索构图，生成结果只作为草案；验收后将路径整理进项目自己的 SVG 源文件。线上不会调用生成工具，审阅 PNG 也只是从源 SVG / HTML 渲染出来的预览。

## 3. 预览图和流程图的再生成

### 图标总览

在 `web/` 目录运行：

```powershell
npm.cmd run brand:preview
```

该命令以 `docs/brand/图标总览.html` 为输入，使用本机 Edge（或 `UI_BROWSER_CHANNEL` 指定的浏览器）重生成 `docs/brand/图标总览.png`。PNG 是审阅预览，SVG 仍是唯一图形源文件。

### 项目整体流程图

在 `docs/architecture/` 目录运行，版本号应使用新文件名，不覆盖历史图：

```powershell
node 项目整体流程图_v0.2.cjs 项目整体流程图_v0.6
node 项目整体流程图_v0.2_render.cjs ..\..\web\node_modules\playwright 项目整体流程图_v0.6
```

生成器输出同名 `.svg` 和 `.html`，渲染脚本输出 `.png` 与 `_排版检查.json`。流程图使用 `web/public/brand/icons/` 下的现行 SVG；更改图标后只生成新的流程图版本，不回写旧版本。

## 4. 检查清单

在 `web/` 目录执行：

```powershell
npm.cmd run build
npm.cmd run test:ui
npm.cmd run brand:preview
```

还应目视检查图标总览、架构说明弹窗、前端欢迎页与最新流程图，确认轮廓未裁切、语义不混淆、文字没有溢出。受控界面检查只验证页面结构与交互，不代表模型回答或业务能力已通过验收。

## 5. 当前图标形态说明

- 主标志使用左右来源面汇合、左侧页签折角与中心核验记号，强调“来源汇合并形成可核验结论”。
- 跨源证桥采用左右来源面与横向桥面，强调“建立受控关联”。
- 口径对齐采用上下测量面与共同基准线，强调“使用同一口径比较”。
- KAG增强路线（图标文件 `gap2graph.svg`）使用独立紫色，不与默认问答主链路混为一谈。

更完整的构形、配色与尺寸约束见 [`品牌图标设计规范_v0.3.md`](../品牌图标设计规范_v0.3.md)。

界面中的图标动作、页面入场和弹窗过渡统一遵循 [`前端动效规范与扩展指南_v0.1.md`](前端动效规范与扩展指南_v0.1.md)，公共参数在 `web/src/styles/motion.css` 中维护。
