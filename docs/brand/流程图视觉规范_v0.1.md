# 知证 VeriMind 局部流程图视觉规范

版本：v0.1　｜　日期：2026-10-16  
适用：设计报告、技术实现说明书及汇报材料中的局部业务流程图

## 用途与边界

本规范记录团队已确认的“图标主体、紧凑排布、仿导师流程图”的局部流程视觉风格。适合说明一段业务链路、核验步骤或来源间关系；不替代项目整体架构图规范、产品界面规范和品牌标志规范。

项目整体品牌仍以[品牌图标设计规范](../品牌图标设计规范_v0.1.md)为准。前端、主标志和通用模块图使用项目品牌资产。只有在制作本规范所述的汇报局部流程图、且任务明确采用该参考风格时，才使用已确认的插画图标样式；不要将其误用为新的产品图标集。

## 视觉目标

- 让图标成为每一步的视觉主体，节点名称直接放在图标下方。
- 通过模块分区、图标、短箭头表达流程，减少节点卡片、长段说明和装饰性几何形状。
- 信息密度参考导师流程图，节点靠近其关系对象，连线尽可能短、清楚。
- 保留可读性和业务逻辑；紧凑不等于把文字缩到不可读，也不改变原有流程含义。

## 布局规则

1. 优先采用“上层两个并列模块 + 下层一个流程模块”。上层两块等宽、等高；下层通栏模块与上层高度接近，避免明显头重脚轻或下层过高。
2. 模块各自使用顶部彩色标题栏。默认不另加居中总标题或编号式分节标题；若页面需要总标题，应放在图外的报告标题位置，不挤占流程区。
3. 模块内优先沿水平方向排布节点。并行步骤可上下错开少量，但要就近汇合；从一个模块传入另一个模块的连接应走边缘或留白通道，避免穿过节点和标签。
4. 节点使用“图标 + 名称”，不加独立背景卡片。只在需要标明一组节点共同属性、互斥结果或可选范围时，使用少量浅底分区或虚线框。
5. 同类结果分支作为并列节点呈现，不把互斥结果画成先后步骤。分支框应包住结果组，连接线表达从判定到各结果的关系。
6. 允许按实际流程调整模块宽高和节点数；v0.9 示例的 1000×720 画布和模块比例是起点，不是固定模板。

## 图标、文字与颜色

- 复用本项目已确认的局部流程插画图标。当前参照底稿为[工单—合同跨源核验流程 v0.9 SVG](../architecture/跨源事实核验_局部流程示例_v0.9_参考图紧凑重排.svg)，对应的 PNG 用于快速预览。扩展图标时先检查品牌图标集是否已有合适语义；不得把业务图标改造成含义不清的装饰。
- 建议图标约为画布宽度的 5%（v0.9 为 52/1000），名称约 16 px；根据最终报告尺寸做等比调整，并在实际导出尺寸下检查可读性。
- 名称优先使用短语；解释性文字仅在不写会产生歧义时添加，尽量置于模块底部或关系线旁，不要给每个节点都塞说明段。
- 模块沿用蓝、紫、绿作来源/核验分区，浅色作为区域底色，饱和色用于标题栏、连线和重点。v0.9 示例用色：蓝 `#0074d8`、紫 `#991ac7`、绿 `#398900`、异常橙 `#e47c00`；浅底分别为 `#f7fcff`、`#fffaff`、`#f8fff2`。颜色只辅助区分，不单独承担状态含义。
- 标题栏可采用醒目的艺术字或倾斜粗体；节点标签保持清晰的中文黑体。字体随报告导出环境检查，不能依赖本机独有字体而造成替换、溢出或错位。

## 连线与箭头

- 以水平直线和直角折线为主。只有确有分支、汇合或跨模块关系时才转向，不为装饰增加弯折。
- 箭头应从来源边缘出发并触达目标附近，避开图标、文字和模块标题；使用统一线宽、圆端点/圆角连接，以及清楚可见的空心折角箭头头部。
- 可用模块主色区分来源路径，核验主线使用绿色，失败或异常路径可用橙色；每种颜色必须有明确语义，同一张图保持一致。
- 连接线交叉不可避免时，调整节点或布线路径；不要让交叉点落在节点、文字或分组标题上。

## 可编辑文件与交付

- SVG 是主源文件；PNG 是预览和不支持矢量格式时的输出。修改时保留原始 SVG，不以 PNG 反向替代源图。
- 新版本使用独立文件名，不覆盖已确认的历史版本。文件名包含主题、版本和简短变化说明。
- 改图时先确认所有业务节点和分支，再调整位置、图标、颜色和文字密度。除非用户要求改业务逻辑，不因排版而删除节点或改变箭头含义。

## 交付前检查

1. 对照需求逐项核对节点、分支、方向和来源，确认业务逻辑没有被视觉重排改变。
2. 渲染 SVG 为 PNG，在目标展示尺寸目视检查整体平衡、文字可读性、图标一致性、边距、裁切和拥挤处。
3. 检查文字没有出框；连线不穿过文字或图标；箭头方向明确且终点对应正确。
4. 检查分组边界、模块底色和颜色语义一致；互斥状态没有被画成串行流程。
5. 保留 SVG 和 PNG，并在交付说明里给出两者位置。
