# 循证问答前端动效规范与扩展指南

版本：v0.1
更新日期：2026-10-13
适用：Vue 前端首页、问答、证据面板、架构导览与工具记录。

## 1. 已实现的动效

动效延续品牌图标的折面风格：斜向入场、切角揭示、短位移和快速落定。视觉反馈帮助用户理解界面变化，对应交互 Demo 可用性与演示效果；动效本身不证明查询准确性或业务能力。

| 位置 | 行为 | 触发与限制 |
|---|---|---|
| 侧栏主标志 | 斜切亮面掠过 | 指针悬停时播放一次；不循环 |
| 全平台会话栏收起 | 使用单一顶栏折页图标；桌面/平板收窄侧栏轨道，手机抽屉沿水平方向收起 | 各尺寸均通过同一个图标按钮切换；沿用 200 ms 动效，遵循减少动态效果设置 |
| 首页标题与说明 | 斜向短位移、错峰入场 | 首页挂载；最迟约 635 ms 完成（架构节点顺序 7） |
| FEVA 架构卡 | 切角揭示、节点依次出现、连接线展开、活跃节点短脉冲 | 首次显示欢迎页及新建/切换到空白会话时播放一次；首节点立即点亮，随后依次推进；不循环。减少动态效果时直接显示完整状态。属于静态架构导览，不表示实际执行进度 |
| 示例卡与操作按钮 | 图标沿右上方向位移、底部线条展开、按下反馈 | 悬停、键盘焦点及按下；不改变布局尺寸 |
| 架构、指南、评测弹窗 | 遮罩短淡入，内容斜向进入，退出更快 | Vue 内置过渡；退出不接收指针操作 |
| 数据库与库表面板 | 遮罩短淡入，内容斜向进入；焦点进入面板并在关闭后恢复 | 点击侧栏入口打开；可用 Escape 关闭；沿用 `vm-dialog`，减少动态效果时立即显示 |
| 来源证据面板 | 从右侧短位移进入 | 打开时播放；关闭立即释放布局，不延长等待 |
| 回答与引用 | 消息挂载时入场；等待结束后内容短入场 | 不逐字伪造输出、不延迟真实回答 |
| 处理记录与追问建议 | 内容出现时短位移 | 展开或出现时；工具记录来自真实响应 |
| 等待标记 | 单个切角折面短促明暗 | 请求尚未返回时播放；不表示具体工具步骤或完成比例 |
| 等待期实时进度 | 请求处理中按后端阶段事件逐项更新；折面节点短暂揭示，已完成步骤转为核验青绿 | 只呈现真实开始/结束的步骤；模型或数据库等待期间停留在当前步骤，不估算百分比；首个事件到达前只显示等待态 |
| 完成时交接 | 最终回答返回后移除上方动态进度，完整工具调用链由答案下方「查看处理记录」展示 | 实时进度用于等待反馈，处理记录用于事后核验；两者不重复呈现 |

## 2. 唯一参数与实现入口

- `web/src/styles/motion.css`：公共参数、入场关键帧、操作反馈、弹窗过渡。
- `web/src/styles/global.css`：导入公共动效并处理全局减少动态效果。
- `web/src/views/WorkspaceView.vue`：首页序列、品牌扫光、架构连线、移动端会话栏和浮层。
- `web/src/components/AnswerBubble.vue`：切角等待标记与仅在请求处理中显示的真实阶段时间线；完成后的证据记录由 `TraceDrawer.vue` 展示。
- `web/src/stores/conversation.ts`：`progressByMessage` 只在请求处理中暂存阶段事件，完成后清理；完整工具链来自 `AskResponse.trace`。
- `app/progress.py`、`app/main.py`：请求级进度事件与 `/api/ask/stream`；原 `/api/ask` 保持原样。
- `infra/public-demo/login_gateway.py`：公网转发必须逐块转发事件流，不能按大块读取后再刷新。
- `web/src/components/ChatThread.vue`：跟随系统设置选择即时或平滑滚动。
- `web/src/components/TraceDrawer.vue`：处理记录展开。
- `web/src/components/Composer.vue`、`CitationList.vue`：输入、发送和引用反馈。

| CSS 参数 | 当前值 | 用途 |
|---|---|---|
| `--motion-fast` | 120 ms | 按下反馈、退出 |
| `--motion-base` | 200 ms | 面板与详情入场 |
| `--motion-enter` | 320 ms | 首页与内容入场 |
| `--motion-sweep` | 420 ms | 品牌亮面扫过 |
| `--motion-stagger` | 45 ms | 相邻元素错峰间距 |
| `--motion-shift` | 10 px | 默认入场位移 |
| `--motion-hover` | 2 px | 图标悬停位移 |
| `--motion-ease` | `cubic-bezier(.16, 1, .3, 1)` | 快速启动、清晰停住，无弹跳 |
| `--motion-exit-ease` | `cubic-bezier(.4, 0, 1, 1)` | 快速退出 |

公共类：`vm-reveal`（短入场）、`vm-facet-reveal`（切角入场）、`vm-panel`（右侧面板）、`vm-detail`（新增详情）、`vm-press`（按下）、`vm-interact` + `vm-icon-shift`（图标反馈）、`vm-turn`（等待结束后的回答内容）。

问答进度的活跃节点复用 `vm-progress-cut`：小幅水平折面闪动，只在后端报告该步骤仍在执行时播放；步骤完成后停止。阶段列表只追加后端已报告的步骤，状态不通过前端计时器推断。

## 3. 新增模块如何复用

普通内容直接使用公共类，不重新编写一套速度和曲线：

```vue
<article class="vm-reveal" style="--motion-order: 2">新增模块内容</article>
<button class="vm-press vm-interact">
  <AppIcon class="vm-icon-shift" name="arrow" />打开模块
</button>
<div v-if="detailsOpen" class="vm-detail">详情</div>
```

列表用 `:style="{ '--motion-order': Math.min(index, 4) }"` 限制错峰长度，不让长列表最后一项迟迟不出现。回答正文不设置错峰。

新的弹窗沿用 Vue 内置过渡，每个过渡只包含一个根元素，遮罩下直接放 `section`：

```vue
<Teleport to="body">
  <Transition name="vm-dialog">
    <div v-if="open" class="my-backdrop" :inert="!open">
      <section role="dialog" aria-modal="true" aria-labelledby="my-title">
        <h2 id="my-title">模块标题</h2>
        <!-- 保留打开后的焦点定位、Tab 边界与 Escape 关闭逻辑 -->
      </section>
    </div>
  </Transition>
</Teleport>
```

面板若会改变页面网格列数，使用 `vm-panel` 入场即可。不要直接为关闭添加离场过渡，否则元素暂留可能与已恢复的网格列冲突。

## 4. 扩展约束

1. 优先复用公共类和参数，新增独有动作写在所属组件，并在本指南登记触发条件。
2. 优先改变 `transform`、`opacity`；切角揭示仅用于小范围、单次展示。避免动画修改宽高、文字尺寸、整页模糊或重阴影。
3. 不设置 `transition: all`、持续 `will-change`，不引入动画依赖或常驻逐帧脚本。
4. 静态品牌和架构展示不循环，不显示虚构进度、假工具调用或假完成状态。
5. 遵循系统 `prefers-reduced-motion`：关闭动画、错峰和过渡，内容立即可见；聊天滚动改为即时。该设置可在页面打开后切换生效。
6. 动画中按钮可操作，退出的浮层不可点击；保留键盘焦点恢复与窄屏布局。
7. 品牌 SVG 继续引用 `web/public/brand/` 的母版；动效不另画、不改变图标语义。

## 5. 复现检查

在项目根目录的 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'C:\Users\86133\WorkBuddy\多模态数据驱动的可解释精准问数问答智能体\web'
npm.cmd run dev -- --host 127.0.0.1
```

另开 PowerShell，在同一 `web` 目录运行：

```powershell
npm.cmd run build
npm.cmd run test:ui
npm.cmd run test:motion
npm.cmd run test:process
```

开发端口改变时先设置 `$env:UI_BASE_URL = 'http://127.0.0.1:实际端口'`。Windows 默认使用本机 Edge；其他环境可设置 `UI_BROWSER_CHANNEL` 或安装 Playwright 所需浏览器。

`test:motion` 使用受控接口响应，覆盖正常/减少动态效果、亮/暗色桌面及手机六种组合，检查动画是否实际播放或关闭、首页无常驻循环、弹窗焦点恢复、等待可停止、回答与证据可见、页面不横向溢出。结果默认保存在 `agent_temp/motion-check/`，包含检查 JSON 与截图；临时产物不作为业务评测结果。

`test:process` 检查等待期实际阶段、答案完成后移除动态进度、答案下方处理记录仍可展开，并回归左下角数据库预览中的业务表字段和文档索引。结果默认保存在 `agent_temp/process-check/`。问答夹具必须用 `addInitScript` 覆写 `window.fetch` 手动推流；`page.route` 的 `fulfill` 传 `ReadableStream` 会缓冲到流结束，测不到等待中间态。

需要录屏时，安装 Playwright 的录制组件（`npx.cmd playwright install ffmpeg`），再运行 `npm.cmd run test:motion -- --video`；正常亮色桌面的短录屏写入同目录的 `video/`。默认检查不依赖录制组件。

最后在实际浏览器中刷新首页，悬停示例卡并开关架构导览，检查斜切节奏和最终态。在系统开启“减少动态效果”后再检查一次，内容应立即出现。
