# EvoOntology 下一轮实验设计 v0.1 —— 业务知识增强对中级任务 1/4/5 的可信验证

更新日期：2026-10-03。状态：**执行前协议（未执行）**。定位：**评估借鉴**（不引框架、不另起系统、不改正式模块与分工）。本文是上一轮（构建器 + 机制验证）之后的、针对「能否改善具体中级任务」的**可信实验设计**，须经负责人确认后方可执行。

---

## 一、要回答的问题

1. Builder 产出的业务知识资产，**能否改善 A 负责的中级任务 1（要素识别与改写）/ 4（精准表定位）/ 5（多表关联生成）**？
2. 如果有效，**是知识本身有效，还是"呈现方式"（整本注入 vs 按需访问）有效**？

这两问都是**中间环节**的问题，不能用"最终 SQL 对错"回答。这是本设计的出发点。

---

## 二、为什么上一轮回答不了（衔接）

| 上一轮的做法 | 后果 |
|---|---|
| 主指标＝最终 SQL 匹配，且 30 题 A 组已 60/60 | **天花板**：任何提升都无处显示 |
| A 组也已拿到"字段可用性 + 空字段事实" | **对照不干净**：差距被压低 |
| 知识"整本塞进提示词" | 只测了论文自己标负的做法 |
| 出题者＝执行者；30 题×2 轮当样本 | **无独立盲审、无统计检验** |

结论：上一轮是「**测不出**」，不是「**没有**」。本轮逐条针对这四点改造。

---

## 三、可信度五原则（每条都解释"为什么"）

### 原则 1 · 换到"有空间"的战场（消除天花板）
**做法**：把测试场景换到 **A 本来就不满分**的难度——数十表中定位字段（任务 4）、含干扰/近义表的混淆概念、多表关联陷阱。
**为什么可信**：天花板下，任何干预都"看起来无用"，这是**结构性的信息缺失**，不是结论。只有在 A 有余量的地方，才可能观察到差异。

### 原则 2 · 测中间环节指标（不用终点分）
**做法**：每个中级任务用**它自己的量化指标**（见第四节），不共用"SQL 对不对"。
**为什么可信**：知识的作用点在**中间环节**（识别、定位、连接），终点分数会把这些差异淹没、且已被天花板封死。指标直接对应题面定义，才谈得上"证明了任务 X 的改善"。

### 原则 3 · 干净对照（A 不得预先获得任何知识产出）
**做法**：A 臂只给原始结构，**不注入任何**本轮知识、也不给"空字段事实"这类知识副产品；知识只进 B/C 臂。
**为什么可信**：上一轮 A 已获得部分产出，等于**对照组被提前加强**，可归因的差距被系统性缩小。干净对照才能归因。

### 原则 4 · 预注册 + 盲审
**做法**：题目、标准答案、指标、判据、样本量、模型标识、提示模板在**首次求解前冻结并记录 SHA**；**出题 ≠ 执行 ≠ 评分**（至少出题在知识冻结前完成、评分由独立流程执行）；不按结果回头改题目或判据。
**为什么可信**：防"事后调标准"和"出题者偏差"——上一轮"出题者＝执行者"是硬伤，预注册+盲审是最低成本的补救。

### 原则 5 · 足样本 + 统计检验
**做法**：每条件（每任务每臂）**≥ 30 道独立题**；**配对设计**（同一题跨臂）；二分类用 **McNemar 检验**，连续指标用 **配对 bootstrap 95% 置信区间**；报告**效应量 + 区间**，不只报百分比。
**为什么可信**：30 题×2 轮 ≠ 60 个独立样本；没有检验就容易把噪声当结论，也无法说"有无显著差异"。

## 四、实验对象：中级任务 × 指标 × 干预

| 中级任务（题面第 5 页） | 本设计测什么 | 主指标 | 题目构造 | 知识干预变量 |
|---|---|---|---|---|
| **任务 1** 识别并标准化不规范业务要素 | 别名 / 业务编号 / 时间表达 的标准化 | **要素级 精确率 / 召回率 / F1** | 含 AW-Chinook 词义冲突（如"账单地址"vs `invoice`）、业务编号与内部 ID | Terms（概念与别名） |
| **任务 4** 数十张表中精准定位字段 | 概念 → 表 / 字段 的定位 | **候选表召回@k、字段定位 top-1 / top-3 准确率** | AW 80 对象（71 基表＋9 视图，约 607 字段）＋ 新增**干扰表/近义表**（多个含 Amount/Total 的表）；模糊业务概念 | Mappings（概念→字段 / 连接路径） |
| **任务 5** 多表关联路径与生成稳定性 | join path 是否正确、是否重复计数 | **join path 准确率 + 最终结果正确率** | 3 表及以上聚合题，含"看似对但会重复计数"的陷阱 | Mappings（连接路径）＋ Constraints（粒度约束） |
| *任务 3（澄清，**需与 B 协调**）* | 漏澄清 / 过度澄清 | **漏澄清率、过度澄清率** | 前置：项目方先定义"允许默认 / 明确多义 / 已明确可回答" | Constraints（字段可用性） |

**说明**：任务 1/4/5 属 A 的职责范围；任务 3 已移交 B，**本设计不擅自纳入**，仅列为后续可选，需 B 确认后另行设计。

## 五、三臂设计（同时回答"有没有用"与"怎么用才有效"）

| 臂 | 输入 | 回答什么 |
|---|---|---|
| **A** 无知识 | 仅原始结构（干净基线，见原则 3） | 对照基准 |
| **B** 知识整本注入 | A ＋ 全部知识塞进提示词（复刻上一轮做法） | "知识本身"是否有效 |
| **C** 知识按需访问 | A ＋ 只给知识**目录**，需要哪条检索哪条（**进程内实现，不建 MCP 服务**） | "呈现方式"是否有效（论文真正的做法） |

**为什么必须三臂**：只测 B 等于只测论文标负的做法；有了 C 才能区分"知识无用"与"用法不对"。

## 六、题集、规模与隔离

- **独立题数**：每任务每臂 ≥ 30 题；三个任务合计 ≥ 90 题/臂，三臂合计 ≥ 270 次求解（另加 C 臂的检索规划请求）。
- **封存**：题集与标准答案在首次求解前封存（记字节 SHA，注意 CRLF/LF 口径，沿用上一轮做法）。
- **隔离**：出题子流程**只看原始结构、旧题去重信息**，不看知识资产；做题流程不看标准答案；评分由独立流程执行。
- **难度校准（preflight，本轮新增的关键一步）**：先在**小样本**上测 A 臂基线，**确认 A 不满分（有 headroom）**；若 A 仍满分，则加干扰表 / 提难度；仍满分就说明"当前库对该模型无挑战"，这是**该换题库**的信号，而不是"知识无用"。

---

## 七、判据与统计

- **成功判据（先冻结）**：C（或 B）相对 A 的主指标提升，**McNemar / bootstrap 检验达到预设显著水平**（如 p<0.05 或 95%CI 不含 0），且**方向在三个任务上不矛盾**。
- **效应量**：报告提升的绝对百分比 + 95% 置信区间，不只给单点百分比。
- **样本量**：以 preflight 实测的 A 基线为准，按目标可检出效应（如 10 个百分点）估算；若不足则加题，不靠加轮次充数。
- **顺序控制**：同题跨臂顺序**随机化 / 拉丁方**，消除顺序与缓存效应（上一轮 B 恒居中）。

---

## 八、执行步骤与决策门

1. **写预注册冻结清单**（题目、gold、指标、判据、样本量、模型标识、提示、评分口径）→ 记 SHA。
2. **preflight**：小样本测 A 基线，确认有 headroom（无则调难度）。
3. **正式跑三臂**（配对 + 顺序随机化）。
4. **统计**：McNemar / bootstrap，出效应量与区间。
5. **决策门**：仅当干预臂显著优于 A 且方向一致，才考虑接入正式链路；否则**保留为离线可审查资产**，并**如实报告"未观察到显著增益"**——这一次的负结论因有统计效力而**可信**。

---

## 九、成本预算（量级）

- 参照量级：上一轮两线合计约 **1,000 次调用 / 9.3M 词元**。
- 本轮估算：3 任务 × 3 臂 × 30–50 题 ≈ **270–450 次求解**，另加 C 臂检索规划与 preflight；预计 **500–800 次调用**量级，可控。
- 全程记录**词元 / 时延 / 失败重试**，不隐藏无效运行成本。

---

## 十、风险与回退

| 风险 | 应对 |
|---|---|
| A 在该难度仍满分 | 加干扰表 / 换更难概念；仍满分则结论是"题库对该模型无挑战"，非"知识无用" |
| 三臂无差异 | 这是**有统计效力的负结论**，如实报告 |
| C 臂（工具化）实现成本 | 无需 MCP，进程内做一个 browse/resolve 即可，符合"不引重框架" |
| 任务 4 干扰表引入新偏 | 干扰表设计需独立审核，且标准答案可单独重放核验 |

---

## 十一、边界（本轮明确不做）

- **不引 MCP 服务、不做自演化闭环、不做进正式运行时代码、不改正式契约与团队分工**；
- **不做多模态、跨域、文档 RAG**（本轮只测结构化中级任务 1/4/5）；
- **不把结果直接兑换赛事分**：自建题集非官方测试集。
