# 账号系统设计 v0.1

更新日期：2026-10-13

## 目标与边界

公网网页使用个人账号登录。系统不开放自行注册，由管理员创建、停用账号并重置密码。角色分为管理员和普通用户；管理员能管理账号、模型配置、评测与项目证据，普通用户只使用问答、查看来源以及查看数据库连接状态。

## 身份与数据隔离

- 账号密码使用 PBKDF2-HMAC-SHA256 加盐保存；浏览器只持有随机、HttpOnly 会话 Cookie，数据库只保存 Cookie 的 SHA-256 摘要。
- 普通 API 必须有有效会话。评测题集、评测运行、内部证据、数据库结构清单和模型凭据配置仅限管理员。
- 服务端把客户端会话标识加上已认证用户标识后再交给问答编排器；结果集也按这个范围读取，防止改写请求头访问其他人的结果。
- 浏览器会话历史仍保存在浏览器本地，但按账号 ID 使用独立存储键。它不会同步到服务器；这提供应用内的账号分隔，不是对同一浏览器配置文件本地访问者的加密隔离。
- 上线前已有的无账号历史没有可靠的归属信息，因此不自动分配给新账号；原有浏览器键保留，但新版界面不读取它们。
- 账号角色控制管理功能，不改变业务数据库已有的数据授权范围；所有普通用户仍查询同一份演示业务数据和文档语料。若以后接入不同租户的数据，必须另加服务端行级授权。

## 存储与部署

账号数据保存在独立的 SQLite 应用库，默认路径为 Windows `%LOCALAPPDATA%\VeriMind\app\accounts.sqlite3`，可由 `VERIMIND_AUTH_DB_PATH` 覆盖。它不进入 Chinook 或 AdventureWorks 业务库。首个管理员通过 `python -m app.auth_cli create-admin` 交互创建，不配置默认密码。

公网入口从共用演示口令改为纯反向代理，账号认证统一由应用完成。会话 Cookie 默认启用 Secure；仅本机 HTTP 开发时可通过 `VERIMIND_AUTH_COOKIE_SECURE=false` 临时关闭。管理员应使用 HTTPS 入口。

存储方案比较：独立 SQLite 文件不增加依赖、与问答业务库解耦，适合当前单机演示，因此作为当前实现；独立 PostgreSQL 应用库更适合多实例和集中备份，规模扩大时迁移；把账号表塞进 Chinook 虽可少建一个库，但会混合演示业务数据与身份管理，故不采用。
