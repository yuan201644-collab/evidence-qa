## 〇、一句话

KAG 线现在缺的不是「再跑一批题」，而是一个**只属于图谱、且项目评分表真正在意的能力**：把「结论—关系—原文」钉在一起。下一步应停止用 KAG 去换答案正确率，改用它产出**可逐条核验的证据链**；用一次预注册的对照实验决定「保留为可选」还是「收口归档」。

## 一、复盘：三个硬事实与一个未分离的变量

| # | 事实 | 证据 | 含义 |
|---|---|---|---|
| 1 | **材料召回优势真实，但不转化** | Stage 5（96 文档 / 24 题）：三份必要文档都进上下文，KAG 22/24、项目多跳 RAG 14/24；但答案关键词命中 15/24 vs 21/24，平均耗时约 53 s vs 12 s。Stage 8（3 题 ×3 轮）：两臂上下文都 9/9 齐，完整引用 KAG 仅 3/9，平均 29 份来源、上下文精确率 10.82% | 找到 ≠ 用对。KAG 的增量停在「文本窗口」，没有走到「结论」 |
| 2 | **作为默认路径、自动触发路径，均已证伪** | Stage B v5（36 题同题盲审）：项目 RAG 35/36，RAG+KAG 向量 32/36，RAG+KAG 图谱+向量 26/36，KAG 两臂无独有完整成功；Stage 14 缺口触发：14/18 vs 14/18，1 题补救、1 题退步 | 不是实现细节没调好，是「多给候选」这件事本身在降低信噪比 |
| 3 | **唯一正信号来自「用户可选 + 换了提示与重排」，且 KAG 的独立贡献没有被分离** | 10-15（20 题单轮）：标准 RAG 9/20、深度提示消融（关 KAG）7/20、深度+KAG 12/20；p=0.375 / 0.125；KAG 独有找回的标准文档 **0/33**；精确章节命中 16/20 → 13/20 | 12 分里有多少是提示与重排、多少是 KAG，说不清；而章节命中在退 |

再补一条**测量前置条件**：提示消融与标准 RAG 的最终上下文 20/20 完全相同，分数却差 2 题，其中一题耗时 166 s。这说明在测出 run-to-run 噪声底之前，**±3 题的差异不应被解释为效果**。过去几轮之所以反复「有希望—又落空」，一部分原因就在这里。

## 二、问题重定义

过去的问法：**KAG 能不能让答案更对？**
三次独立实验的回答都是：没有稳定证据，且代价明确（慢、噪声、引用变粗）。

改成：**KAG 能不能让每条结论都有出处，并且出处能被逐条核验？**

三个理由：

1. 项目的评分与卖点是可解释、可溯源，引用链是硬指标而不是加分项；10-15 的记录里，标准 RAG 的章节命中 16/20，深度路径掉到 13/20——**这是唯一一处 KAG 让核心指标变差的地方，也恰好是项目最在意的地方**。
2. 图谱的结构（实体—关系—实体，理想情况下每条边有原文 span）天然适合表达「跳」，文本检索天然不适合。KAG 的强项正好落在 RAG 的弱项上：Stage 5 完整引用 3/30、Stage 8 3/9、Stage 6 0/12。
3. 换指标就不与 RAG 抢同一条赛道：RAG 负责「答得出」，KAG 负责「说得清」。这样即使 KAG 不提升答案分，也有独立价值可测。

## 三、三条可选路线

| 路线 | 主张 | 成本 | 风险 | 评价 |
|---|---|---|---|---|
| **R1 收口** | 冻结实验，把 KAG 写成设计报告里的方法论述与负结果 | 最低（2–3 人日） | 放弃已有资产；决赛少一个差异化点 | 兜底，不作为首选 |
| **R2 证据链（推荐）** | KAG 只当建图器，产出「链 + span」，做引用台账 | 中（约 3 周，见第五节） | 依赖抽取质量与新语料 | **推荐**，唯一能产出新能力的方向 |
| **R3 引用核验器** | 不改检索，只用图谱核验「答案里的每个断言是否有路径与原文支持」 | 低–中 | 不解决召回；需 KAG 在线，慢 | 作为 R2 的度量件，不单独成立 |

推荐 **R2，并把 R3 作为 R2 的度量件**：R3 既是产品功能，也是这次实验的自动指标来源——一次投入，两处使用。

## 四、方案 v2：KAG 当建图器，不当检索器

### 4.1 核心改动

现行深度路径每次在线调用 KAG solver：单次约 23 s（P95 33.6 s），返回整页文本，跨轮结果不稳定（同一 KB-001 问题一次返回、一次不返回，见接入记录 v0.2 §3）。而建库时**已经抽出了带原文位置的三元组**（15 份文档、103 个切片、388 条语义关系；构建检查点审计脚本已能直接读出每份文档的节点/边数）。

因此 v2 把两件事拆开：

- **建库期**：KAG 负责抽取，额外导出 `triples.jsonl`（subject, predicate, object, doc_id, char_start, char_end, quote）。
- **查询期**：不再调用 KAG solver，改为在本地三元组索引上做实体链接 + 有界路径搜索（深度 ≤3），返回「链」。

三个直接收益：**确定性**（无 LLM 规划，可复现）、**快**（毫秒级，不再是 23 s）、**可审计**（每条边都有原文坐标，可回切校验）。

### 4.2 数据流

```
建库（一次性）
  文档 → KAG builder → 三元组 + 源文 span → triples.jsonl → 本地图索引
                                                        │
查询（每次）                                            ▼
  问题 → 实体约束（合同号 / 供应商 / 文档标题）
        → 种子节点 → 深度≤3 路径搜索 → 链（节点, 边, span）
        → CandidateEvidence(relation_path=[...])
        → 与 RAG 候选联合重排（文本分 + 链覆盖加分）
        → 项目生成器 → 引用台账（claim → chain → spans）
```

### 4.3 代码落点（接口已就位，不用改契约）

- `app/evidence_supplement.py:126` 的 `RelationEdge`（subject / predicate / object / source，其中 `RelationSource` 自带 `document_id`、`locator`、`canonical_char_start/end`、`quote`）与 `:157` 的 `CandidateEvidence.relation_path` **已经在契约里，且已被校验逻辑使用**（`:277`、`:331`）；但 `app/kag_supplement.py` **从未填充过它**。这是现成的空槽。
- 新增 `app/kag_graph.py`：三元组加载、实体链接（复用题面里的合同号/供应商/书名号文档名）、有界 BFS、链去重与排序。
- `app/tools/doc_search.py:_answer_deep`：把 `kag_supplement` 步骤替换为 `graph_chain`（或并列，便于 A/B），候选仍走 `validate_and_convert` 的文档身份与坐标校验，不合格一律拒绝，不伪造坐标。
- 生成侧：`generate(question, context_hits, require_chain=True)` 已有链式提示，v2 追加「按台账输出、每条断言挂一个链编号」的约束，并在生成后做确定性校验（链编号存在、span 存在、金额/编号在 span 内可检索）。
- 引用粒度：现行 KAG 候选是整页文本，回切后是一个大区间，导致章节锚点变粗。v2 在建库导出时就把三元组按**段落**存储，候选直接是段落级 span；无法唯一定位的候选标记 `coarse` 并降权，不再默认进引用。

## 六、实验协议（先冻结，再跑）

### 6.1 语料（硬要求）

- **第二个真实业务域**，≥40 份文档，未参与任何 KAG 调参或提示调试。
- 必须包含：跨文档关系（合同↔承诺函↔验收单）、相邻/干扰文档（同项目不同标包、更正公告）、版本与冲突（新旧版本条款不一致）。
- **拿不到就跳过 P2**（见第八节），不要在 15 份受控语料上再跑一轮——那是选择偏差，10-08 的综合判断已经点过。

### 6.2 题集（30–40 题，先冻结题目与必要事实，不写答案）

| 类型 | 数量 | 要测的能力 |
|---|---|---|
| 三跳链 | 12 | 链路完整性、逐跳引用 |
| 相邻/干扰 | 10 | 作用域消歧（合同号→供应商→附件） |
| 冲突/版本 | 8 | 冲突识别与来源优先级 |
| 不可答 | 5 | 拒答、不编造 |

每题预注册：必要事实列表、必要文档列表、禁答项、可接受引用粒度（条款级 / 段落级）。

### 6.3 四个比较臂（缺一不可）

| 臂 | 配置 | 作用 |
|---|---|---|
| A | 标准 RAG | 基线 |
| B | 深度提示 + 联合重排，**关闭 KAG** | 分离提示与重排效应；没有这一臂，上一轮的 12/20 无法归因 |
| C | 现行深度 + KAG 在线候选 | 证明 v2 相对旧法是否真的更好 |
| D | v2 链式取证 + 台账 | 待验证方案 |

每条臂每题重复 3 次；主指标取逐题多数，稳定性用翻转率。

### 6.4 指标

**主指标**：① 引用逐条支持率（claim 级：每条断言是否有 span 且语义支持）② 三跳链路完整率 ③ 事实有据率 ④ 答案完整率。
**次指标**：必要来源召回、上下文精确率、超时率、p50/p95 耗时。

### 6.5 统计与盲审

- n=30 时，McNemar 双侧要达到 **9:1** 才 p<0.05（8:1 为 0.039，9:1 为 0.022）。所以主判据用**实用阈值 + bootstrap 置信区间**，不追 p 值；能把题量做到 45–50 再报显著性。
- 盲审：Phase A 先由未看过结果的人冻结事实与必要来源，再解盲；抽 40 条校验自动台账指标，与人工一致率 ≥85%（或 kappa ≥0.7）才允许用自动分做主判据。

## 七、判据（预注册，跑前写死）

**Go（四条全满足）**

1. D 对 B：在「引用完整且事实有据」上 **≥8 胜 ≤2 负**（30 题，逐题多数）
2. D 的必要来源召回 ≥ B，上下文精确率比 B 高 ≥10 个百分点
3. p95 端到端 ≤ 90 s，超时率 ≤ 5%
4. 台账抽检与人工一致率 ≥ 85%

**No-Go**：任一条不满足 → 冻结，不再调参重跑，写「检索不是瓶颈、引用才是」的负结果，KAG 转 R1。

> 写死判据的意义：过去几轮反复出现「这次有希望」，但每次都在同一批题上换配置。预注册是唯一能防止事后择优的办法。

## 九、无论成败都有产出

- **正结果**：一个只属于图谱的差异化能力——可核验的引用链；决赛演示可以现场展开「A—关系→B—关系→C」并点回原文。
- **负结果**：一条完整的工程叙事——「我们验证了图谱补检索不成立，把瓶颈从召回定位到引用」，同时给出为什么不做默认路径。这在评审眼里同样是证据链，而不是失败。
- 两种结果都能回答同一个问题：**为什么 KAG 不设默认路径**。
