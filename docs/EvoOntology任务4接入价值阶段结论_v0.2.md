# EvoOntology 是否值得接入项目：阶段结论 v0.2

日期：2026-10-04。决策范围：本项目当前的任务4结构定位和 NL2SQL 主链路；本结论不是赛事得分或生产环境保证。

## 当前判断

**暂不把完整 EvoOntology 按需方案接入项目主链路。** 新的独立题上，按需方案显著提高了表/字段定位召回，但有效题上的端到端 SQL 结果正确率没有提高，点估计反而低 6.25 个百分点；它还把中位响应时间提高到约 2.6 倍、模型调用数提高到 2 倍。词元数下降是实际优势，但现有证据不足以证明它值得用更慢的响应和额外请求换取，尤其没有显示问数答案更准确。

这里的“暂不接入”是工程决策，不是断言 EvoOntology 无效。结果题只有 24 道，区间仍允许一定的正负效果；当前结论限定于此题集、模型服务、知识快照和数据库版本。

## 两个评测层次

| 指标 | A：全量结构、无知识 | C：检索知识并裁剪结构 | 差异及解释 |
|---|---:|---:|---|
| 独立题表/字段定位召回（28 题，每题一次） | 62.76% | 89.29% | C−A **+26.53 个百分点**；题级配对 95% bootstrap 区间 [+3.57,+47.96]。达到这轮预先写下的“定位收益方向”门槛。 |
| 端到端 SQL 结果集正确率（Gold 审计为有效的 24 题，每题每臂两次） | 43/48（89.58%） | 40/48（83.33%） | C−A **−6.25 个百分点**；题级配对 95% bootstrap 区间 [−20.83,+6.25]。不能据此证明改善。 |
| 全有效题模型词元数 | 404,743 | 146,395 | C 少 **63.8%**；规划和 SQL 调用都计入 C。 |
| 模型请求次数 | 48 | 96 | C 是 2 倍。 |
| 中位端到端延迟 | 1.83 秒 | 4.78 秒 | C 是 2.61 倍；平均延迟约 2.79 倍。 |
| SQL 通过只读校验并执行 | A/C 均 48/48 | A/C 均 48/48 | 本题集没有执行拒绝或运行错误；不代表生产安全评估已完成。 |

定位提升没有转化成答案正确率收益。SQL 中反解析字段覆盖率 C−A 是 +5.04 个百分点，但这仍是中间代理指标；正确答案看的是查询结果是否与 Gold 一致。词元下降也不能替代响应时延和答案正确性。

上一轮 v0.3d 在旧 32 题上 C−A 字段召回差为 −1.17 个百分点，95% 区间 [−23.05,+20.70]；新独立 28 题的定位差为 +26.53 个百分点。方向变化提示效果受题目类型影响，不能只挑有利题集报告。

## 可信度：哪些可以说，哪些不能说

- **题集来源：** 独立编题者在查看先前模型结果前制作新题，候选题 SHA-256 为 `01ab76effa0232036466fc9e20bd809b6860e11345e3939f95bab559505950c7`；初始 28 条 Gold 见证 SQL 全部在固定数据库只读执行成功且非空。数据库为 AdventureWorks PostgreSQL 镜像，镜像摘要 `sha256:07e46e828d40cb2ce728025662aae68c289a811244fd9297d189a7c42c3598f5`，运行期另记录 80 个结构对象的数据指纹。
- **盲审：** 运行结果可见前，一名审阅者仅按 `id/question/validation_sql` 独立检查排序语义和题面—SQL 语义；第二名全新审阅者按同样的字段白名单做完整语义审计，明确未查看模型结果、报告和 run 目录。后者判为 24 条有效、4 条不确定、0 条明确无效。H07 日期边界、H14“分类”是否允许重叠、H26 输出粒度/日期字段、H28 是逐日还是年度汇总均存在题面或验证口径歧义。有效题敏感性分析仅包含 24 条 valid；原始 112 条 A/C 模型记录完整保留。
- **H21 边界敏感性：** 两名结果盲审者把“按门店汇总顾客订单小计、显示门店名”判为有效。另一位在看到运行结果后指出 Gold 按 StoreID 分组、模型输出多按 Name 分组，Gold 635 行而 A/C 预测主要为 633 行；这可能是同名门店被合并，也可能是题目未明确门店唯一标识导致的边界争议。主分析遵从事前盲审语义标签而保留 H21；只作敏感性查看时再排除 H21，C−A 点差变为 −8.70 个百分点，95% 区间 [−23.91,+2.17]。该排除是结果揭盲后的敏感性检查，不能替代主分析。
- **事后修订必须披露：** SQL 调用完成后，首个结果集评分器被发现有两处缺陷：没有把按列名保存的行记录还原成数值序列；把 Gold 为稳定展示加入的 `ORDER BY` 当成题面排序要求。首个全失败结果原样保留为 `result_equivalence_report_invalid_order_rule.json`，不作为性能证据。修复后又按盲审确定的题意规则复算；由于这些规则是在看到模型结果后制定，所有 SQL 正确率及有效题子集统计均标为**事后探索性分析**，不能称作预注册确认性结果，也不能隐藏这段修订历史。
- **重复和统计：** 每题每臂运行两次，共 A/C 112 条原始记录、168 个已完成模型请求；所有词元使用记录完整。统计先在每题内部对两次运行求平均，再以问题为单位做配对 bootstrap；`N=24` 是问题数，不是调用数或结果行数。temperature=0 不保证服务端确定性，模型服务没有提供可锁定权重版本的证据。
- **范围：** 只测本题集、AdventureWorks、DeepSeek-V4.1-Flash 公开模型名/当前端点和当前知识快照。不测文档侧检索、不测全部中级任务、不足以推断比赛评分或真实业务表现。

## 导师追问时的简答

可以这样说明：**“我们分开测了定位和最终答案。新题上 EvoOntology 的字段定位召回提高约 26.5 个百分点，但在经盲审确认有效的 24 道题上，SQL 结果正确率没有提高，点估计低 6.25 个百分点，区间也较宽。它省了约 63.8% 词元，但中位耗时约 2.6 倍、调用次数翻倍。因此现在不建议接入主链路；我们把结果定为探索性，公开了 Gold 盲审、原始调用、哈希和评分口径修订，不把中间定位指标包装成答案准确率。”**

如果导师问为什么还要谨慎：SQL 实验是在定位结果揭盲后设计的后续试验；评分器第一次实现有误，Gold 审计又识别出 4 个含糊题。我们完整保留原始运行，依据独立、结果盲审的 24 题子集复算，所以本结论足以支持“目前不接入”，但还不足以宣称“任何场景都没有收益”。

## 下一步

不做主链路接入。若仍需争取导师给的方向，先把 H07/H14/H26/H28 题面和 Gold 消歧，再冻结至少约 120 道全新、分层覆盖的配对题，只比较最终 SQL 答案正确率和端到端延迟，并把“仅加业务知识”“仅裁剪 Schema”和完整 C 分臂。粗略正态估算中，用 28 题全部差值标准差约 0.383 得到检测 +10 个百分点需约 116 题；仅用盲审有效的 24 题，差值标准差约 0.340，得到约 91 题。两者都来自很小的 pilot，差异本身说明样本量估算不稳定；正式复验前需重新做分层功效设计，不能把 120 当作通用统计保证。只有全新确认性题集的准确率差达到预设实际门槛且区间下界大于零，同时延迟可接受，才考虑隔离试接。
