# EvoOntology 任务4独立确认实验方案 v0.1

日期：2026-10-04。状态：可行性审查后未启动确认运行；候选题未冻结，未对候选题调用模型。本方案保留为后续重启的预注册设计，当前决策见 [最终接入价值结论 v0.1](EvoOntology最终接入价值实验结论_v0.1.md)。

## 本轮执行状态

已完成独立候选题构造、数据库可执行性检查和净化输入的语义盲审。25 道候选题中，盲审最终判为 16 道有效、7 道存疑、2 道无效近重复；其中可明确保留的新 covered 题约 10 道，远低于本方案的 80 道目标。为避免把低功效的小样本包装成确认性结论，本轮没有冻结候选题，也没有发起模型调用。候选题和审计记录仅作可行性评估材料，不纳入任何准确率比较。

因此本方案的统计门槛、条件定义和停止规则仍是未来重启时的预注册草案；若重新启动，应先取得足量、独立且通过盲审的 covered 题，并重新冻结所有材料。当前接入判断与各轮实验结果见上述最终结论报告。

## 要回答的问题

探索试跑显示，整包知识对总体 SQL 正确率的题级差异只有 +2.9 个百分点，95% 区间为 −2.9 至 +8.6；知识覆盖题为 +10 个百分点，但只有 10 题。整包提示同时增加 63.6% 词元和 22.6% 中位延迟。当前证据既不能支持接入，也不能证明知识没有价值。

本轮只确认一个核心问题：对 Builder 知识明确覆盖的任务，直接加入当前 16 条知识，能否带来稳定且有工程意义的最终 SQL 正确率提升；同时观察未覆盖任务是否有负迁移。所有试跑题永久排除。

## 预注册设计

| 条件 | 输入 |
|---|---|
| A | 完整 AdventureWorks schema，不提供 Builder 知识 |
| B | 与 A 同一完整 schema，加入冻结的 `verified-v0.1` 16 条知识及字段集 `id/title/aliases/tables/description/mapping/constraints` |

两个条件使用同一问题、模型端点、生成器、系统提示、输出契约、数据库快照、重试策略和只读执行器。唯一计划差异是 B 增加整包知识。每题每臂两次独立请求；重复先在题内平均。Gold 和错误变体不进入模型提示。臂顺序预先确定并按题交错。

### 题组目标与来源

- 目标确认集：80 道 covered 题 + 40 道 uncovered 控制题；如果高质量独立题不足，保留实际可用数并下调结论范围，不用同义改写凑数。
- covered 题按 16 条知识条目分层构造，尽量每个条目有 5 个不同问题意图；不得仅替换年份、名称或输出别名。题目是明确针对已覆盖能力的工程测试，不能宣称代表自然流量。
- uncovered 题仅由 schema 和历史公开题出题者构造，不让其读取知识包或知识覆盖标签；用来监测整包注入是否损伤不相关任务。
- 独立盲审者只看候选题、Gold、schema 和旧 sealed/Builder 题，不看知识包、数据库校验、模型输出；逐题检查语义、粒度、实体标识、日期边界、NULL、连接倍增、列名和近重复。另由不看模型结果的知识审阅者对 covered 题核对其知识条目及概念簇。
- 盲审通过后才执行只读 SQL 检查：所有 Gold 可执行且非空；输出别名与契约一致；预设错误变体可执行并产生可区分结果。不可区分题修题或删除，并重新冻结；不得查看运行结果后挑题。

若达到 120 道题，计划生成调用为 480 次（120 × 2 臂 × 2 次），重试额外计入且保留。运行器必须对照冻结清单核验覆盖率，失败记录不得删去或静默补跑。

### 指标与统计

- 主指标：covered 层的最终 SQL 答案正确率差 B−A。通过需要值与输出列契约同时正确；列顺序、NULL、重复行、题目要求的排序按冻结评分器严格处理。
- 有工程意义的最小增益预设为 **+10 个百分点**；这是本项目本次工程决策门槛，不是赛题评分规则。
- 主统计单位为问题，不是模型调用；题级差值以两次重复在臂内平均后计算。报告配对区间、B-only/A-only/平局题数。另按 16 个知识条目报告等权条目均值与条目簇区间，检查收益是否集中在少数概念；不把同一概念下的多道题当成完全独立的概念证据。
- 确认标准：covered 层 B−A 点估计至少 +10 个百分点，且题级配对 95% 区间下界大于 0；同时披露按知识条目聚类的敏感性结果。题级与知识条目簇结果方向冲突或簇区间很宽时，判为证据不足，不用题级区间单独宣称普遍有效。
- uncovered 层单独报告差异及区间，作为负迁移监测；40 题不足以排除小幅损害，不据此宣称安全等效。
- 同时报 SQL 语义正确、输出契约正确、端到端正确，完整词元、每题模型调用、延迟、重试、请求失败、长度截断和用量记录完整性。分层抽样题组不计算伪装成真实项目流量的总体准确率。

### 样本量依据与局限

试跑 covered 题级标准差约 0.211，但 n=10 且非平局仅两题，plug-in 功效估计很不稳定。若真实 covered 题差值标准差约 0.30，正态配对近似下检测 +10 个百分点、双侧 0.05、80% 功效约需 71 道题；因此目标取 80。标准差若为 0.40，则约需 126 道 covered 题，80 题不够。此计划不是保证功效的承诺；最终按盲审后实际题数和簇结构报告可检出范围。若覆盖概念簇太少或有效题数不足，结果只能视为方向性证据。

### 接入决策门

1. 若 covered 确认标准未达到，或区间仍宽到同时容纳无效应与有意义增益：当前不接入整包知识，报告证据不足；停止机制消融，避免继续用高调用量寻找显著结果。
2. 若 covered 确认标准达到：结论限定为“知识覆盖范围内直接注入有最终 SQL 收益”。结合词元、延迟及 uncovered 结果，**仍不直接接入整包**；进入新题集上的按需机制确认。
3. 按需机制阶段另建独立题组，再比较 A（全结构无知识）、B（全结构整包知识）、D（全结构按需检索知识）、E（独立裁剪结构无知识）、C（按需检索知识并裁剪结构）。D−A 估计检索知识的作用，E−A 估计裁剪结构的作用，C−A 估计整套按需流程。规划器、检索、最终生成的所有调用和成本都计入；不把 C−A 单独归因于本体知识。
4. 若按需方案在新题上保留 covered 收益、未覆盖题无明显回退且总调用/词元/延迟优于整包方案，才建议把相应知识检索环节接入项目；否则结论为暂缓或仅人工维护知识，不动正式主链路。
