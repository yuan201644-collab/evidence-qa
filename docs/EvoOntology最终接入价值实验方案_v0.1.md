# EvoOntology 最终接入价值实验方案 v0.1

日期：2026-10-04。状态：执行方案草案，模型调用前须冻结题集、答案契约与评分脚本。本方案只针对赛题八中级任务 4 的复杂表结构定位及其对最终 SQL 的作用，不代表赛事评分规则。

## 研究目标

判断当前 Builder 构建的 16 条已验证业务知识，是否能在 AdventureWorks 复杂表结构上改善最终问答 SQL；若知识有用，再判断整包提示、按需检索及结构裁剪中哪种用法值得接入。最终决策是“接入哪一部分、暂缓，或证据不足”。

## 当前证据与主要风险

- 旧 32 题静态定位中，整包知识 B 高于 A；新独立题 28 题中，按需方案 C 的字段召回高于 A。但定位指标不等于答案正确率。
- 旧端到端 SQL 有 28 题、每题每臂两次。评分器曾因行对象读取和排序规则产生 112/112 假失败，后续修正属于事后分析。
- 对审定为有效的 24 题，严格结果集评分 A 为 43/48、C 为 40/48。该差异区间较宽，不能据此确认 C 更差或更好。
- 静态数据库结果相同仍可能掩盖业务 SQL 错误：旧 H09 中 A 使用了错误的日期字段，但在当前快照恰好返回相同结果。
- 严格列数也会把合理的附加标识列或姓名合并形式判错。是否允许取决于题面输出要求，必须逐题预先写清。

## 阶段 0：离线评分校准，不调用模型

1. 为新题定义机器可读答案契约：要回答的字段及其含义、要求的输出列、允许的等价列表达、是否允许额外标识列、统计粒度、连接和去重规则、时间字段与边界、空值规则、排序要求及数值容差。
2. 准备不少于 12 个已知正确或错误的评分样例，逐一标明预期判定。必须覆盖：仅列顺序不同；无排序要求时仅行序不同；允许的别名或姓名形式；不允许的多余列；错误日期字段；漏掉小数秒边界；连接造成重复计数；`COUNT(*)` 与实体去重计数；`INNER JOIN` 丢失应保留的零值组；同名实体分组；日粒度与年汇总混淆；数值精度边界。
3. 对业务语义样例构造最小反例数据，使正确 SQL 与错误 SQL 至少在一例产生不同结果。若固定 AdventureWorks 快照上无法区分，必须标记为需人工审查，不能仅凭当前结果相同计为逻辑正确。
4. 独立审阅者在看不到 A/B/C 预测的条件下检查样例和题目契约。评分脚本须对所有校准样例全判对，且错误 SQL 对照检查通过，才冻结评分器、契约、题集和校验代码的 SHA-256。

校准失败就修评分规则或题目，不运行新的模型对照；保留每次校准版本及失败案例。

## 阶段 1：建立新的配对题集

准备 40 道独立试跑题，分为 5 类、每类 8 题：相近表字段、跨表关联、业务公式、时间边界、实体身份及分组粒度。题目必须来自真实 schema，Gold 查询只用于运行后评分，绝不进入模型提示。对比每一道题与历史任务4题以及 Builder 的构建开发题（`eval/reports/run-builder-20261003T083145Z/construction_questions.json`），按业务意图与查询模板去重，不能只换年份或实体名。知识覆盖层和邻近未覆盖层都要取样并分别报告。

每题先通过以下检查：题意单一明确；答案非空且有区分度；标准 SQL 只读且独立复核；输出列与题面吻合；涉及混淆字段时，专门验证常见错误字段在固定数据或最小反例上能被区分；不同题不重复考同一模板。按构题、盲审、运行和评分职责分离记录人员/智能体身份与可见材料。

固定模型公开标识、端点和请求参数、提示模板、知识文件哈希、数据库镜像和数据指纹、归一化时间锚、重试规则、并发度、随机化种子和评分规则。先检查 A/B 的实际完整提示：B 不得截断 schema 或挤掉共同指令；若上下文超限，暂停并修设计，不能把截断影响误称知识收益。若服务端权重版本不可锁定，如实记录这一边界。

## 阶段 2：A/B 探索实验，回答“知识本身有没有用”

| 条件 | Schema 输入 | 业务知识 | 检索/裁剪 |
|---|---|---|---|
| A 基线 | 完整 AdventureWorks schema | 无 | 无 |
| B 整包知识 | 与 A 完全相同 | 冻结的 16 条 verified knowledge | 无 |

同一题分别进入 A、B；每题每臂运行两次。题目内臂顺序随机交错，固定随机种子。所有请求、重试、失败和完整词元均计入；解析失败、安全拒绝、执行失败按失败保留，不删除、不补题。

40 题共 160 次 SQL 生成调用起步（重试另计）。主指标为题级最终答案正确率；以问题为独立单位，将每题两次运行先在臂内平均，再计算配对差和题级 bootstrap 95% 区间。同步报告表/字段召回、输出契约通过率、只读安全失败、词元、端到端延迟和知识覆盖/未覆盖题分层结果。不得把重复调用当作独立样本。

40 题仅定位为试跑集：可用于发现程序问题、估计 A/B 题级配对差异波动并规划确认样本量；若依据试跑结果改提示、题目、评分或知识包，这 40 题永久排除在确认分析之外。无论结果如何，都不单独声称“稳定有效”。

## 阶段 3：A/B 独立确认实验

用与试跑题不重叠的新题，并冻结评分契约、知识包和程序后再运行。确认题数根据试跑集 A/B 配对差异估算，以双侧显著性 0.05、功效 80%、最小实际收益 5 个百分点为暂定规划目标；同时给出功效分析对小样本配对差异估计不稳定的敏感性范围。若估计题数不可承受，应报告证据不足，不降低门槛或反复窥看中途显著性。五个百分点是本次工程决策门槛，不是题面规定或官方分数线。

主判据预先定为：B−A 最终 SQL 答案正确率点估计至少 +5 个百分点，且配对 95% 区间下界大于 0。错误语义 SQL 必须由逐题契约、最小反例和/或盲审捕获；数据库单快照执行结果一致不能单独证明业务逻辑正确。答案通过率、延迟、模型请求数和词元同时呈现；性能代价单独作为接入决策条件，不折算成比赛分数。

## 阶段 4：仅在知识有效时测试 C 的使用方式

在新的配对题集上比较：A；B（完整 schema＋整包知识）；D（完整 schema＋按需检索知识）；E（独立选表、无知识）；C（按需知识＋独立选表）。E 的选表不得借用暴露知识后的 C 规划结果。规划、检索和 SQL 生成所有请求均计入延迟、词元、调用数和失败率。

这一阶段拆分知识检索和 schema 裁剪的单独及组合效果。一次对比若样本不足或区间过宽，就只作机制线索；选出候选方案后再用未见题独立确认，不能把消融题直接当确认题。

## 最终接入决策

- B 达到确认判据且成本符合项目要求：建议先接入经过证据审核的知识增强，并在隔离分支回归正式项目评测集。
- D/C 达到确认判据并优于 B 的实际取舍：只建议接入经确认的按需组件；保留完整 trace 和知识来源。
- 只有部分题型有效：限定到这些概念或问题类型，报告适用边界。
- 区间覆盖无效应与有意义收益，或准确率收益不足以抵消明显时延/维护代价：结论为“证据不足”或“当前不值得接入”，按预设规则区分。

最终报告须附题集与评分冻结清单、审计者职责和盲法、完整原始记录、版本哈希、失败清单、每题配对结果、置信区间、调用/词元/时延、校准样例结果、题目歧义及所有事后偏离。旧实验只作历史背景，不与新确认实验合并计算。
