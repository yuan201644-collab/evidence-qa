# 知证 VeriMind 品牌与技术命名

更新日期：2026-10-12  
状态：项目采用的展示名称；对应能力以当前代码和实验状态为准。

## 产品与架构

| 层级 | 展示名称 | 含义与使用范围 |
|---|---|---|
| 产品 | 知证 VeriMind | 项目面向用户和评审的产品名称；“知证”强调答案能回到可核验来源。 |
| 整体架构 | 事实—证据核验架构（FEVA，Fact–Evidence Verification Architecture） | 组织事实依赖、数据与文档取证、关系及口径核验、证据记录和有界处理的架构叙事。它是本项目对现有机制的命名，不代表行业已有标准或独立算法。 |

## 核心机制

| 名称 | 对应机制 | 当前实现范围 |
|---|---|---|
| 事实流（FactFlow） | 将复合问题表示为待回答事实及其依赖，按依赖顺序执行。 | `app/fact_planner.py`、`app/fact_executor.py`；当前专用跨源流程覆盖工单—合同场景。 |
| 跨源证桥（SourceBridge） | 依据稳定标识、受控映射、客户范围和有效期检查不同来源中的对象是否对应。 | `app/cross_source_fact_plan.py`、`app/tools/cross_source_policy.py`；名称相似只生成候选，不能单独证明对象相同。 |
| 口径对齐（MetricAlign） | 在比较前核对事实定义、事件类型、时间端点、时区、单位及适用条件。 | `app/cross_source_fact_plan.py` 中的事件、合同条款与时限核验；当前以工单—合同规则为主。 |
| 证据账本（EvidenceLedger） | 记录事实状态及其来源关联，区分候选、支持、冲突、不足和歧义。 | `app/evidence_ledger.py`；是内部核验记录，不等同于完整的通用知识图谱。 |
| 有界求证（BoundedVerify） | 对补查、重试和依赖任务设置边界；前置条件不成立时停止后续依赖执行。 | 编排器及事实执行器中的预算、失败和早停处理；CS18 复核仍记录过部分多合同题晚停，相关边界继续跟踪。 |

## 问答能力名称

| 名称 | 用户可理解的能力 | 状态 |
|---|---|---|
| 文证透镜（DocLens） | 文档解析、章节切片、混合检索、重排和原文引用定位。 | 文档问答主线能力；各文档形态仍按测试结果确认覆盖范围。 |
| 查询卫士（QueryGuard） | 数据库查询中的表字段定位、关联检查、SQL 只读校验与执行。 | NL2SQL 主线能力；具体通过情况以同版题集验收为准。 |
| KAG增强路线 | 在 RAG 出现跨文档关系或证据缺口时，研究是否按需补充图谱检索。 | KAG 研究支线；真实图谱尚未接入项目默认问答链路。原名“缺口补图（Gap2Graph）”，2026-10-12 起对外统一用现名；图标文件仍为 `web/public/brand/icons/gap2graph.svg`。 |

## 展示规则

1. 首次出现时使用“中文名称（English name）”；产品标识写作“知证 VeriMind”，整体架构写作“事实—证据核验架构（FEVA）”。
2. 对外介绍名称时同时说明它对应的实际机制，不把命名本身当作创新或实验结论。
3. FactFlow、SourceBridge、MetricAlign、EvidenceLedger 和 BoundedVerify 只描述当前专用跨源核验能力的组成。不得据此宣称任意业务场景都能自动完成事实分解与融合。
4. KAG增强路线始终标注为 KAG 研究支线，除非真实工具接入默认作答链路并通过相应验收。改名不改变它的能力状态：展示名从“缺口补图（Gap2Graph）”改为“KAG增强路线”只是让名字直白说明它属于哪条线，不表示接入进度有任何变化。
5. 既有 Python/TypeScript 标识符、API 字段、数据库对象和评测组名保持原样；展示命名不触发公共契约或历史实验数据改名。历史文档与既有架构图中的“缺口补图（Gap2Graph）”字样不回写，按当时的记录保留。
6. 产品标志和功能图标统一遵循[品牌图标设计规范](品牌图标设计规范_v0.1.md)，同一模块在前端、架构图和报告中使用同一个图形语义；图标不表示该功能已经验收。
