# EvoOntology 任务4端到端 SQL 复验设计 v0.1

日期：2026-10-04。性质：**在定位复验揭盲后的探索性后续实验，不是原预注册的确认性检验**。

## 研究问题

在已封存的 28 道独立 AdventureWorks 题上，按需知识方案 C 是否比无知识、全量结构方案 A 更常生成与人工核验见证查询结果一致的安全只读 SQL？前一轮只测字段定位，本实验检查定位提升能否传递到最终查询答案。

## 设计与判定

- 使用同一题集、固定数据库镜像、当前正式实验运行器和知识快照；Gold SQL 单独保存在候选题集，只用于模型调用全部完成后的离线比较，不放进问题或 prompt。先冻结本文件、题集、Gold、运行器、知识快照和运行环境哈希。
- A 与 C 为题内配对。每臂每题按现有 SQL 运行模式运行两次，题内臂次序由固定随机种子打乱。生成器最多进行三次 SQL 生成/只读执行尝试；安全校验拒绝、请求/解析错误、最终执行错误均计答案失败，不删题、不补题。
- 主要结果是**SQL 执行结果集一致率**：与对应只读见证 SQL 的结果依项目已实现判定口径比较；仅见证 SQL 有顶层 `ORDER BY` 时要求行序一致；数值容差沿用 `eval/metrics.py`。列顺序不同记 `pass_loose` 并单列。`error`、安全拒绝及空结果异常不算正确。全部 28 题作为分母，每题两次运行分别报告；配对差异以题为统计单位，先对每题两次结果取平均，再对题级 A/C 差计算固定种子 bootstrap 95% 区间。
- 次要结果：首次成功执行率、正确答案率、SQL 安全拒绝/报错率、题均模型调用数、完整词元、端到端延迟。知识检索规划调用必须计入 C 的成本。
- 工程判断：C 的答案一致率若有正向点估计、95% 区间下界大于 0，且安全失败不增加、成本可接受，则建议进入隔离分支小流量试接；否则不建议当前接入。由于仅 28 题且每题两次，这一轮仍是探索性工程证据，不称为普遍有效或正式确认性试验。

## 可信度边界与风险

题目编制者与 Gold 审阅者独立于模型结果；数据库见证查询在固定镜像、只读事务中逐题成功且结果非空。运行器可验证相同题面和版本，但模型服务端实际权重/路由若不提供版本号，冻结只能覆盖公开模型名、端点、请求参数和客户端环境，不能证明服务端二进制在整个实验期间完全不变。模型输出有随机性，temperature=0 不等于确定性，因此每题两次只能估计很有限的波动。结果只外推到该题集、该模型服务与 AdventureWorks 结构，不直接代表真实项目收益或竞赛得分。

Gold 结果在模型运行后由独立脚本从只读数据库重新取得，并使用项目 `eval/metrics.py` 比较；原始逐调用响应、SQL、trace、词元、错误与哈希全部保留。报告同时展示分母和失败，禁止只挑正确题或最好的一次。
