# EvoOntology 任务4 SQL 结果判定口径修订 v0.1a

日期：2026-10-04。性质：运行后发现测量缺陷后的**透明、探索性复评分规则**，不是原始预注册内容。

## 发现的问题

SQL 复验 v0.1 最初的结果集提取器把运行记录中按列名组织的行对象当成可迭代数值行，另把见证 SQL 是否含 `ORDER BY` 直接传给结果比较器。运行完成后，首轮离线评分显示 112/112 均失败；复核发现这两个评测器缺陷都会造成假失败：前者把列名当作单元格，后者把 Gold 为稳定展示加入的排序误当成用户语义。初始全失败报告保留为无效评分记录，不能作为模型表现结论。

## 修订口径

模型输出以列名映射还原为列值序列。第二名盲审者仅按限定字段检查封存题面，未访问模型记录或报告；其规则和逐题理由保存在 `task4_holdout_order_rubric_clean_v01.md` 及 JSON 文件中。只有题面明确要求排序、排行、按字段升降序或前 N 时才要求行序；其余题忽略行序。Gold 有排序但题面没有排序语义时，Gold 排序仅是稳定展示顺序，不进入答案正确性判定。所有其他列数、数值容差、结果集多重性和执行错误规则继续沿用项目 `eval/metrics.py`。

盲审记录、修订脚本及本文件在最终复评分前冻结并计算 SHA-256，同时校验模型运行时数据库指纹不变。题目、Gold SQL、原始模型请求、输出、SQL 和数据库均不更改；不发起任何新模型调用。主要比较仍以题为单位，题内两次运行各臂先取均值，再算 C−A；因修订规则是在看到初始无效评分后、且模型结果已揭盲时制定，修订结果只能作**有清晰审计轨迹的探索性复评分**，不能冒充预注册确认性结论。报告必须同时保留原错误评分文件、修订原因、盲审规则和修订后结果。
