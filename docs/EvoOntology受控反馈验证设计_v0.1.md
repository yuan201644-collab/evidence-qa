# EvoOntology受控反馈验证设计 v0.1

更新日期：2026-10-03。状态：受控阶段模型调用前固定。

## 原因与判断边界

机制实验v0.2的12道开发题两轮全对，没有真实失败可触发内容修改。因此新增一项明确标注的故障注入（fault injection）：故意给知识层加入错误，用来检测发现、修改和拒绝机制，而非证明项目自然错误被减少。

## 固定干预

只改sales_header条目：错误声称SubTotal是未完成订单临时金额，商品金额应使用TotalDue。错误版本仅留在评测内存和快照，绝不进入正式业务。其他11条、所有表字段和求解代码不变。

本受控阶段第一次模型调用前，原库已发现TotalDue全空。因此故意错误以SubTotal+TaxAmt+Freight表达含税应付额，并错误宣称它是商品金额；标准查询采用校准后的非NULL结果。所有组共享真实缺失字段说明，字段定义证据取自微软官方源码及当前库非空计数，避免通过NULL匹配制造收益。

开发只使用dev-01的商品金额问题和dev-03采购控制题，各两轮。修改器获得失败轨迹、字段和真实数据探查，不获得标准SQL或结果。只允许修改sales_header的说明与别名，不改变关联表、不增加工具。独立证据审查验证TaxAmt/Freight/TotalDue/SubTotal关系，错误与无证据主张拒绝。

验证固定validation-01销售商品金额与validation-03采购控制题，两轮配对；每轮至少一个改善、无退步才接受。最终测试固定test-01区域商品金额、test-02销售含税应付额、test-07采购商品金额、test-08采购含税应付额、test-20收货国家商品金额，各两轮。它们不参与候选构建或接受判定。

表/知识检索规划与查询生成预算沿用主实验；每题两轮、两个独立题并发、只读执行。最终对比损坏父版本与验证后版本；无候选或验证拒绝就停止在拒绝记录，禁止手工填写修复成绩。

报告包括：注入错误是否真的诱发失败；是否提出有证据的修复；验证门槛是否通过；测试迁移与负向控制是否稳定；构建及维护额外词元。即使全部通过，也只证明这个预设缺陷上的修复机制可以工作，不能据此声称初赛得分增加、自主通用演化、多模态或跨域效果。使用同一主题集不是新的独立盲测。
