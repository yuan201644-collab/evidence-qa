## 一、结论与口径

两份报告已有完整章节结构和较多项目说明，跨源实验也有一组已核验结果；目前不能视为可提交终稿。主要缺项是：**选定交付候选版本上的主线测评、中级任务验收、效率计时、真实界面与异机复现证据，以及最终 Word/PDF 的一致性检查。**

本计划区分三种信息：

1. **赛题原文要求**：以 `docs/reference/赛题八_题面原文.txt` 中“校内初赛作品要求及评分标准”为准。原文在技术文档页数处使用“建议不超过”，设计报告亮点预览页、基础题数、中级任务有效性和评分档位等要求按原文执行。
2. **项目内部执行口径**：以项目 `AGENTS.md`、已定任务组合和本文件所列的交付检查为准。内部要求比题面更具体时，不能将内部测试方案误写成赛事新增规则。
3. **实测结论**：只能由明确版本、题包、评分口径和原始记录共同支撑。代码中有功能、接口健康、HTTP 200、已有引用或受控界面截图，均不能单独替代业务正确性验收。

- [ ] 运行鲁棒性和连续五轮以上对话测试；把历史 19/20 作为历史记录，不直接复制到新候选结果栏。

**通过门槛**：测试题、Gold/参考答案和评分规则先固定；所有题均有原始响应；成功、失败、拒答、空答、截断均有统计；两种主线指标分别报告。

### 第 3 步：补齐效率、解释性和真实界面证据

- [ ] 按当前技术说明书计划完成数据库和文档规模计时；若无法全部完成，先修改内部测量矩阵并说明差异，不得把未测部分伪装成实测。
- [ ] 至少保留能展示 SQL/数据证据、文档原文/定位和真实工具处理记录的候选响应。
- [ ] 登录后检查三个问答方向的实际入口和功能边界；单源问题不应被描述成跨源流程。跨源演示需使用其专用数据与真实响应。
- [ ] 从同版候选截取报告所需界面图；每张截图绑定候选、问题、时间和对应原始响应。
- [ ] KAG 若因资源限制不验收，则明确保持不可用/不纳入当前候选能力，不为它阻塞主线验收。

**通过门槛**：截图与同一候选的真实运行记录互相对应；静态图示只解释设计，不替代功能证据。

### 第 4 步：回填两份报告并作交叉核对

- [ ] 先回填技术说明书中的配置、题集、判据、逐项结果和复现表，再将简明结论同步到设计报告。
- [ ] 两份报告的提交号、样本量、通过数、比例、限制和术语一致；不把历史结果写成候选结果。
- [ ] 保留 CS18 描述性结果和全部已知流程偏离；不把它改称真实业务效果验证或官方分数。
- [ ] 每个核心数字附近标注对应证据文件/附录编号；附件清单和源码包能找到该文件。
- [ ] 设计报告第 1–2 页更新为已核验的亮点、任务和结果；不要用未验收指标作宣传数字。

### 第 5 步：图表、Word/PDF、源码包最终门禁

- [ ] 绘制 FEVA 核验图，替换占位图；依 `docs/brand/` 与图标规范复核现有架构图。
- [ ] 更新五张候选界面截图、表图编号、交叉引用、参考文献和生成清单哈希。
- [ ] 重新生成两份 v0.1 后续修订版 Word；更新目录；导出各自 PDF。Word 与 PDF 的正文、图表、表号和版本一致。
- [ ] 对技术说明书“格式要求同上”是否继承亮点预览页要求保留一次口径确认。题面明确写出设计报告第 1–2 页亮点预览，技术说明书写“格式要求同上”；当前内部预算按说明书不加两页处理。若无法确认，采用不超过 30 页的保守方案，避免因解释差异漏掉必要页面。
- [ ] 渲染并逐页检查最终文档，确认目录、页码、图表清晰、无占位图、无空表误留、无断页/裁切；设计报告按项目内部不超过 20 页，技术说明书不超过 30 页控制。
- [ ] 核对源码 ZIP：目录和 README、数据库 schema、至少 10 份不同类型知识库样本、依赖与版本、必要模型资产说明、快速启动脚本；在干净环境执行启动与至少一条问数、一条文档问答。

**最终门槛**：两份 Word、两份 PDF、源码 ZIP 和证据索引都引用同一候选版本；所有仍无法完成的项目明确标“未完成/不纳入本版”，不留模糊的“基本完成”。

## 七、工期优先级

初赛截止为 2026-10-20，具体时刻与提交通道须另行核对。项目内部排期把 10-18 作为打包与演练目标，10-19 用于提交和核对回执，10-20 只处理应急事项；因此应压缩装饰性改写，优先形成可复核结果。

| 优先级 | 事项 | 为什么先做 | 完成标志 |
|---|---|---|---|
| P0 | 候选、运行配置、题集和评分口径一致 | 否则不同分支、问题和判据的结果不能汇总。 | 唯一提交号及测试绑定清单可复核。 |
| P0 | 至少一个中级任务通过，并跑基础 SQL/RAG 核心题 | 关系参赛有效性与主要基础分。 | 题目、答案、原始响应、逐题判分成套保存。 |
| P1 | 准确率、忠实度、鲁棒性、多轮和两档效率 | 覆盖主要性能与优化评分项。 | 各指标有明确分母、规则和候选版结果。 |
| P1 | 真实 Demo、证据展示截图、复现演练 | 支撑可解释性、交互、演示和交付可信度。 | 同版录屏/截图、启动步骤与运行记录。 |
| P2 | 报告语言润色、非必要版式美化 | 不应挤占封存候选和验证时间。 | 不改动数字口径，Word/PDF 排版通过逐页检查。 |

## 八、报告文字中的禁用替代口径

- 不用“接口返回 200”“服务健康”代替答案正确率。
- 不用“有引用/检索到文档”代替 RAG 忠实度。
- 不用功能清单或模块代码代替中级任务攻克证据。
- 不把 CS18 合成题上的配对差写成真实业务准确率或统计显著结论。
- 不把主工作区、历史分支、隔离候选中的最好数字拼成一个结果。
- 不把未启用的 KAG、静态 FEVA 动画或架构图当作实际运行能力。
- 不用空白单元格表达已通过；空白表示尚未获得最终证据，完成后填结果或写明不适用及理由。
