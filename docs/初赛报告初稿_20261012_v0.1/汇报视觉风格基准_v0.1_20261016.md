# 知证 VeriMind 汇报视觉风格基准

版本：v0.1　｜　日期：2026-10-16　｜　适用：设计报告、技术实现说明书及其图表

## 定位与参考取舍

以“问题需要哪些事实 → 如何核验 → 结论依据什么证据”为叙事主线，整体可信、清晰、克制。借鉴技术方案的分层与流程分区、项目报告的蓝白主色和统一层级；减少渐变大背景、重复装饰条、密集小图标和过小文字。

## 视觉与图表规则

- 白 / 浅灰底，品牌蓝 `#315bc7`、深蓝 `#254ba6` 为主，浅蓝 `#8fa8e9` 作次级；核验青绿 `#168b82` / `#55d4c3` 少量强调证据状态，KAG 紫 `#80649b` 仅标识可选 Beta 路线。状态必须同时写文字，不能只靠颜色表达。
- 主标志、功能图标复用 `web/public/brand/` 的 SVG 与折面风格；不另造近似图标，不用 emoji。正文沿用现有模板宋体，标题黑体；图中文字统一、A4 导出后清楚可读。
- 汇报中的局部业务流程图可采用“图标主体、紧凑排布”的导师参考风格；它只约束局部流程图，不替代整体架构图、产品界面和主标志的品牌资产规则。详见[局部流程图视觉规范](../brand/流程图视觉规范_v0.1.md)及其中的 v0.9 可编辑示例。
- 一图一重点，标题说明图要表达的结论；品牌蓝突出主路径，重点色最多 1–2 处。连线方向一致、尽量直角，避免交叉；单图优先控制在 9 个核心节点内，超出拆为总览与细节。
- **箭头画法**：线身用浅蓝 `#8fa8e9`、约 2.1 px，圆端点与圆角连接；箭头头部用品牌蓝 `#315bc7` 的空心折角，约 14×14 px、线宽约 2.2 px。明确一对一对应的步骤用直线，箭头尖触达目标卡片边缘；只有汇入共享模块等确有转向关系时才用轻微圆角折线，避免为了装饰弯折。
- 总览图呈现**问数、问答、跨源问题**三个入口：前两者分别走结构化查询、文档检索；跨源才联合两类来源。三者可共享核验展示，但不可画成所有问题都走跨源。
- 流程统一表达“问题 → 所需事实 → 对应查询 / 检索 → 核验 → 结论与证据”。指标图标出定义、分母、比较对象、数据来源和版本；截图只证明真实界面，不替代架构图或数据图。

## 两份报告与验收

- **设计报告**：前两页讲清项目定位、主线总览和已验证成果；少图、重点突出，并说明结果边界。
- **技术实现说明书**：呈现模块关系、数据流、三类问答分流、核验展示、部署接口与评测流程；细节分图并配口径说明。
- 图优先保留可编辑源文件，报告用清晰 SVG / 高分辨率 PNG。最终检查逻辑与正文一致、字体可读、无裁切重叠、图号图注正确，并逐页目视复核导出 PDF。

参考依据：导师提供的《技术方案(1).pdf》《项目报告(1).pptx》；项目[《品牌图标设计规范 v0.3》](../品牌图标设计规范_v0.3.md)；GitHub [drawio-skill](https://github.com/Agents365-ai/drawio-skill) 的可编辑图与自检实践、[diagram-design](https://github.com/cathrynlavery/diagram-design) 的留白、重点色和复杂度控制实践。该基准约束报告视觉，不改变系统功能、实验口径或品牌图标资产。
