# 事实判定扩展层（方向三 · KAG 适配补丁）

> 交付位置：`项目主体/contrib/kag/feva_override/`
> 上游基线：OpenSPG/KAG 0.8.0（Apache-2.0，`OpenSPG-KAG-fdab15b`）
> 更新：2026-10-28

## 一、这个补丁做什么

上游 KAG 的职责是「查什么」：把问题解析成逻辑形式，规划检索步骤，召回原文块。
它不负责「哪些事要确认」——这是实测结论，不是设计判断（见 §五）。

本补丁在 KAG 的生成步骤之前插一层**事实表**，把问题拆成一条条待确认的事实，
逐条判定，再让模型照着表作答：

```
问题 ──► KAG 规划与检索 ──► [本补丁] 拆事实 → 判真假 → 挂证据 → 拼表 ──► 生成答案
                              ↑ 复用 1031 条结构化记录做集合运算，不调模型
```

四段的实际含义：

| 环节 | 做法 | 是否调用模型 |
|---|---|---|
| 拆 | 复用语料解析器，一个**子问**一行（不是一份文档一行） | 否 |
| 判 | 对结构化记录做计数 / 求交 / 求差 / 跨年比对 | 否 |
| 证 | 走 `(项目)-[:source]->(块)` 图边取块；应用侧改取本次召回块 | 否 |
| 用 | 表插在 `refer_data` 首位，附「表中没有的数就是语料里没有」 | — |

判定不经过模型是刻意的：同一道题判多少次都是同一个数，可复算、可审计。

## 二、两条运行路径，一份代码

| | 容器内 | 交付应用内 |
|---|---|---|
| 位置 | `<site-packages>/feva_override/` | `contrib/kag/feva_override/` |
| 触发 | 新增 pipeline yaml 指向覆盖后的 planner | `app/kag_ask.py` 按文件路径加载 |
| 证据来源 | Neo4j 的 `source` 边（实测 34,525 条） | 本次 KAG 响应里的召回块正文 |
| 产物 | 注入 `refer_data`，模型看到 | `fact_review` 字段，界面看到 |

`__init__.py` 里用 `import kag` 是否成功来分辨环境：容器内注册覆盖模块，
应用侧静默跳过。**`facts.py` / `ledger.py` 两份环境完全相同**，
否则界面上的表会和模型当时看到的表对不上。

## 三、文件清单

| 文件 | 作用 |
|---|---|
| `facts.py` | 拆 / 判 / 证 / 用四段；`build()` 是总入口 |
| `ledger.py` | 结构化记录索引：文档定位、单位与类别解析、聚合查询 |
| `clause.py` | 条款脚注：把答案里的条号指回原文（**实验性**，条号会错） |
| `verify.py` | 生成后核验：字符串比对答案与表是否一致（**实验性**） |
| `__init__.py` | 容器内注册 prompt / executor / prompt_dag 三个覆盖 |
| `data/_records.json` | 1031 条结构化记录（从 14 份公示语料解析） |
| `data/qbank_v4.json` | 冻结题库 31 题（判分口径见报告） |

`refinject.py`（生成钩子）与 `prompt*.py` / `executor.py` **只在容器内使用**，
不随交付目录分发——它们的形态是「补丁上游源码」，不是应用代码。

## 四、启用与回滚

### 容器侧（模型看到事实表）

```bash
# 1. 部署目录
docker cp feva_override release-openspg-server:/home/admin/miniconda3/lib/python3.10/site-packages/
# 2. 开关（标记文件，缺省全关）
docker exec release-openspg-server touch /tmp/feva_inject_on /tmp/feva_facts_on /tmp/feva_gen_on
# 3. 必须重启：feva_override 的类只在容器启动时注册一次
docker restart release-openspg-server
```

回滚：`rm /tmp/feva_*` 再重启，行为完全回到上游；删目录则彻底移除。

### 应用侧（界面看到事实表）

```bash
ASK_BACKEND=kag KAG_BASE=http://10.166.33.23:8887 KAG_APP_ID=5 uvicorn app.main:app
```

`ASK_BACKEND` 不设或设为其他值即回到原编排链路，代码零删除、一秒回滚。

## 五、能力边界（写报告必须照实说）

1. **31 道冻结题里 19 道能拆成事实，12 道拆不动**
   拆不动的两类：① 7 道指代题（主语在上一轮，如「上述四校」「两份名单」）；
   ② 5 道非计数题（条款对照、字段语义）。拆不动就落回检索，不硬凑行。
2. **M 层（计数与集合）得分 12–15 / 20**，与不含本补丁的轮次差异在噪声内。
   这套补丁的价值是**证据可得与结构完整**，不是准确率。
3. **条款级溯源未解决**：块级映射 5049/5049 = 100%，但条级会报错条号
   （B-01 给「第二条」，真值第六条）。`clause.py` 因此默认关闭。
4. **KAG 只拆「查什么」**：三级调参（谓词闭集、依赖显式化、分层提速）实测均无增益，
   详见报告第六章的负结果消融。
